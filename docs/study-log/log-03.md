### 2. 이번 타임의 학습 전략

- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?

  학습로그 2에서 사용했던 질문 큐 방식과 이모지로 학습 상태를 표시하는 방식을 그대로 유지했습니다.


- 실제로 어떻게 학습했는지 디테일한 과정을 써보세요.

  학습 순서는 문제 정의 → 답변 → 참고 자료 → 추가 질문(Now, Later) 순으로 진행했습니다.
  먼저 FK가 무엇인지 짧게 답변을 만들고, PK와의 관계나 FK가 필요한 이유처럼 바로 이해에 필요한 질문은 Now로 분리했습니다.
  그리고 CASCADE, 제약 조건, 실제 테이블 설계에서의 사용 방식처럼 조금 더 깊은 내용은 Later로 미뤄두었습니다.
  학습을 진행하면서 의구심이 들거나 좋았던 점은 따로 기록해두었습니다.

### 3. 전략 평가

- 효과적이었던 것과 그 이유

  FK에 대해 모든 내용을 한 번에 정리하려고 하지 않고, 먼저 3줄 이내로 답변을 만들었습니다.
  이렇게 하니 FK가 어떤 개념인지 먼저 잡을 수 있었고, 이후에 무엇을 더 모르는지 확인하기 쉬웠습니다.
  그리고 추가 질문을 Now와 Later로 나누니 FK의 기본 개념과 세부 개념을 분리해서 볼 수 있었습니다.


- 비효과적이었던 것과 그 이유

  FK는 개념 설명만으로는 완전히 이해하기 어려웠습니다.
  실제 테이블을 만들고 PK와 FK를 연결해보지 않으면, 참조 관계가 어떻게 동작하는지 감이 부족했습니다.
  그래서 다음에는 개념 정리 후 작은 테이블 예제를 직접 만들어보는 과정이 필요하다고 느꼈습니다.


- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?

  효과적이었습니다. FK라는 개념 자체를 모르는 상황에서 질문 큐를 사용하니, 지금 이해해야 할 것과 나중에 봐도 되는 것을 구분할 수 있었습니다.
  다만 FK는 테이블 관계를 직접 만들어봐야 더 잘 이해되는 개념이라, 이번 학습법은 4/5점입니다.

### 4. AI 피드백

- 자신의 학습 전략에 대해 AI 학습 전문가에게 피드백을 요청하고, 유용했던 제안 1가지 이상 기록

  AI에게 완료 기준은 처음부터 정확히 세우는 것이 아니라, 학습하면서 수정하는 가설로 보면 된다는 피드백을 받았습니다.
  특히 FK처럼 처음 보는 개념은 먼저 “한 문장으로 설명할 수 있다”, “필요한 상황을 예로 들 수 있다” 정도의 임시 완료 기준을 세우고,
  학습하면서 “테이블 예제를 직접 만들 수 있다”처럼 구체화하면 된다는 점이 유용했습니다.

### 5. 다음 타임에 바꿀 것

- 유지할 것과 그 이유

  질문 큐를 만들고 Now / Later로 나누는 방식은 유지할 것입니다.
  이유는 학습 범위가 너무 넓어지는 것을 막아주고, 지금 집중해야 할 질문을 명확히 보여주기 때문입니다.


- 바꿀 것과 그 이유

  다음 타임에는 개념 정리 후 작은 예제를 직접 구현하는 과정을 추가할 것입니다.
  FK는 설명만 읽으면 이해한 것처럼 느껴질 수 있지만, 실제 테이블 관계를 만들어봐야 제대로 이해했는지 확인할 수 있기 때문입니다.
