### 2. 이번 타임의 학습 전략

`ReservationTest` 클래스의 테스트 코드를 실행하던 도중, 에러가 발생했다.
이 상황에서 나의 학습법을 적용하여, 문제 발생 시 고민과 해결 과정을 자세히 기록해두기로 했다.

### 3. 전략 평가

- 효과적이었던 것과 그 이유
    - 발생한 에러의 원인, 해결 방안, 해결된 이유까지 형식에 맞게 기록해둔 것이 효과적이었다.
    - 에러 발생 이후의 해결 과정 흐름을 정리해 보며, 내가 새롭게 알게 된 것을 제대로 이해하고 있는 것이 맞는지 확인하는 데 도움이 되었다.

- 비효과적이었던 것과 그 이유
    - 없었다.

- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
    - 내가 막힌 문제에 적합한 학습 전략이었다고 생각한다. 특히, 수정 과정에서 다른 종류의 에러가 두 번 발생했는데, 형식에 따라 기록해 두니 원인과 해결 흐름을 따라가기 수월했고, 나중에 다시 보기에도 좋았다.

### 4. AI 피드백

- 에러가 발생했을 때 원인-해결-이유의 흐름을 기록하는 습관은 단순히 문제를 푸는 것과 이해하는 것을 구분하는 핵심 행동이다.
- 다만, 학습 초반에 비효과적인 것이 없다고 느껴질 때는 정말 잘 맞는 전략을 찾은 것이거나, 아직 전략의 한계를 만날 만큼 깊이 들어가지 않은 것이다.
- **학습 범위에 대한 추가 질문**: "@SpringBootTest 없이 같은 테스트를 돌리면 어떻게 될까? 그리고 그게 왜 그렇게 되는 걸까?" → 이 질문에 말로 막힘 없이 답할 수 있다면 이번 개념은 소화된 것이다.

```
피드백에 따른 추가 학습 내용
- @SpringBootTest는 테스트 환경에서, RestAssured가 실제 HTTP 요청을 보낼 수 있도록 Tomcat을 통해 서버를 띄워줌
- RestAssured는 실제 HTTP 요청을 보내는 도구이기 때문에, 요청을 받을 서버가 필요함
- @SpringBootTest 없이 돌리면, Spring Context와 Tomcat을 실행시키지 못함
- => RestAssured가 요청을 보낼 서버가 없어서 ConnectionException 발생
```
