# 학습 로그 인덱스

## 학습법 변천사

### v1 — 사이클1 
- **방식**: AI 없이 나와 페어의 생각 위주로 진행
- **기록**: AI와 대화한 내용을 바탕으로 공부한 내용 정리 요청 → 노션에 간단히 정리만, 다시 읽지 않음
- **문제점**:
  - 속도가 너무 느렸다
  - 복잡한 문제에서 쓰레기 코드를 만들었다
  - AI를 활용해 개념 정리는 했지만 활용하지 않았다

### v2 — 사이클2 (설계 선행 + AI 토론)
- **방식**: 내 생각과 설계 먼저 문장으로 작성 → AI와 토론으로 합의점 찾기, 납득 → 구현
- **막혔을 때**: 검색 → 그래도 안 되면 AI에게 방향성 질문 → 납득되면 구현
- **코드 리뷰 피드백**: 간단한 것은 직접 해결, 막히는 지점은 AI와 토론하며 리뷰어 의도 파악
- **문제점**:
  - 납득은 했지만 응용이 필요한 상황에서 또 AI에게 물어보게 됨
  - 지식이 "AI를 통해서만 꺼낼 수 있는 형태"로 저장됨 → 혼자 응용 불가
  - "이해한 것 같은 느낌"과 "실제로 설명할 수 있는 것" 사이의 간격이 좁혀지지 않음

### v3 — 이번 미션 (Structural Thinking)
- **핵심 목표**: AI를 통해 납득한 것들을 연결해서 구조화하고, 내 언어로 작성할 수 있게 되는 것
- **사이클**:
  1. 학습할 개념에 대해 직접 생각해보기 (ex. 왜 getter를 사용할까?)
  2. AI에게 상황과 문제를 인식시킨 후 토론 → 틀린 부분은 틀렸다고, 맞은 부분은 맞았다고 짚어줌
  3. 학습 내용을 **나의 언어**로 정리 (대화내용·문서 참고 없이, log-n.md 파일에 작성, 오직 내 생각과 문장으로)
  4. 비슷한 문제를 직면하면 과거에 작성한 문서를 참고 → 문서 업그레이드 (Notion MCP + AI 활용)
  5. 내가 정리한 문서를 AI로 검증
  6. 3일 후 문서를 참고 없이 다시 작성해보기 → 술술 작성되면 진짜 내 지식

## 주말에 시도할 것
Java 문법이 막힐 때, 크루 코드 3개를 보고 이해되는 방식을 골라 직접 기억해서 작성해본다

적용 시나리오:
1. 문법이 안 써지는 순간, AI 대신 크루 코드 3개를 먼저 열어본다. 내가 이해할 수 있는 코드를 하나 고른다.
2. 코드를 닫고, 기억을 더듬어 직접 작성해본다. 기억이 안 나면 다시 열어서 확인하고 다시 작성한다.
3. 크루 코드를 봐도 왜 이렇게 쓰는지 이해가 안 되는 순간이 멈출 신호! 그 시점엔 AI한테 "이 코드가 왜 이렇게 동작해?"로 이유만 물어본다.
