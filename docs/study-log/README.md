## 학습법 변천
### V1 (레벨 1)
1. 강의를 통해 정제된 지식을 전달받는 수동적 학습에 익숙해져 있었다.
2. 아무런 가이드 없이 스스로 시작점을 찾아야 하는 상황에서 무력감을 느꼈다.
3. 시간 압박 속에서 본질적인 이해 없이 구현에만 몰두했다.
4. AI에 피상적인 질문을 던지며 원론적인 답변에 그쳐 본질적인 갈증이 해소되지 않았다.
5. 해결되지 않은 궁금증이 기술 부채로 쌓이며 심리적 부담이 커졌다.
6. 부채를 빠르게 처내기 위해 다시 AI를 오남용하는 악순환에 빠졌다.
### V2 (스스로 생각한 문제점 해결 방법)
1. 목표와 난이도 명확하게 구축하기
2. 무작정 잘하려는 욕심보다는 현재 레벨에서 한 단계 업시키는걸 노리기
3. 배운걸 말한마디로 정리할 수 있게하고 크루에게 설명하기
4. 하루 한 번 배운것에 대한 기록 남기기
5. AI는 코드 작성자가 아닌 멘토로 활용한다 (중요지점은 AI가 판단)
6. 문제 내달라고 하기
### V3 (AI 피드백 반영)
```
막히는 순간, AI나 검색에 손대기 전에 종이에 10분간 손으로 적기.
코드를 짜다 손이 멈추는 순간, 다음을 실행.

종이(또는 메모 앱)를 펼치고 10분 타이머를 켠다.(시간은 유동적으로)
세 가지를 순서대로 적는다.
1. 내가 지금 만들려는 것은 무엇인가? (목표 한 문장)
2. 내가 모르는 것은 정확히 무엇인가? (가능한 한 좁혀서)
3. 내가 추측하는 답은 무엇인가? (틀려도 좋으니 가설)

10분이 지난 후에야 AI·구글·동료에게 질문한다.

핵심 원칙

완벽하게 지키려 하지 않는다. 첫 주는 절반만 지켜도 성공.
기존 6개 원칙을 의식하지 않는다. 이 한 가지가 자동화되면 나머지(목표 명확화, 한 마디 정리, AI 멘토화, 기록)는 자연스럽게 따라온다.
점검은 미션 단위로 한 번씩. "이 규칙을 몇 번 적용했고 그때 무슨 일이 있었는가"만 회고에 남긴다.
```

### V4 최종 학습법
막히면 종이로. 묻기 전에 추측 한 줄. 도구 쓰기 전 0.5초.
도구 4개

Picture Walk: 새 단계 문서를 받자마자 5분 훑기. 다음 단계도 함께 훑어 보류 항목 식별.
양식 A (출발점 막힘): 한 줄 요약 / 동작 쪼개기 (동사로) / 동그라미 (의존 관계상 가장 아래 + 검증 가능한 최소 묶음).
양식 B (진행 중 막힘): 목표 / 모르는 것 / 추측. 10분 타이머 후에야 질문.
흐름 그리기: 구조가 안 그려질 때만. 박스에 명사, 화살표에 동사.

규칙 3개

알면서 미룬다. 보류 항목은 종이에 적어둔다.
도구는 잘못 써보면서 익힌다. 사전 확인받지 않는다.
AI는 추측 검증 도구로만 쓴다. 추측 없이 묻지 않는다.

측정
미션 끝마다 한 줄: 막막함 []분 / 명확한 질문 []% / 후회 []개 / 시작 시 압도감 []/10. 본인의 과거와만 비교한다.
핵심 원칙

V3의 한 가지(10분 종이 작업)가 양식 A·B로 분화됐다.
6개 원칙을 의식하지 않는다는 V3 원칙은 그대로다. 손에는 한 줄만 들고 다닌다.
도구를 모든 상황에 일괄 적용하지 않는다. 0.5초 점검 후 선택적으로.
새 도구는 추가하지 않는다. 가진 것을 단단히 굳히는 단계다.

```
주말에 시도할 것: 1단계부터 4단계까지의 학습 로그를 한 장으로 압축한 누적 회고 만들기

적용 시나리오:
1. 토요일 오전에 1단계부터 4단계까지의 학습 로그 4개를 나란히 펼치고
   각 단계에서 무엇을 발견했는지 한 줄씩만 뽑아 한 페이지로 정리한다.
   학습법의 변화가 아니라 본인의 발견을 추출한다.
2. 일요일에 그 한 장을 다시 읽고 다음 미션 시작 시점에 가장 먼저 떠올릴 한 줄을 고른다.
   포스트잇에 적어 모니터 옆에 붙인다.
3. 회고 작업이 30분을 넘기거나 누적 회고가 두 페이지를 넘어가면 멈춘다.
   압축이 목적인데 분량이 늘면 이미 어긋난 것이다.
```
