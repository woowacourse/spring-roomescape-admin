v2. 기술 블로그로 흐름 잡고 공식문서 보기

v3. 에러 메시지 기준으로 원인 좁히기  
[log-03](./log-03.md)  
에러를 먼저 읽고, 원인 후보를 세운 뒤 검색과 AI를 순서대로 활용했다.

금요일 코칭에서 받은 아이디어

문제를 바로 해결하려고 하지 말고, 먼저 에러를 분류한다.  
DB 문제인지, 요청 매핑 문제인지, 테스트 기대값 문제인지 나누고 들어간다.

주말에 시도할 것: 에러 분류표를 먼저 쓰고 디버깅하기

적용 시나리오:
1. 주말 미션 중 테스트가 터지면 바로 코드를 고치지 않고, 에러가 DB, 요청, 응답, 테스트 중 어디에 가까운지 먼저 적는다
2. 원인 후보를 2개 이하로 줄인 뒤 코드와 테스트를 확인한다
3. 20분 안에 후보를 못 줄이면 검색하고, 그래도 안 되면 AI에게 현재 가설과 함께 질문한다

주말 적용 결과

아직 적용 전. 주말 미션 진행 후 실제로 도움이 됐는지 이어서 기록한다.
