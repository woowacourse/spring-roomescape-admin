### 3. 전략 평가
- 효과적이었던 것과 그 이유
  - 흐름을 먼저 스케치하고 모르는 부분을 ???로 남기는 방식
  - 키워드(@GetMapping, @ResponseBody) 중심으로 학습
  - "요청 → ??? → Controller → json 반환" 처럼 전체 구조를 잡고 들어가니 어디서 막혔는지 빠르게 특정할 수 있었다.
- 비효과적이었던 것과 그 이유
  - "개념을 모른다"고 체크했지만, 실제로 막힌 지점은 개념보다 실행 환경의 이해였다. 
  - @Controller 누락, private 생성자, Jackson 직렬화 오류, RestAssured 테스트 환경 미설정 등은 개념 문제라기보다 스프링이 어떻게 동작하는지 모르는 문제였다.
- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
  - "개념 자체를 모른다"에 체크했는데, 실제로는 "코드는 돌아가는데 이게 맞는 건지 모르겠다"에 더 가까웠다. 
  - 전략이 개념 습득에 맞춰져 있어서, 실제로 필요했던 동작 원리 검증 쪽은 상대적으로 약했다.
