### 1. 막힌 것의 종류
이번에 막힌 것은 어떤 종류의 어려움이었는가? (해당하는 것에 체크)
- [ ] 개념 자체를 모르겠다 (예: "스프링 빈이 뭔지 모르겠다")
- [ ] 개념은 알겠는데 코드로 어떻게 쓰는지 모르겠다 (예: "JdbcTemplate 문법을 모르겠다")
- [ ] 코드는 돌아가는데 이게 맞는 건지 모르겠다 (예: "계층 분리를 이렇게 해도 되나?")
- [x] 기타: schema.sql 파일 내에서 PK로 인한 테이블 생성과정에서, 순서로 인한 오류를 찾는데 시간이 좀 걸렸다.

### 2. 이번 타임의 학습 전략
- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?

마감기한의 압박으로 인해 요구사항을 빠르게 반영하기가 우선이었다.
우선 돌아가는 코드를 만들고 리팩터링을 진행해야 할 것 같아서, 생각나는 방법으로 우선 진행했다.

에러와 막히는 지점이 생긴다면 약간의 고민은 하지만 너무 깊은 고민까지 이어지는 것을 의식적으로 제한했고,
특히 찾지 못하는 에러가 발생했을 때는 AI를 조금 활용했다.
