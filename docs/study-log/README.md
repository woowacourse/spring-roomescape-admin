# 나의 학습법

> 각 버전은 이전 버전의 한계를 인식하고, 그 단점을 보완하는 방향으로 발전한다.

---

## 학습법 v1 — 스스로 사고하는 학습

AI와 외부 자원에 최대한 의존하지 않고, 스스로 사고하며 해결한다.

### 학습 방식
단편적 사용법이 아닌 동작 원리까지 이해하는 깊이 있는 학습을 목표로한다.
- **설계 방식**: "객체지향의 사실과 오해", "오브젝트" 등 개발 서적을 참고하여 객체의 책임과 역할을 직접 고민하며 구조를 설계
- **문법 학습 방식**: 검색에 의존하기보다 페어와의 대화로 해결하거나, 라이브러리(함수)의 내부 코드를 직접 읽으며 동작 원리를 이해

### 성과
스스로 사고하고 문제를 해결하는 힘을 기르며, 객체 간 협력과 책임 분리 관점에서 코드를 바라보는 시야를 확보하였다.

### ⚠️ 한계점
1. "이 설계가 좋은 설계인가"에 대한 확신 부족으로 여러 방향을 비교하다 구현이 지연되었다.
    - 예: 블랙잭 미션에서 기물 이동 설계 시 의존성, 책임 분리, 변경 유연성을 모두 비교하느라 구현 속도 저하

2. 검색 제한으로 인한 비효율이 발생하였다.
    - 이미 잘 정리된 개념도 직접 코드 추적으로 접근 → 시간 대비 효율 저하

## 학습법 v2 — 자원 활용형 학습

가장 빠르게 문제를 해결하기 위해 모든 자원(AI, 팀원, 자료)을 적극 활용한다.

> v1의 **"자원 활용 부족 → 속도 저하"** 문제를 해결하기 위해, 다양한 자원을 적극 활용하는 방향으로 전환하였다.

### 학습 방식
- AI, 검색, 자료를 **의도적 제한 없이** 적극 활용
- 같은 공간에서 학습하며 막히는 부분을 즉시 팀원과 논의
- 필요시 비순차적으로 학습하며 가장 빠른 경로 선택

### 성과
문제 해결 속도가 향상되었고, 팀원과의 즉각적 대화로 혼자 학습할 때 놓칠 수 있는 관점을 보완하였다.

### ⚠️ 한계점

AI가 처음 제공한 설명에 사고가 갇히는 현상이 발생하였다. <br>
→ 단일 출처에서 개념을 받아들이면, 그 출처의 맥락 안에 사고가 제한됨을 확인

 - 예: sub-agent를 학습할 때 AI 설명이 특정 환경에서의 사용 방식에 집중되어 있었고, 이를 그대로 받아들이면서 개념을 좁게 이해함 <br>
   → 팀원과의 대화를 통해서야 채팅 환경 등 다른 맥락에서도 활용 가능함을 인지

## 학습법 v3 — 이중 모델 기반 재구성 학습

하나의 개념을 단일한 정의로 받아들이지 않고, 최소 두 개 이상의 서로 다른 관점에서 정의하고, 비교 + 검증 + 재구성한다.

> v2의 **"단일 입력원에 따른 사고 제한"** 문제를 해결하기 위해, **처음부터 여러 관점을 의도적으로 확보**하는 단계를 도입.

### 학습 방식

특정 설명이나 맥락에 갇히지 않고, **새로운 상황에서도 개념을 유연하게 적용할 수 있는 이해**를 만드는 것을 목표로 한다.


#### 1단계: 다양한 관점 수집
- AI를 통한 설명과 다른 자료를 통한 설명을 의도적으로 분리하여 확보한 뒤, 각 관점이 가진 장단점을 비교한다.

#### 2단계: 차이 비교를 통한 개념 확장
- 관점 간 차이를 분석하며 개념을 "정답"이 아닌 **"여러 관점에따라 다르게 해석되는 구조"**로 인식한다.

#### 3단계: 사람과의 상호작용을 통한 검증
- 토론을 통해 놓친 관점이 없는지 점검하고, 재구성된 개념이 새로운 상황에서도 적용 가능한지 확인한다.

## 학습 패턴

1. AI를 1차 진입점으로 고정                                                                                                                                                        
   - 막히면 첫 행동이 거의 항상 AI 즉문즉답. 막힘의 종류가 바뀌어도 진입점은 그대로다.
2. 비교를 통한 이해 
   - 한 가지를 단독으로 묻는 경우가 거의 없고, 대부분의 질문이 비교형이었다.
