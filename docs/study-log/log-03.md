### 2. 이번 타임의 학습 전략
- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?

- 실제로 어떻게 학습했는지 디테일한 과정을 써보세요.

1. 학습 목표(질문)를 세운다.
    - 구체적인 학습 목표를 세울 때, HTTP 요청-응답 메시지 구조를 정확히 알지 못해 학습 목표를 세우는데 어려움이 있다.
    - AI에게 다음 프롬프트를 건네주어, 추천 받자.
    - ``` text     내가 지금 **HTTP 요청-응답 메시지 구조**를 처음 배우려고 해. 내 목표는 HTTP 요청-응답 메시지 구조에 대한 학부생 수준의 이해야.  
     이 기술을 깊이 있게 이해하기 위해 내가 반드시 스스로 답해봐야 할 **'작고 구체적인 질문 5가지'**만 뽑아줘. (단, 초보자가 실험으로 검증할 수 있는 수준이어야 해)  
     ```  

2. 공식문서로 바로 들어가지 않고, AI에게 “최소 비교 실험”을 설계해달라고 한다.
```text  
// 추천 프롬프트  
  
나는 [HTTP 요청-응답 메시지 구조]을 처음 배우고 있다.    
    
목표는 [학습 질문]을 이해하는 것이다.  // AI 답변 중, 하나를 선택   
    
공식문서를 읽기 전에,  이 기술이 있을 때와 없을 때의 차이를 비교할 수 있는  아주 작은 실험 프로젝트를 설계해줘.    
    
조건:  
1. 5분 안에 실행 가능해야 한다.  
2. 파일 수는 최소로 해줘.  
3. 실행 결과로 차이가 바로 보여야 한다.  
4. 실험 후 관찰해야 할 포인트를 알려줘.  
5. 아직 깊게 들어가지 않아도 되는 개념은 따로 표시해줘.  
```

3. AI의 가이드라인을 따라 실험을 진행한다.
    - HTTP 요청-응답 구조에 대한 부분을 확인할 수 있었다.
    - AI 답변에 포함된 코드를 조금씩 수정해보면서 Http 요청, 응답 메세지가 어떻게 바뀌는 지 관찰한다.

4. 실험만으로는 구체적인 정보를 학습할 수 없는 거 같아. Http 관련 문서와 책 그리고 정리된 글을 찾아봤다.
    - 이때 학습 시간을 좁히고 두 사이클 반복한다.
        1. 첫번째 사이클 요청과 응답 구조를 가볍게 파악한다. (아~ 이런 형식이구나)
        2. 두번째 사이클 요청과 응답 구조에 등장한 용어 중, 하나를 선정(i+1)하여 공부해본다. `Http Method`를 선정했다.
    - [HTTP Guide](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Messages)
    - HTTP 완벽 가이드 3장

5. 문서나 책을 읽으면서 드는 궁금증은 학습 목표에 적절한 지 판단하여 탐구 여부를 결정한다.
    - 학습 목표에 부합하는 궁금증이라면 알아본다.
    - 학습 목표에 부합하지 않다면, 궁금증 Storage에 기록해둔다.

6. 학습 내용을 정리한다.
    - Http Request-Response 구조 형식 파악
    - Http Method 읽고 자주 사용되는 `GET`, `PUT`, `DELETE`, `POST` 정리


### 3. 전략 평가
- 효과적이었던 것과 그 이유
    - 학습 시간을 좁히고, 사이클을 반복한 것.
    - `이유1`: 20분이라는 짧은 시간동안 두번의 사이클을 반복해봤는데, 첫 번째는 Http 요청과 응답 구조라는 큰 틀을 빠르게 학습해볼 수 있었다. 그리고 두 번째 사이클에서 비교적 깊은 내용인 Http Method를 집중적으로 학습해볼 수 있어서 좋았다.
    - `이유2`: `GET`, `POST`, `Header`, `Body`, `Status Code`, `Content-Type`을 전부 따로 공부하면 머릿속에서 흩어지기 쉬울 것 같다.

- 비효과적이었던 것과 그 이유
    - 어느정도 알고 있는 부분이라, 작은 단위의 실험에서 얻을 수 있는 지식이 많지 않았다.
    - 이번에는 공식문서나, 책 그리고 정리된 글을 읽는 게 더 유용했다.
    - 실험이 효과적인 학습 전략과 독서가 효과적인 학습 전략이 존재한다.

- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
    - Http 관련 내용을 작은 단위의 프로젝트로 실험하는 경우, 얻을 수 있는 것이 그리 많지 않아 아쉬웠다. 그러나 이런 아쉬움을 느꼈다는 것만으로도 뜻 깊은 경험이다.
    - _"더 나은 실험 방법이 있었을까?"_ 라는 생각이들기도 한다.

### 4. AI 피드백
- 자신의 학습 전략에 대해 AI 학습 전문가에게 피드백을 요청하고,  
  유용했던 제안 1가지 이상 기록

사용한 프롬프트
```text
[지침] 
새로운 고민이 생겨 이를 해결하기위해 학습했습니다. 이때, [맥락]에 적혀있는 학습 전략을 사용했습니다. 해당 학습 전략의 장점과 단점 3가지씩 언급해주고 학습 효과를 올리기 위해서 어떤 방법을 시도하면 좋을 지 2가지 이상의 피드백을 부탁드립니다. 답변을 바로 하지말고 해당 답변을 스스로 2번정도 검토한 뒤 답변 부탁드립니다. 이해가 안되는 내용이 있다면, 바로 답변을 중단하고 저에게 다시 물어봐주세요. 추가적으로 부족한 점으로부터 피드백을 주지 않고, 색다른 학습전략도 좋습니다.

그리고 프로젝트를 통해 어느정도 배경지식이 있지만, 자세한 개념은 모를 경우 어떻게 학습하면 좋을지도 마지막 코멘트로 남겨주세요.

[역할] 
당신은 리처드 파인만 입니다. 학습, 교육에 전문성이 있습니다.

[맥락]
학습 로그 1-3단계 내용
```

유용했던 제안 1가지 이상 기록하기
- 학습 목표가 아직 약간 넓다 -> 질문이 구체적이면 실험이나 문서로 확인하기 더 쉽다
- 관찰 대상 역시 추상적이다. -> 관찰 대상을 `응답 메시지가 어떻게 바뀌는지 관찰한다`보다는 `Method를 바꾸면 Request Line이 어떻게 바뀌는가?` 처럼 구체적으로 적으면 비교를 관찰하기 쉽다.

- 궁금증을 지금/다음/나중으로 나눠보는 것. 궁금증을 구체적으로 나눠볼 생각은 안해봤는데 좋은 인사이트다.

### 5. 다음 타임에 바꿀 것
- 유지할 것과 그 이유  
  학습 시간을 줄여보고 사이클을 반복하는 것.
  이유: 짧은 시간 안에 전체 구조를 한 번 훑고, 다시 특정 개념 하나를 골라 깊게 보는 방식이 다른 곳으로 새지 않고 집중적으로 공부할 수 있어서 좋았다.

- 바꿀 것과 그 이유  
  궁금증을 적을 때, 조금 더 구체적으로 적어보는 것.
  지금/다음/나중으로 나눠보면 궁금증이 학습을 방해하는 요소가 아니라, 다음 학습주제가 될 수 있다.

학습 질문을 조금 더 구체적으로 적어볼 것.
질문이 추상적이면 답변도 추상적이다 라는 말을 들어본 적이 있다.
상황이 추상적이면 이에 대한 실험과 프로젝트 역시 추상적이며, 얻을 수 있는 정보도 추상적이라는 생각이 들었다.
