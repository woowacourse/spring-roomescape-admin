### 5. 다음 타임에 바꿀 것
- 유지할 것과 그 이유

```
막히는 부분이 생기면 바로 정리하지 않고, 키워드나 당시 궁금했던 내용을 간단히 기록한 뒤
AI를 통해 최소한의 학습만 진행하고 구현을 이어가는 방식은 유지할 것 입니다.

-> 구현 도중에 깊게 학습하면 "완벽히 이해하려는 과정" 때문에 시간이 과도하게 소모됩니다.
-> 반면, 기록해두면 미션이 끝난 후에도 당시 맥락을 유지한 상태로 다시 학습할 수 있어 학습 내용의 휘발을 줄일 수 있고,
구현에 흐름이 끊기지 않아 시간소모도 적기 때문입니다.
```

- 바꿀 것과 그 이유
```
AI가 제공해주는 예제코드를 한 번에 모두 이해하려 하기보다는,
미션 도중에도 i+1 원칙을 적용하여 예제를 작은 단위로 나누고 하나씩 직접 구현해보려고 합니다.

구체적으로는,
1. 예제코드를 한 번 확인한 뒤,
2. 해당 코드를 보지 않고 가장 작은 단위 하나(query 등)를 직접 다시 작성해보고,
3. 막히는 부분이 있으면 다시 예제를 확인한 뒤 닫고 재작성하는 과정을 반복한다.

기존에는 예제코드를 통해 해당 개념의 전체기능을 "어떻게 사용하는지"만 빠르게 파악한 뒤 바로 구현하려고 했기 때문에,
실제로는 코드에 대한 이해 없이 사용하는 경우가 많았고, 그로인해 구현 당시 예제코드를 계속 확인해야 하는 문제가 있었습니다.

-> 예제를 작은 단위로 쪼개어 직접 재현해보는 과정을 추가함으로써, 단순히 사용하는 것이 아니라 "내가 구현해본 경험"을 통해 개념을 체득하기 위함입니다.

예시)
JdbcTemplate 사용 시 query()와 update()를 한 번에 구현하려 하지 않고,
query() 하나만 예제를 참고한 뒤 직접 재작성하여 동작시키는 것부터 시작한다.
```
