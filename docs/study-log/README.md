## 학습 패턴

### 1. “판단 문제를 학습 문제로 처리” 패턴

#### 정의

“이게 맞는가?”라는 설계/판단 문제를

“개념을 더 알면 해결된다”로 접근하는 패턴

#### 근거

- JdbcTemplate, @DirtiesContext 등에서
  → 사실은 선택 문제인데 사용법 위주로 접근
- 토론을 “기회가 없었다”고 판단

#### 문제

판단 문제는:

- 더 많이 안다고 해결되지 않음
- 기준과 비교가 있어야 해결됨

### 2. “확신 수집형 토론” 패턴

#### 정의

토론을 통해 새로운 관점을 얻기보다

이미 가진 생각을 확인하고 확신을 쌓는 방향으로 흐르는 패턴

#### 근거

- “근거가 통한다는 것을 알 수 있었다”
- “토론이 길어지면서 반복된다는 느낌”

#### 문제

이 상태가 되면:

- 새로운 정보는 거의 없음
- 시간만 소비됨
- 결론 없이 루프 발생


---

### 질문

- 의견을 확정해두고서 토론을 하는 것도 좋은 것 같다
- 결론에 도달하는 과정에서 했던 생각들도 토론을 해본다
- 토론의 목적을 분명히 한다.
  - 내 생각에 대한 검증이 목적이라고 하면 괜찮다
  - 다른 크루의 의견을 듣는게 목적이라고 하면, 조금 더 열린 목절
- 선택지에 대한 장단점을 나열시키고, 판단은 토론을 통해서

### 도입

- 결론에 도달하는 과정에서 했던 생각들로 토론을 해본다. 토론을 시작하기 전에 목적을 분명히 한다.
