```
Q1. @ResponseBody가 붙은 메서드는 무엇이 달라질까?
   
우선 Controller에서 주로 사용하는데, ResponseBody를 사용함으로써 Controller에서는 어떤 데이터를 보낼지만 신경쓰면된다.
만약 @ResponseBody를 사용하지 않는다면 "good" -> good이라는 view를 찾아서 전달한다.
하지만 @ResponseBody를 선언하면 Spring에서 요청 타입에 맞게 직렬화 역직렬화를 알아서 해준다.
나는 어떤 데이터를 보낼지만 신경쓰면 된다.

Q2. Spring은 “어떻게” 이 메서드가 View를 찾지 않고, 데이터를 그대로 응답으로 써야 한다는 걸 알까?

이 부분에서 지식이 없어, 어떤 키워드를 공부해보면 좋다고 생각해?

Q3. 아래 키워드들을 하나씩 따라가면서 구조를 그려봐
DispatcherServlet
HandlerMapping
HandlerAdapter
HandlerMethod
ReturnValueHandler
HttpMessageConverter


“이 반환값을 View로 해석할지 vs 그대로 응답 바디에 쓸지”
이 판단은 어느 시점에서, 어떤 컴포넌트가 할까?
```

제가 이해한 구조는 DispatcherServlet에서 HttpServletRequest를 받아서 Handler(Controller 메서드)를 찾습니다. 이때 HandlerMapping에서 URI에 해당하는
Handler를 찾아오고,
HandlerAdapter에서 Handler 메서드가 실행됩니다. 근데 Handler에서는 필요한 메서드 인자와 같은 메타 데이터가 필요한데요, 이 정보를 HandlerMethod를 이용합니다.
Handler에서 반환한 객체는 -> ReturnValueHandler에서 처리됩니다. @ResponseBody 와 같은 메타 데이터를 확인해서 필요 객체를 HttpMessageConverter에게 전달합니다.
마지막으로 만약 View를 전달한다면 HandlerAdapter에서는 ViewResolver를 이용해서 반환을 해줍니다
