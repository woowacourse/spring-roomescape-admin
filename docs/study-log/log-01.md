### 2. 이번 타임의 학습 전략

- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?

  사전 학습에서 진행한 학습법 v3를 적용하려고 했지만,
  Annotation의 작동 원리를 아는 방법에 대해서는 2번 순서인 개념 정리 카드 작성에서부터 무엇을 공부해야할 지 몰라 어려움을 겪었습니다.
  따라서 이번에는 학습법 v3에서 필요하다고 생각되는 부분을 발췌하여 학습법을 간소화 했습니다.


- 실제로 어떻게 학습했는지 디테일한 과정을 써보세요.

  학습 순서는 문제(목표) 정의 &rarr; 추가 질문 정리 &rarr; 지식의 원천 찾기 &rarr; 실험 &rarr; 질문의 답변 정리 순으로 진행했습니다.
  그리고 학습을 진행하면서 의구심이 들거나 좋았던 점이 있다면 아래에 적어 기록했습니다.

### 3. 전략 평가

- 효과적이었던 것과 그 이유

  하나의 목표를 기반으로 추가 질문으로 뻗어나갈 때, 어디까지 알고 어디까지 모름을 명확히 알 수 있었습니다.


- 비효과적이었던 것과 그 이유

  파생된 모든 질문에 답변을 해야 최상위 목표가 완성되는 구조라 하나의 목표를 이루기 위해
  너무 많은 것들을 공부를 해야한다는 생각이 들었습니다.


- 자신의 학습 전략에 대해 AI 학습 전문가에게 피드백을 요청하고, 유용했던 제안 1가지 이상 기록

  저는 위의 학습법을 진행하면서, 어디까지 학습해야하지?, 파생된 모든 질문에 답변을 해야 할까? 두 개의 의구심이 있었습니다.
  그리고 AI 학습 전문가에게 피드백을 요청하고, 아래와 같은 질문 큐 구조로 추가 질문을 정리해보라는 조언을 받았습니다.

```text
## 질문 큐

### 지금 답할 질문
- [ ] [[각 어노테이션이 의미하는 바는?]]
  - 이유: @RestController 코드에 직접 등장하므로 현재 목표에 필요함

### 보류할 질문
- [ ] [[Java에서의 Annotation 등장 이유]]
  - 이유: 배경지식이다. 작동 원리 1차 이해에는 필수 아님
- [ ] [[Annotation를 만드는 방법은?]]
  - 이유: 사용하는 원리 이해 후 실습 단계에서 다룰 질문

```

### 5. 다음 타임에 바꿀 것

- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?

  목표를 먼저 정의하니 학습을 하면서도 문제 해결에 가까워지고 있는지 상시 생각할 수 있었고,
  방향을 잃는 일이 없었습니다. 하지만 목표에 따른 추가 질문이 생기고 질문에 대한 질문을 적다보니,
  한 시간을 넘게 공부했음에도 목표에 도달하지 못했습니다.
  막힌 것의 종류와 전략의 궁합은 5점 만점에 2.8점이라고 생각합니다.
  이유는 예전에는 학습을 하고 정리하는 것 조차 할 수 없었는데,
  현재의 전략을 통해 새로운 지식을 정리를 할 수 있고 어디까지 해봤으며 어디까지는 안해보았다는 것을 이야기 할 수 있는 근거가 생겼습니다.
  하지만 큰 틀이 생긴 것이지 이를 제대로 활용하기 어려운 부분이 있고 위에서 언급한 문제가 있어 이를 보완해야할 것 같습니다.

### 4. AI 피드백

- 유지할 것과 그 이유
    - 질문에서 출발하는 방식
      Annotation의 작동 원리는 무엇일까?처럼 직접 궁금한 질문에서 시작하면 학습 목적이 분명해집니다.
      백엔드 학습은 개념이 많기 때문에, 질문 없이 자료를 읽으면 범위가 쉽게 흐려집니다.

    - 파생 질문을 남기는 방식

      모르는 것을 그냥 넘기지 않고 추가 질문으로 분리하는 것은 좋은 학습 습관입니다.
      Oakley 관점에서는 큰 개념을 작은 청크로 나누는 과정입니다.

    - 공식 문서나 원천을 기록하는 방식

      dev.java 같은 원천을 남기면 나중에 다시 확인할 수 있고, 블로그나 요약 자료에만 의존하지 않게 됩니다.
      백엔드 학습에서는 정확한 기준점을 잡는 데 중요합니다.

    - 실제 코드로 확인하는 방식

      @RestController 실제 코드를 본 것은 좋습니다.
      개념을 설명으로만 이해하지 않고, 프레임워크 코드와 연결하면 지식이 실무 맥락에 붙습니다.

    - 학습 의구심과 인사이트를 회고로 남기는 방식

      “어디까지 학습해야 하지?” 같은 메타 질문을 남기는 것은 학습법 자체를 개선하는 데 도움이 됩니다.
      단순 지식 축적이 아니라, 학습 시스템을 개선하는 방향으로 가고 있습니다.


- 바꿀 것과 그 이유
    - 추가 질문을 단순 목록이 아니라 질문 큐로 바꾸기

      지금은 질문이 생기면 모두 같은 무게로 쌓입니다.
      그러면 모든 질문에 답해야 할 것처럼 느껴지고, 학습 범위가 계속 커집니다.
      now / later / done 상태를 붙이면 지금 답할 질문과 나중에 볼 질문을 구분할 수 있습니다.

      ```
      ## 질문 큐
        
      ### 지금 답할 질문
        
      - [ ] [[각 어노테이션이 의미하는 바는?]]
        
      ### 보류할 질문
        
      - [ ] [[Java에서의 Annotation 등장 이유]]
      - [ ] [[Annotation를 만드는 방법은?]]
        
      ### 답한 질문
        
      - [x] [[Annotation를 만드는 방법은?]]
          
      ```
    - 학습 끝에 현재 결론을 3문장으로 남기기

      지금 노트는 학습 과정은 잘 보이지만, 나중에 봤을 때 “그래서 내가 이해한 내용이 뭐지?”를 바로 찾기 어렵습니다.
      현재 결론은 학습한 내용을 하나의 청크로 압축하는 역할을 합니다.
      이것이 있어야 노트가 단순 기록이 아니라 재사용 가능한 지식이 됩니다.

      ```text
      ## 현재 결론
      
      Annotation은 코드에 붙이는 메타데이터다.
      Java는 @Retention 설정에 따라 이 정보를 어느 시점까지 남길지 정한다.
      Spring은 런타임에 남아 있는 Annotation을 읽고 Bean 등록, 요청 처리 같은 동작에 연결한다.
      ```

    - 모든 파생 질문에 답하려는 태도 바꾸기

        - 파생 질문은 전부 중요해 보이지만, 지금 목표에 모두 필요한 것은 아닙니다.
        - Sweller 관점에서는 관련 질문이 많아질수록 인지 부하가 커집니다.
        - 기준은 단순하게 잡으면 됩니다.
      ```text
      지금 목표 질문의 답을 설명하는 데 필요한가?
      필요하면 now.
      흥미롭지만 없어도 설명 가능하면 later.
      이미 답했으면 done.
      ```

    - Obsidian에서 질문 노드를 상태 기반으로 관리하기

      지금처럼 링크만 만들면 어떤 질문이 답변됐고, 어떤 질문이 열려 있는지 한눈에 보기 어렵습니다.
      질문 노트에 status를 붙이고 Dataview로 모으면 관리가 쉬워집니다.
      ```text
      ---
      type: question
      status: now
      parent: "[[Annotation의 작동 원리]]"
      topic: Spring Boot
      ---
      ```

      대시보드에서는 이렇게 볼 수 있습니다.
      ```text
      TABLE status, parent, topic
      FROM "우아한테크코스/학습"
      WHERE type = "question"
      SORT status ASC
      ```
