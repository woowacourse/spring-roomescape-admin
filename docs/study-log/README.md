## 2. 학습법 선택 과정

### V1. 기존의 학습법 장점 유지하기
우선적으로 구현이나 설계에 측면에서는 최대한 직접 시도해보고 완성시키기 위해 노력하였다. 그리고 작은 결과물 속의 보완점을 찾기 위해 AI를 사용해 어떤 부분이 부족하고 더 나은 구현이나 설계가 있는지 자문하는 형태로 활용했다. AI가 짚어준 보완점 속에서 새로운 키워드를 접하게 된다면, 해당 키워드를 별도로 이론 학습하는 방향으로 지식의 반경을 더 넓혀나갔다.

특히, 이 과정에서 알게된 새로운 키워드를 학습하는 과정에서는 외부 기술블로그나 공식문서를 우선적으로 읽어보며, 사전 지식없이 해당 키워드가 왜 필요한지 어떤 의도로 생겨났는지를 우선적으로 이해하려고 노력했다. 예를 들어, 구현 과정에서 Enum타입을 도입할지 말지에 대한 고민지점이 있었는데, 원론적으로 ENUM이 어떤 이유로 등장하게 되었고 어느 상황에 사용하기 위한 용도로 탄생하였는지와 같은 방향으로 학습을 진행했는데, 이를 기반으로 타입 안전성이라는 개념 또한 연이어 알게 되었다. 이 과정 속에서 ENUM을 어떻게 사용하는지보다 해당 키워드가 등장하게 된 배경을 이해할 수 있었고, 어플리케이션에서 발생할 수 있는 일반적인 문제나 병목에 대한 키워드를 많이 접할 수 있었던 것 같다. 


### V2. 토론 이후 다른 크루의 학습법 추가하기
현재 학습법대로, 투박하더라도 직접 코드를 작성하는 과정을 의식적으로 시도한다. 구현된 내용에 대해 AI를 통해 새로운 키워드를 접하고 바운더리를 넓혀가는 과정에 집중한다. 이때 새롭게 알게된 키워드나 기술은 어떤 문제 배경에서 생겨났는지를 먼저 분석하고 기술을 이해하려고 노력한다. 이 과정 속에서 그 기술의 철학을 이해하고 트레이드 오프를 감수하고 선택한 최우선 순위의 철학이 무엇인지 이해한다. 예를 들어, 자바 제네릭은 타입 안정성을 극복하기 위해 등장한 개념이다. 이와 같이 기술의 문제 배경을 하나, 두개씩 알아가며 문제 해결력의 기반이 되는 간접적인 경험을 쌓으려고 한다.

위의 학습 방법 기반 위에서, AI를 학습 도구로 최대한 활용해보고자 한다. 우선 학습 내용을 옵시디언에 정리한 이후, 이를 기반으로 공식 문서나 학습 포인트를 추출하는 용도로 활용할 계획이다. 추후 적응이 된다면, 주기적인 루틴이나, 주간 리포트를 메일 발송해주는 서비스나 하네스도 구축해 볼 계획이다.

### V3. AI 자문을 통한 학습 시도들 추가
학습 플로우는 다음과 같이 설정한다.
1. 빠르게 구현하기
2. 기존 V2와 같이 개념 이해하기
3. 회상하며 3분 설명하기
4. 다른 기술과 비교하기 (interleaving)
5. 2시간 미니 프로젝트에 적용하며 체득하기

- 현재 학습법 V2에서는 기술의 등장 배경과 철학을 이해하는 데 집중하며, 단순한 개념 암기가 아닌 문제 해결 맥락 속에서 지식을 확장해 나가는 방식을 지향해왔다. 이 과정은 새로운 키워드를 접할 때마다 기존에 알고 있던 개념을 중심으로 지식의 반경을 점진적으로 확장해 나간다는 점에서 의미 있는 학습 경험이었다.   
- 다만 회고 과정에서, 학습 초기 단계부터 개념의 배경과 철학까지 깊게 파고드는 방식은 인지 부하를 높이고 학습 속도를 저하시킬 수 있다는 한계를 느꼈다. 이에 따라 V3 학습법에서는 학습의 순서를 재구성하고, 능동적인 학습 루프를 강화하는 방향으로 개선하였다.   
- 먼저, 학습의 시작은 ‘이해’가 아닌 ‘빠른 구현’으로 전환하였다. 새로운 기술을 접할 때는 공식 문서를 처음부터 깊게 읽기보다는, 간단한 예제를 직접 구현해보며 전체 구조와 사용 맥락을 빠르게 파악하는 데 집중한다. 이를 통해 개념에 대한 직관을 형성하고, 이후 단계에서 보다 깊이 있는 이해를 위한 기반을 마련한다.    
- 그 다음 단계에서는 기존 V2 학습법의 강점을 유지하여, 해당 기술이 등장한 문제 배경과 해결하고자 했던 본질적인 문제를 분석한다. 이 과정에서 단순한 기능 이해를 넘어, 설계 철학과 트레이드오프를 파악하며 개념 간의 연결을 강화한다. 또한 AI를 활용하여 새로운 키워드를 확장하고, 학습 범위를 조정하는 보조 도구로 적극 활용한다.    
- 이후에는 학습 내용을 단순히 정리하는 데서 그치지 않고, 의도적인 회상을 통해 지식을 강화한다. 노트나 자료를 보지 않고 해당 개념을 스스로 설명해보는 과정을 통해, 실제로 이해한 부분과 그렇지 않은 부분을 구분하고 기억을 장기화한다.     
- 또한 학습을 단일 기술에 고정하지 않고, 의도적으로 서로 다른 개념을 섞어 학습하는 interleaving 방식을 적용한다. 이를 통해 기술 간의 차이와 적용 맥락을 비교하며, 실제 문제 상황에서 어떤 기술을 선택해야 하는지에 대한 판단력을 기른다.     
- 마지막으로, 학습한 내용을 실제로 적용하기 위해 짧은 단위의 미니 프로젝트를 수행한다. 특정 기술의 핵심 개념이 드러나는 기능을 중심으로 간단한 구현을 진행함으로써, 개념을 코드 수준에서 체화하고 실무 적용 가능성을 높인다.     
- 결과적으로 V3 학습법은 **빠르게 구현하여 구조를 파악하고, 이후 개념과 철학을 이해하며, 회상과 적용을 통해 지식을 강화하는 순환 구조**를 가진다. 이는 단순한 지식 습득을 넘어, 실제 문제 해결 능력으로 이어지는 학습을 목표로 한다.

## 3. 학습법 피드백 이후 아이디어
### 3-1. 사전 과제에서 찾은 나의 패턴 3가지
- 너무 깊이 있는 학습을 지향하고 있었기에 개발 속도를 빠르게 나아가지 못했다.
    - 오히려 짧은 시간 안에 좋은 코드를 작성하는 것 또한 하나의 능력인데, 이를 고려하지 않았다는 생각이 들었다고 생각한다.
- 이해가 제대로 되지 않으면 먼저 AI에게 물어봐서 구현 디테일을 의존하려는 경향이 있었다. 전체적인 구조 이해는 내 스스로 진행하지만, 이를 이해하면 구현 자체는 ai에게 조금 의존하는 경향이 있었다고 생각한다.
- 애매한 포인트에 대해 모두 노션에 질문 형태로 남기다 보니, 너무 많은 질문이 쌓여 추후 학습에 부담이 될 수 있을 것이라고 생각한다.

### 3-2. 상호 코칭 세션
- 직접 구현하는 것의 장점이 학습 차원에서는 있다고 생각한다. 최대한 처음부터 끝까지 직접짜려고 시도해보자. 의식적으로 직접 쳐 보는 방식을 선택하자. 래퍼런스의 코드를 최대한 안보고 진행해보자.

### 3-3. 개인 정리
**주말에 실제 시도할 1개, 3줄 적용 시나리오**    

주말에 시도할 것: 각 키워드의 탄생 배경과 적용 배경을 기반으로 히스토리 이해하기
적용 시나리오:
1. 토요일에 노션에 적힌 DB, Spring 관련 고민 포인트를 하나 직접 코드베이스에 작성하고 탄생 배경을 이해한다.
2. 기술이 탄생하게 된 그 보편적인 문제 상황을 간접적으로 경험하고, 여기서 생겨난 기술의 철학을 이해한다.
3. 뎁스가 깊어져 기본 원리를 넘어서는 새로운 분야의 개념일 경우, 우선 이전까지 멈춘다.
