### 2-2. 이번 타임의 학습 전략
- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?
  - 전략은 따로 변경하지 않고 이전 방식 그대로 진행했다.
    기존 학습 전략이 개념을 이해하는 데 충분히 효과적이라고 판단했기 때문에, 방식을 바꾸기보다는 동일한 흐름을 유지하며 학습을 이어갔다.
- 실제로 어떻게 학습했는지 디테일한 과정을 써보세요.

  - README의 설명이 바로 이해되지 않는 경우에는 코드를 다시 직접 읽어보거나, 관련 개념과 용어를 찾아보며 맥락을 파악하는 데 집중했다.
  - 이후 initial 코드를 혼자 작성하면서 앞서 학습한 개념을 실제로 적용해보며 체득하려 했다. 이 과정에서 사용된 메서드와 개념, 용어들을 따로 정리하며 학습 내용을 구조화하려고 노력했다.

### 3. 전략 평가
- 효과적이었던 것과 그 이유 
  - 메서드와 용어를 직접 정리하는 과정이 특히 효과적이었다. 예를 들어 queryForObject와 query 메서드의 차이를 비교하며, 동일한 인자를 사용하더라도 반환 결과의 개수에 따라 어떤 메서드를 선택해야 하는지 명확히 이해할 수 있었다.
    단순히 코드를 따라가는 것을 넘어, 개념을 스스로 정리하고 비교하는 과정을 거치면서 이해도가 한층 깊어졌고, 부족한 부분을 추가로 학습하는 계기도 되었다.

- 비효과적이었던 것과 그 이유 
  - JdbcTemplate.query와 queryForObject의 인자 구성이 유사하다 보니, 각 인자가 어떤 역할을 하는지 명확히 구분하지 않은 채 코드를 작성했다.
    그 결과 파라미터를 전달하는 과정에서 실수가 발생했고, 디버깅을 진행하면서 에러 메시지를 확인한 이후에야 뒤늦게 관련 내용을 정리하게 되었다.
    즉, 개념을 충분히 구조화하지 않은 상태에서 구현을 먼저 진행한 것이 비효율로 이어졌고, 사전에 인자 역할을 명확히 정리했더라면 시행착오를 줄일 수 있었을 것이라고 느꼈다.

- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가? 
  - 기존 전략대로 개념을 먼저 이해하고, 이후 코드에 적용하는 흐름이 잘 맞았으며,
    이를 통해 JdbcTemplate의 동작 방식과 사용 패턴을 보다 명확하게 정리할 수 있었다.
    결과적으로, 이미 알고 있는 SQL과 새로운 기술 JdbcTemplate을 연결하는 데 있어
    현재의 학습 전략이 효과적으로 작용했다고 느꼈다.

### 4. AI 피드백
단순한 문법 암기를 넘어 Template-Callback 패턴의 관점에서 JdbcTemplate의 내부 동작 흐름을 파악하라.
내가 넘긴 람다식이 스프링 내부의 어느 라이프사이클에서 실행되는지 이해하면, KeyHolder와 같이 세밀한 제어가 필요한 복잡한 API도 문법적 혼동 없이 훨씬 논리적으로 사용할 수 있게 된다.

### 5. 다음 타임에 바꿀 것
- 유지할 것과 그 이유 
  - 전체적인 동작 구조를 먼저 머릿속에 그린 뒤, 백지 상태에서 하나씩 구현해보는 방식이 개념의 빈틈을 찾아내는 데 효과적이었다.
    특히 낯선 라이브러리를 처음 접할 때 어떤 부분을 모르는지 식별할 수 있게 해준다.
