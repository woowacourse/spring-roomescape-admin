### 7. 나의 언어로 작성한 학습 문서

(이번엔 좀 적다. ReservationTime을 만드는 것은 Reservation을 만드는 것과 비슷해서 단순 반복이었고, Reservation을 수정하는 것이 어려웠다. 이 내용을 나의 언어로 작성할 수 없었다.)

Reservation의 필드 String time을 ReservationTime로 수정하는데 결국 ReservationTime의 필드 start_at도 String인데 이러면 굳이 클래스로 처리할 필요가 있는건가?

- ReservationTime을 미리 관리자가 등록을 해두고, Reservation이 ReservationTime를 등록해둔 시간 내에서 선택하게 하려는 것이 목적이다.
- 같은 논리라면 String date 필드도 이런식으로 처리해줘야 할 것 같다.



 Reservation으로 요청을 받으면 timeId를 담을 필드가 없다.  timeId 하나만 담을 수 있는 별도 클래스를 만들면 어떨까? 어떤 필드들이 필요할 것 같아?

- 필드에는 기존 Post 요청에서 있던 String name, String date를 포함하고 long timeId를 가지는 RequestBody용 별도의 클래스를 만들겠다. 클래스의 이름은 ReservationRequest 으로 한다.
