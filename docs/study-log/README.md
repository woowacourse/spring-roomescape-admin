## v1

만족할 때까지 스스로 고민한 뒤 결과를 도출하는 것

## v2


**Resourceful 집중**
1. 학습 중 고민 포인트가 발생하면 AI에게 질문한다.
2. AI로 부터 답변을 받은 내용이 이해가 되지 않는다면, AI에게 참고 자료(서적-챕터, 공식 문서, 기술 블로그 등)를 추천받는다.
3. 관련 참고 자료를 확인하고 정리해서 AI에게 피드백을 받아본다.
4. 피드백 과정이 실패한 경우 어느 부분에서 문제인지 기록한다.
5. 기록한 학습 내용을 토대로 리뷰어가 있다면 리뷰어에게 피드백을 받는다.
6. 리뷰어에게 당장 피드백을 받을 수 없는 경우 코치에게 피드백을 받는다.

## v3

1. 가설 기반 질문 (Hypothesis-Driven Inquiry)
    * 학습 중 고민이 생기면 바로 AI에게 묻지 말고, 딱 20분간 스스로 고민하여 나만의 가설을 세운 뒤 질문한다.
    * Action: "내 가설은 [A]인데, 이게 맞는지 확인해줘. 아니라면 반박할 수 있는 근거를 알려줘."

2. 자원 확장 및 심화 (Contextual Resource Expansion)
    * AI의 답변이 모호하거나 이해되지 않을 때, 구체적인 외부 자원(Resource)을 요청한다.
    * Action: "이 개념을 가장 잘 설명하는 [서적의 특정 챕터, 공식 문서의 섹션, 기술 블로그]를 추천해줘."

3. 장난감 모델 검증 및 피드백 (Toy Model & AI Feedback)
   * 확보한 자료를 바탕으로 개념을 정리하고, 가장 작은 단위의 연습 코드(Toy Model)를 짜서 AI에게 피드백을 받는다.
   * Action: "이 개념을 바탕으로 [비유/비즈니스 로직]을 코드로 짜봤어. 내가 이해한 게 맞는지 검토해줘."

4. 의도적 파괴 및 실패 기록 (Sabotage & Failure Logging)
   * 피드백 과정에서 막히거나 코드가 예상과 다르게 작동한다면, 일부러 규칙을 어겨보며(Sabotage) 원인을 파악하고 기록한다.
   * Action: "이 규칙을 어겼을 때 발생하는 문제와 내 해결 시도가 실패한 지점을 [학습 로그]에 기록한다."

5. 리뷰어 피드백 (Social Resource Validation)
   * 기록된 학습 내용과 '가설-실험-실패'의 과정을 들고 리뷰어에게 질문한다.
   * Action: "저는 [가설]을 세우고 [실험]을 해봤는데, [기록된 지점]에서 막혔습니다. 리뷰어님의 생각은 어떠신가요?"

6. 코치 피드백 (Ultimate Expert Resource)
   * 리뷰어 단계에서도 풀리지 않는 철학적/구조적 난제는 최종 자원인 코치에게 가져간다.
   * Action: 앞선 모든 과정의 정수를 모아 최종적인 판단 기준을 세우는 데 도움을 받는다.
