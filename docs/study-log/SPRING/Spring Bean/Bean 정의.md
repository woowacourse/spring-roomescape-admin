Spring Bean이란 Spring Framwork가 관리하는 Java 객체를 의미한다. Bean은 스프링 컨테이너에 의해 생성, 소멸, 관리 되며 스프링의 핵심 기능 중 하나인 Ioc(Incersion of Control)을 구현하는데 사용된다.

> IOC가 뭐지?
> 객체 생성/제어 권한을 개발자가 아니라 프레임워크에 넘기는 것
> 
> 그러면 원래 내가 자바 개발할 때에는 내가 생성을 해서 사용을 했는데, IoC를 통해서 스프링이라는 프레임워크가 직접 생성한다는 건가?

> 객체를 직접 생성하지 않는게 뭐가 장점이지?
> 직접 생성하지 않으면 결합이 낮아지고, 테스트하기 쉽고, 변경하기 쉽기 때문임.
> 
> 만약 직접 생성한다면 테스트 코드에서도 직접 생성해야하는데, 스프링으로 넘기면 테스트할 때도 생성할 필요도 없는거네

1. 의존성 관리 및 제어의 용이성 : 직접 객체 생성해야하는 번거로움 줄여줌
2. IoC : 객체 생성과 의존성 주입을 프레임워크가 관리하도록 함
3. 싱글톤 객체 관리 : 싱글톤으로 관리하여 동일한 객체 재사용
