### 1. 팩터리 메서드를 사용하는 이유
팩터리 메서드는 객체 생성 규칙(검증, 가공, 정책)을 한 곳에 강제하기 위해서 씀.
생성 로직을 숨긴다.
> 근데 생성자를 할때 검증을 넣으면 되는거 아닌가?
> 1. 핵심 한 줄 요약  
    **생성자에 검증 넣는 건 가능하지만, “통제력”과 “의미 표현”에서 팩터리가 더 강력하다.**
>2. 개념 정리 (헷갈리는 부분 중심)
>
>- 네 말 맞음: 생성자에도 검증 넣을 수 있음  
>    → 하지만 문제는 **외부에서 생성자를 계속 직접 호출 가능**하다는 것
>- 핵심 차이
>    - 생성자 public → 아무나 `new` 가능 → **생성 방식 통제 불가**
>    - 팩터리 + 생성자 private → **생성 경로 강제 (단 하나로 고정)**
>- 추가 차이 (중요)
>    1. **이름으로 의도 표현 가능**
>        - `new Member(...)` → 의미 없음
>        - `Member.signUp(...)` → 가입 상황 명확
>    2. **생성 방식 확장 가능**
>        - 캐싱, 다른 객체 반환, 조건 분기 가능
>        - 생성자는 무조건 자기 자신만 생성
>    3. **생성 정책 변경 대응**
>        - 팩터리 내부만 수정하면 됨
>        - 생성자 직접 쓰면 전부 수정해야 함
