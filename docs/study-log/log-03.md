### 4. AI 피드백

- 자신의 학습 전략에 대해 AI 학습 전문가에게 피드백을 요청하고,
  유용했던 제안 1가지 이상 기록

```text
코드 수정 전에 “데이터 흐름 3단계”를 먼저 적는다.

이번 문제에서는 빨간 줄부터 수정하기 전에, 아래 3가지를 먼저 적었으면 훨씬 빨리 원인을 찾을 수 있었을 가능성이 큽니다.

1. 요청 데이터는 어떤 형태로 들어오는가?
예를 들어 예약 생성 요청에서는 다음 값이 들어옵니다.

name
date
reservationTimeId

여기서 중요한 점은 요청에서 ReservationTime 객체가 들어오는 게 아니라, 보통 reservationTimeId가 들어온다는 것입니다.

2. DB에는 어떤 컬럼으로 저장되어야 하는가?
reservation 테이블에는 객체가 아니라 컬럼 값이 저장됩니다.

따라서 저장 시에는 이렇게 생각해야 합니다.

reservation.name → name 컬럼
reservation.date → date 컬럼
reservation.time.id → time_id 컬럼

이번 문제에서는 이 단계가 핵심이었습니다.

time 객체를 저장하려고 하면 안 되고, DB에는 time_id가 들어가야 합니다.

3. 조회 후 객체는 어떻게 복원되어야 하는가?
조회할 때는 reservation 테이블만 보면 time_id만 있습니다.
하지만 응답으로는 ReservationTime 객체나 시간 값이 필요합니다.

그래서 조회 쿼리에서는 join이 필요합니다.

reservation.time_id = reservation_time.id

그리고 RowMapper에서는 join 결과를 바탕으로 다시 객체를 만듭니다.
이렇게 하면 DB의 컬럼 값이 다시 객체 구조로 복원됩니다.

즉, 코드 수정 전에 입력 → 저장 → 조회 흐름을 먼저 잡는 것입니다.
```
