##  학습법 변천사

### 학습법 v1

일단 프로젝트를 시작한다.
이후 막히는 부분과 추가 학습이 필요하다고 생각하는 지점이 발생하면 학습하고 다시 구현을 이어간다.

학습은 다른 크루들의 의견, 구글링, AI 의견을 종합하여 선택한다.

### 학습법 v2

1. 여러 해법이 있다면, PiFSR의 F(Feedback Loop) 활용한다.

   이전의 학습법은 고민의 시간이 너무 길어지는 지점에서 문제가 발생한다.

   빠른 도전과 빠른 실패로 인한 피드백을 반영하여 개선한다.

2. 큰 문제 발생 시, PiFSR의 i(i+1)를 활용

   이전의 학습법은 큰 문제를 쪼개지 않고 해결하려 해서 어디서부터 시작해야 할 지 엄두가 안나는 문제가 발생한다.

   거대한 문제를 마주한다면 작은 문제로 쪼개서 해결한다.

### 학습법 v3

1. 프로젝트 우선순위 전략
    - 개념을 먼저 학습하는 것이 아닌, 프로젝트를 먼저 던져놓고, 필요한 이론을 거꾸로 찾아가는 방식이다.
2. 거대한 문제 발생, i+1을 활용
    - 거대한 문제를 마주하면 작은 문제로 쪼개어 순차 학습한다.
3. 여러 해법 존재, Feedback Loop 활용
    - 나만의 기준이 없을 경우, 어떤 의견이 옳을 지 고민할 때 사용한다.
    - 빠른 도전과 빠른 실패로 인한 피드백을 반영하여 개선하여 문제를 해결한다.
4. 능동적 인출을 위한 '백지 복기'
    - '다시 읽기'가 아니라 '기억해내기'를 통해 학습하기.
    - 학습 후에 그냥 넘어가지 않고, 나만의 언어나 그림으로 정리하는 시간을 갖는다.
5. 지식을 습득할 때, 즉시 시험(Test)을 하기
    - 내가 이해한 것이 맞는지 확인해본다.
    - 간단한 실행을 수행하여 확인해보고, 나선형 학습법을 활용한다.
6. 의도적 디버깅 및 드릴
    - '잘 돌아가는 코드를 짜는 것' 보다 '문제가 생겼을 때 왜 안되는지 이해하는 것'이 더 중요하다.
    - 의도적으로 코드를 망쳐 에러/실패 상황을 만들고 이를 마주하는 것을 통해 실패 사례의 패턴을 인식하도록 한다.
