## V1
원래는 모르는 부분이 생기면 AI에 의존해서 코드를 짜는 경향이 있었는데 레벨을 진행하면서 깊이있는 공부가 필요하다고 생각되는 부분이 있으면
그 부분을 잘 설명해주는 책을 완독하거나 강의를 완강하려고 했었다. 예를 들어, 설계나 TDD의 경우 다뤄야 할 내용이 많기 때문에 이를 잘 설명해주는
책이나 강의를 들으려고 했다. 나는 책이나 강의의 순서대로 공부하는 것을 좋아하기 때문에 지금까지 그렇게 학습했었는데 그러다보니 중간에 끊기는
경우가 많았고, 몇 주 후에는 잘 기억에 남지 않는 경우가 많았다. AI로 학습할 때보다는 기억에 오래 남았지만 순서대로 학습할 때 시간이 너무 많이
걸리는 등 효율이 좋지 않았다. 또한, 가벼운 부분(자바 stream 문법 오류 등)이라고 생각되는 부분은 AI에게 물어보는 경우가 많았는데 이렇게
하다보니 결국 기억에 안남는 부분이 많았다. 

## V2
- 한 번에 넓은 주제를 공부하려고 하지 않고(책 완독 X, 강의 완강 X) 하나의 주제를 정하고 이 부분을 짧은 시간에 학습하려고 한다
- 학습한 내용이 빠르게 휘발되는 것을 방지하기 위해서 mindmap을 통해서 점점 확장해 나가도록 한다(mindmap/obsidian 활용)
- 학습한 내용을 나만의 언어로 다시 바꿔서 설명하도록 노력한다.

## V3
- 역문제 풀이 학습을 적용한다(기술을 공부하지 않고 문제 상황을 먼저 만든다)
    - 왜 이런 문제가 생겼을까?
    - 어디를 봐야 할까?
    - 어떤 개념이 필요한가?
- 지금 당장 학습해야 하는 범위를 정하기 위해서 명사형 주제보다 동사형 주제를 선정한다. (Gradle dependency 공부 X, task와 dependency의 차이는 무엇일까?)
- Primary Source 하나만 정한다(여러 자료 같이 공부 X)
  1. 공식문서
  2. AI 설명
  3. 책
  4. 블로그
- Primary Source로 개념 이해가 잘 되지 않으면 Secondary Source로 넘어간다.
- 이론을 70% 이상 공부했으면 실제 실습을 진행한다(이론은 최대 1시간 이상 공부하지 않는다)
- 모르는 개념이 나왔을 때 15분 내로 이해되지 않으면 키워드만 적어두고 넘어간다
- 학습한 내용이 빠르게 휘발되는 것을 방지하기 위해서 mindmap을 통해서 점점 확장해 나가도록 한다(mindmap/obsidian 활용)
- 학습한 내용을 나만의 언어로 다시 바꿔서 설명하도록 노력한다.
