## 학습 로그 #3

**시간**: 04/30 12:40 ~ 12:54 (약 15분)
**학습 범위**: 3단계 시간관리 api 테스트 중 Not Acceptable 에러 해결

### 1. 막힌 것의 종류
이번에 막힌 것은 어떤 종류의 어려움이었는가? (해당하는 것에 체크)
- [ ] 개념 자체를 모르겠다 (예: "스프링 빈이 뭔지 모르겠다")
- [ ] 개념은 알겠는데 코드로 어떻게 쓰는지 모르겠다 (예: "JdbcTemplate 문법을 모르겠다")
- [ ] 코드는 돌아가는데 이게 맞는 건지 모르겠다 (예: "계층 분리를 이렇게 해도 되나?")
- [x] 기타: 트러블 슈팅 (시간 추가 api 응답이 정상적으로 반환되지 않는 문제 해결)

### 2. 이번 타임의 학습 전략
실제로 어떻게 학습했는지 디테일한 과정을 써보세요.
1. 문제가 발생한 상황에 대해서 기록한다.
   - 요청 데이터
   - 응답 데이터
   - 예외 로그
2. 로그를 기반으로 문제 원인을 추측해보고 시도해본다.
3. 로그의 예외 클래스에 적힌 주석을 확인하고 원인을 추측한다.
4. 이전에 동일한 문제를 겪은 적이 있는지 생각하고 참고한다.

### 3. 전략 평가
- 효과적이었던 것과 그 이유
로그에 나오는 예외 클래스에 들어가서 주석을 확인한다.

- 비효과적이었던 것과 그 이유
단순히 로그만 보고 원인 추측 후 해결을 시도하는 것이 효과적이지 않았다.
정보가 부족한 상태에서 해결 시도는 오히려 상황을 악화시킨다.
로그만 봤을 때는 요청 dto를 파싱하는 과정에서 문제가 생겼다고 판단했다. 
하지만 결과적으로 응답 dto를 정상적으로 생성할 수 없었기에 발생한 문제였다.
로그만 봐서 문제 원인 지점을 명확히 판단할 수 없다면 섣부른 해결 시도를 하지 않는 것이 옳다.

- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
적절하다. 트러블 슈팅 과정에서 단순히 로그를 확인하는 것 외에 발생한 예외 클래스에 들어가서 어떤 경우에 발생되는 예외인지를 확인하는 과정이 문제 원인 파악에 도움이 된다.

### 4. AI 피드백
제안: '실패 재현 테스트 코드(Negative Test) 작성' 단계 추가
가장 유용할 것으로 판단되는 개선책은 해결 직후 혹은 시도 과정에서 "해당 예외를 의도적으로 발생시키는 최소 단위의 테스트 코드를 작성하는 것"입니다.

해당 제안을 기반으로 생각해봤을 때, 예외 상황 해결을 시도해보는 과정에서 처음 상황이 오염될 가능성이 있습니다.
트러블이 발생하면 해당 상황을 해결 하기 위한 브랜치를 생성해서 해결을 시도하는 것이 적절할 것이라 판단됩니다.

### 5. 다음 타임에 바꿀 것
- 유지할 것과 그 이유
에러 발생 시 로그 내 예외 클래스에 작성된 주석을 확인하는 과정을 수행한다.

- 바꿀 것과 그 이유
문제 원인을 추측해보고 시도해볼 때 브랜치를 생성하여 시도한다.
이유는 문제 해결을 시도하는 과정에서 상황이 오염되어, 여러가지 문제점이 추가로 발생할 수 있다고 생각된다.
