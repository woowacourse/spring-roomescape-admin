### 2. 이번 타임의 학습 전략
- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?

#### 1단계: 가벼운 개념 스캐닝 (기존 강점 유지)

실행: 기존처럼 책의 큰 흐름을 읽고, AI를 통해 핵심 개념을 빠르게 파악합니다.
목표: 깊은 이해보다는, 뇌의 분산 모드(Diffuse Mode)를 활용해 새로운 기술이 어떤 문제를 해결하기 위해 등장했는지 '지도'만 그리는 단계입니다.

#### 2단계: 초소형 샌드박스 구축 (장벽의 해체)

실행: 거대한 프레임워크나 기존 코드베이스는 철저히 배제합니다. 오직 순수 자바(Java)의 main 메서드 단 하나만 존재하는 빈 프로젝트를 엽니다. 이곳에서 Virtual Thread를 생성해 콘솔에 'Hello World'를 찍어보는, 가장 초라하고 원시적인 형태의 코드 딱 10줄만 작성합니다.
전문가의 멘탈 모델: 뇌가 두려움을 느끼지 않도록 진입 장벽을 밀리미터 단위로 낮추는 작업입니다. 외부 요인이 완벽히 통제된 안전한 모래놀이터(Sandbox)에서 성공을 경험하면, 뇌는 비로소 이 기술을 다룰 수 있다는 작지만 단단한 '청크(Chunk)'를 형성합니다.

#### 새로운 학습법 V4 신규 전략: 설계 리트머스 테스트
코드가 동작하지만 설계가 맞는지 확신이 없을 때

설계가 맞는 확신이 없는 상황에서는 작성했던 학습법이 무의미 하였습니다.
코드 동작은 알지만 이를 확신의 영역으로 넘기는 과정에서는 새로운 학습법이 필요하였습니다.

이번에는 새로운 개념들에 대한 이해가 필요하였습니다.
- JdbcTemplate
- Jackson 직렬화, 역직렬화,
- H2
- yml, properties 차이점
- runtimOnly, implements 차이점
- KeyHolder
- SimpleJdbcInsert
등등 AI와 빠른 프로토타입 개념을 익히고 숙지하며 바로 적용을 해보았습니다.

두려움을 느끼지 않도록 돌아가는 코드를 만드는 것에 초점을 맞췄습니다.

### 3. 전략 평가
- 효과적이었던 것과 그 이유
빠르게 AI에게 핵심 개념만 파악하고 바로 적용하면서 어떻게 쓰이는지 이해하는 과정에서 도움이 되었습니다.
이과정에서 궁금점들이 생긴 것들을 간단하게 따로따로 기록을 해두었습니다.

- 비효과적이었던 것과 그 이유
하지만 바로 적용을 해보면서 시간이 빠르게 돌아가는 코드를 만들 수 있었지만,
깊은 이해는 부족하였습니다.
다양한 키워드들을 뽑을 수 있었지만, 어떻게 적용 되어야 하는지에 대한 세부적인 개념은 파악할 수 없었고,
궁금점들이 많이 생겼습니다.

- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
살짝 맞지 않는거 같았다.
지금 구현해야하는 것에 초점을 맞춰서 개념 파악 -> 궁금점 생김 -> 궁금점 해결 -> 심도 있게 탐구
이 과정이 부족했던거 같습니다.

- 바꿀 것과 그 이유
V3 2단계에서 순수 Java 개념이 아닌 프레임워크 개념의 경우 수정
- 프레임워크 통합 개념 (JdbcTemplate, Jackson 등): 프레임워크 맥락 안에서만 의미가 있는 개념이므로, 기존 프로젝트에 직접 적용하되 딱 하나의 기능만 동작시키는 것에 집중한다. 한 번에 모든 것을 적용하려 하지 않는다.
