### 1. 막힌 것의 종류
이번에 막힌 것은 어떤 종류의 어려움이었는가? (해당하는 것에 체크)
- [ ] 개념 자체를 모르겠다
- [ ] 개념은 알겠는데 코드로 어떻게 쓰는지 모르겠다
- [ ] 코드는 돌아가는데 이게 맞는 건지 모르겠다
- [x] 기타: 무엇을 모르는지 모르겠다.

1~2단계는 시작 전에 "이건 궁금하다"는 키워드를 스스로 잡을 수 있었다.
3단계는 달랐다.  미션 테스트 돌아가는 데만 집중해서 그런지 솔직히 궁금한 게 없었다. 그렇다고 다 아는 것도 아니었다. 
예를 들어 Repository 클래스에 `Component`를 달아놓았는데, `@Repository`를 안 달았어?라는 질문에 답을 하지 못했다.
모르고 있었지만, 모르는 줄도 몰랐다.

### 2. 이번 타임의 학습 전략

- 이번 단계에서 가장 크게 깨달은 것
  - "나는 무엇을 모르는지 찾애는 것부터 약하다. 그래서 전략을 살짝 바꿨다."
- 평소의 나: 궁금한 키워드를 먼저 잡고 AI에게 질문
- 이번: AI에게 이 단계에서 무엇을 학습하면 좋을지 먼저 물어보았다.
  - 받은 질문을 하나씩 종이에 옮겨적었다.
  - 하나씩 답을 떠올려보고 다시 AI에게 검증하는 식으로 했다.

질문 예시
```aiignore
- 객체 세계와 데이터베이스 세계의 패러다임은 어떻게 다른가?
- 도메인 간 의존관계가 생겼을 때 어떻게 처리해야 하는가?
- jdcbTemplate.update()는 왜 int를 반환할까?
- 동작은 하지만 controller/repository 내에 시간 관련 로직을 같이 둬도 되는가?
- 트랜잭션 처리는 어떻게 할까?
- @Component / @Repository / @Service 차이는 뭘까?
```

### 3. 전략 평가

1. 효과적이었던 것과 그 이유
: 스스로 방향을 잡지 못할 때 AI에게 학습 주제 자체를 물어보는 것 자체가 좋았다. 처음에 어떤 걸 집중적으로 학습해야 하는 지 막막했는데, 의외로 잘 맞았다.

2. 비효과적이었던 것과 그 이유
: 모르는 부분을 책을 통해 학습하려고 했지만 막상 궁금한 내용을 제공하는 책이 어느 부분에 존재하는 지 바로 판단하기 힘들었다. 만약 책이 있더라도 지금 가지고 없는 책이라면 더욱 힘들었다. 
내가 궁금한 게 없는데 학습이 되긴 할까?라는 의구심이 들어서 초반에는 수동적인 학습이 됐다.

3. 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
: 무엇을 모르는지 모르겠다 상태이면 AI에게 학습 방향을 먼저 받는 것이 잘 맞는 것 같다. 궁금한 게 없는 상태로(모르는 상태로) 다음 단계를 넘어가는 것보다 훨씬 나앗다. 
단, 받은 질문을 그대로 따라가면 수동학습이 되니깐 중간에 "나의 답"을 먼저 적는 걸 추가해 능동학습으로 만드는 게 중요한 것 같다.
