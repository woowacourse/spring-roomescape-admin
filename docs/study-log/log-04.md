### 2. 이번 타임의 학습 전략

### 3. 전략 평가
- 효과적이었던 것과 그 이유
막혔을 때, 
- 이 개념이 모르는 것인지 -> 단계 1부터 실행, 
- 개념을 알겠는데 코드를 어떻게 구현해야할지 모르겠다 -> 2단계에 중점적으로 실행,
- 코드는 돌아가는데 이게 맞는 건지 모르겠다 -> 3단계에서 실행 하여 의도적으로 파괴한다.

3번째 기준을 이렇게 세웠을 때 효과적이었다.

**무엇을 파괴할 것인가 — 3가지 기준:**

1. **경계 조건 파괴** — 정상 입력이 아닌 것을 넣어본다
  - 없는 id로 조회/삭제하면 어떤 에러가 나는가?
  - null이나 빈 값을 넣으면 어디서 터지는가?
  - 숫자 필드에 문자열을 넣으면 어디서 막히는가?

2. **연결 고리 파괴** — 두 개념이 맞닿는 지점을 끊어본다
  - JOIN 쿼리의 컬럼명을 하나 틀리면 어떤 에러가 나는가?
  - JSON 필드명과 Java 필드명이 다르면 역직렬화가 어떻게 실패하는가?
  - 매핑 키를 바꾸면 어디서 null이 되는가?

3. **순서 파괴** — 의존성의 순서를 바꿔본다
  - 이 설정이 없으면 어디서 먼저 터지는가?
  - 어떤 Bean이 먼저 만들어져야 하는가?

- 비효과적이었던 것과 그 이유
시간이 되게 오래걸렸다. 의도적인 파괴의 기준을 판단하기가 어려웠습니다.
의도적으로 무엇을 파괴해야하는지 판단해야하는게 어려웠습니다.

- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
코드는 돌아가는데 그게 왜 그렇게 돌아가는지 애매할 때, 판단하는게 어려웠습니다.
