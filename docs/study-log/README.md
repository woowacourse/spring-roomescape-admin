# 학습법 변천 과정

## 학습법 v1

```text
레벨1에서는 먼저 코드를 작성해보고, 막히면 강의나 책, AI, 공식문서를 참고하는 방식으로 학습해왔다.
특히 리뷰를 통해 내가 놓친 부분을 발견하고 개선하면서 많이 성장했지만, 혼자 더 좋은 코드를 고민하는 시간이 길어져 진행이 느려지는 경우가 많았다.

모르는게 있으면 예전에는 AI에게 먼저 물어보는 편이었지만, 장기 미션부터는 공식문서처럼 신뢰할 수 있는 자료를 직접 찾아보려 노력했다.
다만 공식문서를 찾는 데 시간이 오래 걸리고, 문서만으로는 좋은 사용법이나 동작 원리까지 알기 어려워 블로그나 AI에 다시 의존하기도 했다. 또 책이나 강의를 통해 개념을 이해하려 했지만, 직접 적용해보지 않으면 금방 잊어버리는 한계가 있었다.

그래서 레벨1의 나는 리뷰와 경험을 통해 배우는 데 강점이 있었지만, 완벽하게 하려다 멈추는 습관과 자료를 실제 경험으로 연결하는 연습이 부족했던 것 같다.
```

# 학습법 v3

## 전체 과정

```text
막힌 지점 찾기
→ 질문 하나로 바꾸기
→ 20~30분만 찾아보기
→ 바로 작은 코드로 확인하기
→ 프로젝트에 적용하기
→ 한 줄 기록하기
```

---

## 1. 막힌 지점 찾기

너무 크게 잡지 않는다.

```text
Spring Security를 모르겠다 ❌
```

이렇게 좁힌다.

```text
Controller에서 로그인한 사용자 ID를 꺼내는 방법을 모르겠다 ⭕
```

좋은 기준
> **기술 이름이 아니라, 지금 코드에서 안 되는 부분으로 표현한다.**

---

## 2. 질문 하나로 바꾸기

검색하기 전에 질문을 하나로 만든다.

```text
지금 필요한 질문:
JWT 인증 후 Controller에서 현재 사용자 ID를 어떻게 가져오는가?
```

- 질문이 작아야 검색도 짧아진다.

---

## 3. 20~30분만 찾아보기

자료를 오래 보지 않는다.
딱 3가지만 확인한다.

```text
이게 왜 필요한가?
어떻게 쓰는가?
자주 나는 오류는 무엇인가?
```

지금 안 쓸 내용은 넘긴다.

```text
전체 구조
고급 옵션
역사
성능 최적화
```

---

## 4. 바로 작은 코드로 확인하기

프로젝트 전체를 고치기 전에 작게 확인한다.

예시:

```text
GET /me API 만들기
→ 현재 로그인한 userId가 잘 나오는지 확인
```

작게 성공하면 실제 코드에 넣는다.

---

## 5. 프로젝트에 적용하기

처음 문제만 해결한다.

```text
게시글 작성 API에서 현재 userId 연결하기
```

아직 다른 것까지 건드리지 않는다.

```text
인증 구조 전체 리팩토링 ❌
refresh token 추가 ❌
권한 관리 전체 설계 ❌
```

---

## 6. 한 줄 기록하기

마지막에 길게 정리하지 않는다.

```text
문제:
Controller에서 현재 사용자 ID가 필요했다.

해결:
@AuthenticationPrincipal로 인증된 사용자 정보를 받았다.

주의:
token이 없거나 잘못되면 Controller 전에 실패해야 한다.
```
