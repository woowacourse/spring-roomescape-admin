## 학습 로그 #1

**시간**: 04/29 23:30 ~ 02:00 (약 2시간 30분)
**학습 범위**: 1단계 — 웹 요청-응답 (MVC, 메모리 저장)

### 1. 막힌 것의 종류
- 개념을 어렴풋이만 알고있다
- 개념은 알겠는데 코드로 어떻게 쓰는지 모르겠다
- 코드는 돌아가는데 이게 좋은 코드인지 모르겠다

> 개념(DispatcherServlet 흐름)은 알고 있었지만 설명할 수 있는 정도는 아니었다
> AtomicLong / ResponseEntity / @PathVariable 등 실제 코드 사용법을 몰랐다
> entity 패키지 네이밍, 인터페이스 분리 필요성 등 최선의 설계 판단이 서지 않았다

### 2. 이번 타임의 학습 전략

- 이전에 바꾸기로 한 전략: PiFSR + 모르는 것 중 중요하지 않은 것들은 일단 키워드 메모해두고 넘어가기
- 실제 학습 과정
  1. 학습 5원칙 적용 — Output First로 테스트 파일 먼저 확인하고 목표 정의
  2. DispatcherServlet 흐름을 직접 말로 설명한 뒤 구현 시작
  3. AtomicLong, ResponseEntity, @PathVariable vs @RequestParam 등 막히는 개념은 AI 강의 모드로 WHY부터 이해
  4. 에러 발생 시 원인 파악 후 트러블슈팅 문서 작성 (`-parameters` 플래그 이슈)
  5. 구현 완료 후 코드 리뷰로 개선 포인트 확인

### 3. 전략 평가
- **효과적이었던 것**
  - Output First: 테스트 파일로 목표를 먼저 잡으니 방향이 흔들리지 않았다
  - 개념을 WHY부터 설명받으니 이 코드를 왜 공부해야 하는지 이해됐다
    - AtomicLong 동시성 등에 대한 학습
  - 에러를 트러블슈팅 문서로 정리하니 원인-해결 흐름이 명확해졌다

- **비효과적이었던 것**
  - 학습이나 트러블슈팅 문서화에 시간을 쓰느라 진도를 빠르게 치고나가지 못했다

- **막힌 것의 종류와 전략의 궁합**
  - 코드로 어떻게 쓰는지 몰랐을 때 AI 강의 모드로 간단히 학습하고 바로 타이핑하니 체화가 잘 됐다
  - 이게 맞나? 하는 올바른 객체지향이나 아키텍처 등에 대한 의문은 아직 해결되지 못했다 (일단 넘어가기로 했다..)

### 4. AI 피드백
- 강의모드 활용 시 궁금했던 개념을 WHY부터 설명해주니 조금 더 기억에 오래 남는다
