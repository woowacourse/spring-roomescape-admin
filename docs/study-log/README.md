# 학습법 v3

## 1. 문제 앵커 고정

해결하고 싶은 문제가 명확하면:

나는 [개념/기술]을 배워서
[현재 상황]에서
[해결하고 싶은 문제]를 해결하고 싶다.
왜냐하면 [이 개념을 배워야 하는 이유] 때문이다.

문제가 모호하면:

나는 [개념/기술]이
어떤 상황에서 필요하고, 어떤 문제를 해결하는지 알고 싶다.

또는

나는 [개념/기술]이
어떤 한계를 극복하기 위해 탄생했는지 알고 싶다.

## 2. 개념 정리 카드 작성

공식문서와 AI를 이용해 개념을 수집하되,
개념을 바로 목차처럼 정리하지 않는다.

다음 순서로 정리한다.

1. 공식문서의 목적 문장
2. 이 기술이 등장하는 문제 상황
3. 기존 방식의 불편함
4. 이 기술의 핵심 해결 구조
5. 지금 필요한 개념
6. 나중에 볼 개념
7. 실험을 위한 개념 순서

## 3. 가장 작은 실험 만들기

실험이 가능하다면,
개념을 완벽히 공부하기 전에 문제에 가까워지는 최소 실험을 만든다.

실험은 다음 조건을 만족해야 한다.

- 1시간 안에 시도 가능하다.
- 성공/실패를 관찰할 수 있다.
- 오늘의 문제와 직접 연결된다.
- 새로운 개념을 너무 많이 요구하지 않는다.

## 4. 막히면 Stuck Log 작성

- 무엇을 하려고 했는가?
- 기대한 결과는 무엇인가?
- 실제 결과는 무엇인가?
- 어디서 막혔는가?
- 이 막힘은 개념 부족, 구현 문제, 설정 문제, 방향성 문제 중 무엇인가?
- 내 가설은 무엇인가?
- 다음에 확인할 가장 작은 것은 무엇인가?
