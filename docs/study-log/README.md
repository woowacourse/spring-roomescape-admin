### 학습법 v1 -> v2 -> v3

**1️⃣ v1** (레벨1 학습법)

공부하고 싶은 것이 생기면, 책/강의를 먼저 보는 편이다. 
(객체지향의 사실과 오해, 헤드퍼스트 디자인 패턴)책의 앞에서 부터 순차적으로 읽었고, 
각 챕터별로 한번 읽고 노션에 해당 내용을 정리하는 방식으로 공부하였다. 
여기까지만 해도 한 챕터에 꽤 많은 시간을 썼었기에, 실제로 코드를 작성해보는 등 해당 내용을 적용해보지는 않았다.

미션 중 객체지향 설계를 하면서 수많은 고민지점이 있었다. 
1시간 정도 혼자 고민하다가 해결이 안되면 참고자료를 찾아봤다. 
이때는 공식 문서나 구글링 보다는 AI를 우선적으로 활용했다. 
때때로 다른 크루들과 토론을 통해 해당 고민을 해결했었다.

미션을 하다가 특정 문법이나 개념이 기억이 안나면 정리해둔 노션문서를 찾아봤다. 
만약 정리해둔 내용이 없거나 있는데 부족하다 싶으면 AI를 사용했고, 해당 내용을 다시 정리하였다.

**2️⃣ v2** (Problem-Driven 학습법)

1. **Problem-Driven**

   > 이걸 왜 배우지? 먼저 정의
   >

   예시: “Controller 왜 쓰지?”, “서비스 레이어 왜 나누지?”

2. **i+1**

   > 한번에 하나의 키워드만 정해서 무엇인지만 이해하기
   >
    - ❌ “Spring MVC 전체”
    - ✅ “@Controller 역할 하나만”
3. **Output**

   > 가설을 설정하고 직접 만들어보기
   가설은 아무자료 없이 사전 지식으로만
   >
    - @Controller는 ~~일 것이다.
    - Controller 없이 코드 작성해보기
4. **Input**

   > 만든 결과물을 AI를 통해 검증 및 알아야 하는 개념 추천받기
   >
    - “내가 이렇게 이해했는데 뭐가 틀렸어?”
    - “추가적으로 알아야 하는 내용 추천해줘”
5. **Takeaways**

   > 학습한 내용 최종 정리하기
   이전처럼 전체 개념 정리 X
   >
    - 핵심 개념
    - 적용한 결과물
    - 다음에 적용할 것

      예시:

        - 다음부터 HTTP 요청 처리 로직은 Controller에만 둔다
        - 비즈니스 로직은 절대 Controller에 넣지 않는다

**3️⃣ v3** (AI가 개선한roblem-Driven 학습법)

1. **Problem-Driven**

   > 이걸 왜 공부하지? 먼저 정의
   >

   예시: “Controller 왜 쓰지?”, “서비스 레이어 왜 나누지?”

2. **i+1**

   > 한번에 하나의 키워드만 정해서 무엇인지만 이해하기
   >
    - ❌ “Spring MVC 전체”
    - ✅ “@Controller 역할 하나만”
3. **Output**

   > 가설을 설정하고 직접 만들어보기
   가설은 아무자료 없이 사전 지식으로만
   >
    - @Controller는 ~~일 것이다.
    - Controller 없이 코드 작성해보기
4. **Input**

   > 만든 결과물을 AI를 통해 검증

5. **Self-Explanation**

   > Output 내용을 기반으로 해당 학습내용을 스스로 설명해보기
   막히는 경우, 해당 부분만 다시 AI에게 Input.

6. **Takeaways**

   > 학습한 내용 최종 정리하기
   이전처럼 전체 개념 정리 X
   
    - 핵심 개념
    - 적용한 결과물
    - 다음에 적용할 것

      예시:

        - 다음부터 HTTP 요청 처리 로직은 Controller에만 둔다
        - 비즈니스 로직은 절대 Controller에 넣지 않는다
7. **Backlog**

   > 나중에 알아야 할 것 같은 개념이나 더 깊은 개념이 있다고 느껴지는 부분 기록 해두기.
   학습은 추후 Problem Driven이 확고해질 때 다시(예: 프로젝트 하다가 막힌 경우)
