### 7. 나의 언어로 작성한 학습 문서

application.properties 파일? 

- 스프링 앱의 설정 파일, 앱 동작(DB, URL, 포트 등) 설정

schema.sql을 resources 디렉터리에 저장하는 이유가 뭐지? (개념 모름)

- 기존 List, AtomicLong 기반 ID는 인메모리 DB 형태였는데, 이제 h2 DB에 저장하려고 한다. 
- spring 앱이 시작될 때, 테이블이 있어야 하는데 자동으로 spring이 이 schema.sql 파일을 자동으로 찾아서 sql을 실행시켜준다.
- 레벨1 장기에선 프로그램 처음 시작할 때, InitDatabaseTable 클래스를 통해서 테이블 초기화 쿼리문을 실행하도록 직접 설정했는데, spring은 자동으로 해주나보다.

현재(1단계에서 마무리 한 코드 기준) ReservationController가 List + AtomicLong으로 예약을 관리하고 있잖아. 2단계에서 이걸 JdbcTemplate으로 바꿔야 하는데, Controller가 JdbcTemplate을 직접 들고 있는 게 맞을까? 어떻게 생각해?

- Controller가 DB 관련 코드를 몰라야한다는 레벨1의 규칙이 이어져야 할 것 같다. 그럼 별도의 계층이 필요할 것 같은데, @Repository 계층이 추가되어야 할 것 같다.

Controller에서 Repository를 어떻게 주입받아야 할까?

-  Controller에서 @RestController를 달았던 것은 Spring한테 이 클래스를 관리해줘라고 선언한 것이다. 이렇게 Spring이 관리하는 객체를 빈(Bean)이라고 한다.
  - 빈 끼리는 서로 주입받을 수 있다.

근데 이런식으로 IoC 컨테이너가 빈을 모두 관리하고 필요한 곳에 주입해준다면 계층분리가 필요 없는 것 아닌가?

- IoC는 전역 인스턴스 저장소 같은 곳이라고 생각해도 된다.
- 주입을 편하게 해주는 것은 맞는데, 역할 구분 자체를 없애는 것은 아니다. 만약 DB코드가 수정되어야 하는데 그 때, Controller가 수정되는 구조는 어색하다.

insert 함수를 하고 return으로 Reservation 객체를 넘겨줘야 하는데 jdbcTemplate 메서드의 update를 활용하면, 영향받은 행 수만 리턴받을 수 있다. 어떻게 할 것인가?

- KeyHolder를 활용해서 삽입 혹은 수정한 객체의 id를 받아올 수 있다.

update 함수에서 delete 할 때, 만약 삭제할 원소가 없다면 결과는 어떻게 되어야 하는가?

- 영향받은 행수가 0개라면 그것대로 알려야 할 것 같은데, Status 코드를 200을 줘야할지 에러를 줘야할 지 감이 잘 안온다. 상황에 따라 다르지 않을까?
- 지금 상황에서 나의 생각은 삭제하려는 예약이 없는 상태라는 것을 return 해주면 좋을 것 같다. 이 결정은 일단 나중으로 미루도록 하겠다.

JdbcTemplate 내부에서 벌어지는 일

1. connection 열기
2. PreparedStatement 생성
3. 파라미터 바인딩
4. SQL 실행
5.  ResultSet 처리 또는 영향받은 행 수 반환
6. connection, statement 닫기
