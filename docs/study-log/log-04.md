**학습 범위**: 4단계 계층 분리

### 단계 전환 체크
- 이전 단계에서 쓴 접근법을 그대로 쓸 것인가, 바꿔볼 것인가?
  - 바꿔본다.
- 바꾼다면 왜? 바꾸지 않는다면 왜?
   - 이번 단계에서도 내가 도전할 수 있는 부분이 분명 존재한다. 3단계와 차별화하여 학습 방식을 개선하기 위해 AI를 사용하기 전에 스스로 구현에 도전한다.
- 이전 단계에서 발견한 "나에게 맞는 전략"이 새 단계에서도 통할 것 같은가?
   - 막히는 부분이 생길 때 바로 답을 찾을 수 있다는 점에서 통할 것 같다.

### 1. 막힌 것의 종류

- [x] 코드는 돌아가는데 이게 맞는 건지 모르겠다 (예: "계층 분리를 이렇게 해도 되나?")
- [ ] 기타: ___

### 2. 이번 타임의 학습 전략
- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?
  - AI를 사용하기 전에 생각하고 코드를 직접 추가해본다. 이 때, 부담갖지도 걱정하지도 않고 조금만 도전해본다. 만약 막히는 부분(스스로 스트레스를 받는 부분)에서 즉히 AI를 통해 필요한 정보를 제공 받는다.
- 실제로 어떻게 학습했는지 디테일한 과정을 써보세요.
  - 컨트롤러의 책임을 dao로 분리했지만, service에는 어떤 로직이 포함되어야 하는지 알 수 없었다. 즉시 AI를 통해 현재 구조에서 service를 추가한다면 어떤 부분이 분리되어야 할지 알아내고 적용했다.

### 3. 전략 평가
- 효과적이었던 것과 그 이유
  - 스스로 도전해본 부분이 있기에 이전보다 이해도가 높다는 느낌을 받았다. 또한, 학습 스트레스가 크게 줄었다. 어차피 모르면 AI로 잘못을 바로잡을 수 있다는 생각에 도전과 실패에 부담이 없었다.
- 비효과적이었던 것과 그 이유
  - AI를 안 쓰고 최대한 구현해보는 것보다는 배움이 적었던 것 같지만, 스트레스 받지 않고 지속가능하다는 점에서 비효과적인가?에 대한 질문에는 고민이 필요한 것 같다.
- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
  - 적당히 좋았다. 코드가 돌아간다는 것은 알고 있는 지식의 활용이 필요하다는 것인데, 도전하고 실패하고 피드백 받는 것이 빠르게 이루어졌다.

### 4. AI 피드백
- 자신의 학습 전략에 대해 AI 학습 전문가에게 피드백을 요청하고,
  유용했던 제안 1가지 이상 기록
  - AI를 '코드 생성기'가 아닌 '설계 리뷰어'로 활용하기
    - 새로운 도메인 기능이나 예외 처리를 추가해야 할 때, 일단 내가 생각하는 가장 합리적인 위치에 코드를 작성한다.

    - 작성한 코드를 AI에게 보여주며 "이 코드가 서비스 레이어의 책임에 부합하는가?" 혹은 "더 나은 분리 방법이 있는가?"라고 질문하여 이유(Why)를 듣는다.

    - AI의 설명을 듣고도 "그냥 코드로 짜줘"라고 말하고 싶어지거나, 계층 분리 원칙보다 '빠른 구현'에만 마음이 급해지면 5분간 심호흡하며 학습의 목적을 되새긴다.
