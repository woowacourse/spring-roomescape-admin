### 2. 이번 타임의 학습 전략
- 이전에 바꾸기로 한 전략
    - 검색 엔진을 사용하지 않고, AI만을 활용해서 개념 학습을 진행한다.
    - 학습을 시작하기 전에 "이 학습이 끝났다고 판단할 기준"을 먼저 정한다.
    - 학습 시작 전, "이 학습의 완료 조건: ___를 구현할 수 있다."를 먼저 생각해라.
    - AI에게 묻기 전, 내가 이미 아는 것과 모르는 것의 경계를 먼저 쓴다. 경계 지점만 질문한다.
    - 꼬리 질문이 생겼을 때 이렇게 자문한다. "이걸 몰라도 지금 당장 코드를 한 줄이라도 쓸 수 있는가?" 쓸 수 있으면 꼬리 질문을 메모만 하고 멈춘다. 쓸 수 없으면 그것이 다음 질문이 된다.
    - 개념을 먼저 배우고 코드를 짜는 것이 아니라, 코드를 먼저 짜다가 막히는 지점에서만 AI에게 묻는다.
- 실제 학습 과정
    1. 다른 검색 엔진을 사용하지 않고, AI만을 이용해서 지식을 습득했다.
    2. 미션을 진행하다가 헷갈리거나 궁금해서 막히는 부분이 생기면 노션에 궁금한 것을 작성한 후에 해당 질문에 대해 "내가 알고 있는 것", "내가 모르는 것", "당장 미션 수행에 필요한 지식인지"를 검토했다.
    3. 당장 미션 수행에 필요한 지식이라면, 모르는 것에 대해 AI에게 질문했다. 
    4. AI의 답변을 읽으면서 개념을 정리하고, 새롭게 생기는 질문들을 노션에 작성했다.
    5. 노션에 새롭게 작성한 질문들에 대해서도 검토를 진행하며 꼭 필요한 질문이라면 추가적으로 학습했고, 나중에 찾아봐도 되는 질문들이라면 일단 넘어갔다.

### 3. 전략 평가
- 효과적이었던 것과 그 이유
    - AI에게 질문하기 전에 내가 아는 것과 모르는 것을 생각하다 보니 질문이 좀 더 명확해졌다.
- 비효과적이었던 것과 그 이유
    - 질문을 하기 전에 질문을 검토하며 아는 것과 모르는 것의 경계를 먼저 썼는데, 이 과정이 반복되다 보니 꽤 많은 시간이 소모되었다.
    - 학습의 완료 조건을 ___을 구현할 수 있다로 설정했으나, 이 조건 또한 명확하지 않아서 학습 방식이 **미션 구현 -> 개념 이해**로 바뀌는 것을 경험했다. 그러다 보니 자연스레 미션 진행 시간이 길어졌다.
- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
    - 적절한 방법이었다고 생각한다.
    - 2단계 미션을 하면서 크게 어렵거나 이해하지 못 한 개념들을 접하지 못 했는데, 그래서 더 깊게 파지 않고 딱 미션 수행에 필요한 부분만 학습해도 크게 어색하지 않았다.

## 다음 단계 적용 전략

**질문 처리 방식**

질문이 생기면 두 가지로 즉시 판단합니다. 이 판단은 이제 적지 않고 머릿속에서만 합니다.

```
이거 모르면 코드 한 줄도 못 쓴다 → 즉시 AI 질문 (블로킹)
이거 몰라도 일단 쓸 수 있다 → 노션에 키워드만 메모하고 계속 진행 (비블로킹)
```

**학습 완료 기준**

구현 전과 후를 분리합니다.

```
구현 전 → "이걸 알면 코드 한 줄 쓸 수 있는가?" → Yes면 시작
구현 후 → "이걸 모르면 내가 짠 코드를 나중에 내가 못 고치는가?" → Yes면 그때 더 학습
```

@Repository처럼 왜 되는지 궁금한 것은 일단 구현을 먼저 완성한 후에 내려갑니다.

**AI 답변 처리 방식**

```
답변을 끝까지 읽는다
→ 창을 닫는다
→ 기억나는 것만 먼저 쓴다
→ 창을 열어 빠진 부분만 다른 색으로 보완한다
```

- 유지할 것과 그 이유

        - 이유 : 분류함으로써 학습의 방향을 잃지 않을 수 있었고, 그로 인해 미션 진행의 속도도 잃지 않을 수 있었다.
- 바꿀 것과 그 이유
    - 변경 전 : AI에게 묻기 전, 내가 이미 아는 것과 모르는 것의 경계를 먼저 쓴다.
    - 변경 후 : AI에게 묻기 전, 내가 이미 아는 것과 모르는 것의 경계를 검토한다.
        - 이유 : 매 질문마다 아는 것과 모르는 것을 작성하다 보니 시간이 적지 않게 소모되었다고 생각한다. 이번 2단계 미션에서 매 질문마다 아는 것과 모르는 것의 경계를 쓰는 연습을 하면서 질문하기 전에 질문을 구체화하는 단계를 거치는 것이 익숙해졌다. 다음 단계에서는 굳이 작성하지 않아도 질문 구체화 과정을 거칠 수 있다고 생각한다.
    - 변경 전 : 학습 시작 전, "이 학습의 완료 조건: ___를 구현할 수 있다."를 먼저 생각해라.
    - 변경 후 : 학습 시작 전, 학습의 완료 조건을 "막힌 부분의 코드를 한 줄이라도 쓸 수 있다"로 설정한다.
      - 이유 : 단순히 "구현할 수 있다"라고만 설정하니, 그 시점이 명확하지 않아 "어디까지 이해해야 내가 구현할 수 있는거지?"라는 생각이 들며 학습의 완료 시점을 판단하기가 어려웠다.
