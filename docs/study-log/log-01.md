## 학습 로그 #1

**시간**: 약 70분  
**학습 범위**: 1단계 MVC

### 1. 막힌 것의 종류
이번에 막힌 것은 어떤 종류의 어려움이었는가? (해당하는 것에 체크)
- [x] 개념 자체를 모르겠다 (예: "스프링 빈이 뭔지 모르겠다")
- [x] 개념은 알겠는데 코드로 어떻게 쓰는지 모르겠다 (예: "JdbcTemplate 문법을 모르겠다")
- [ ] 코드는 돌아가는데 이게 맞는 건지 모르겠다 (예: "계층 분리를 이렇게 해도 되나?")

### 2. 이번 타임의 학습 전략
- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?  
궁금한 점이 생길 떄 무작정 AI를 통해 답을 얻어내 코드에 적용하는 것보다, 어떤 식으로 문제에 접근하려고 했고 AI가 제시한 방식이 이 미션에 정말 필요한 방식인지를 인지하는 전략을 가져보기로 했다. 
1단계 미션에서는 제공된 학습 테스트를 활용하면 문제 해결이 크게 어렵지 않았기 때문에, 부족한 개념을 보충하고 테스트 실패 원인을 찾는 용도로만 활용하였다.


- 실제로 어떻게 학습했는지 디테일한 과정을 써보세요.  
이번 방탈출 예약 관리 미션을 통해 스프링을 처음 접했기에 프레임워크에 대한 이해가 부족한 상태였다. 
따라서 모든 개념을 구글링으로 먼저 찾아보기보다는, 미션에서 제공된 spring-learning-test를 적극 활용했다.
1단계의 핵심 개념인 CRUD, 템플릿 엔진, JSON 관련 테스트를 직접 통과시켜 보며 스프링의 기본적인 동작 방식에 익숙해지는 과정을 우선시했다.
이 과정에서 발생하는 모르는 개념이나 이해가 가지 않는 동작 방식들은 별도로 기록해 두었으며, 이후 AI를 활용해 질문하며 해당 궁금증을 해결하는 방식으로 학습을 진행했다.


### 3. 전략 평가
- 효과적이었던 것과 그 이유  
  스프링 프레임워크의 개념 자체를 잘 몰랐지만, 학습 테스트를 통해 전체적인 흐름을 파악한 뒤 내가 모르는 부분과 지금 파고드는 내용이 꼭 필요한지를 스스로 질문하며 학습을 진행했다.
  이 과정에서 주도적으로 고민하며 공부하고 있다는 생각이 들었고, 앞으로도 계속 유지할 만한 가치가 있는 학습법이라고 생각한다.


- 비효과적이었던 것과 그 이유  
현재 단계에서는 변경한 전략이 비효과적이라고 느꼈던 부분이 없어서, 다음 단계에서 지켜봐야할 것 같다.


- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?  
  효과적이었던 전략에서 적었던 바와 같이 앞으로도 계속 유지할만한 가치가 있는 학습법이라고 생각하기 떄문에 좋았다고 생각한다. 

### 4. AI 피드백
- 자신의 학습 전략에 대해 AI 학습 전문가에게 피드백을 요청하고,
  유용했던 제안 1가지 이상 기록  
모든 것에 대해 왜? 라는 질문을 붙이다보면 진도가 느려질 수도 있다. 프레임워크의 내부 동작 원린처럼 깊이 파고드는 부분은 '지금 당장 필요한 수준'까지만 파고드는 절제가 필요하다는 피드백이다.

### 5. 다음 타임에 바꿀 것
- 유지할 것과 그 이유  
지금 당장 필요한 부분만 스스로 파악해서 절제하는 방식은 그대로 유지해야할 것 같다. 이번 1단계에서 스프링 프레임워크를 잘 모르기 때문에, 학습 테스트를 진행하면서 모르는 개념이 생겼을 때 AI에게 질문하다보면 완벽하게 이해해야한다는 마음가짐 때문에 게속해서 질문을 던지는 경우가 생겨서
진도가 느려질떄가 있었는데 해당 사항을 다시 인지하면서 먼저 얕게 이해해보는 방식을 선택하였다.
- 바꿀 것과 그 이유  
1단계에서는 아직 바꿀 것이 없어서 단계를 진행하면서 더 고민해보아야 할 것 같다.
