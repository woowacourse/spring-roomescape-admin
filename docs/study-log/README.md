### 시도한 학습법
1. 미션 1단계 - "나에게 집중해서 학습하기"
2. 미션 2단계 - "AI를 통해 학습 방향 잡기"
3. 미션 3단계 - "코드 구현 위주의 학습"
4. 미션 4단계 - "개념 학습과 구현 학습을 반반 섞은 학습법"

----
### 최종 학습법
[학습법 - 개념 학습과 구현 학습을 반반 섞은 학습법]
1. 집중할 하나의 필수개념을 정의하고, 내가 아는 것을 작성하며 내 상황을 체크한다.
2. AI에 과제와 1번 내용을 넣고 3가지 질문을 추천해달라고 요청한다.
3. 공식문서를 참고해서 질문에 대한 답을 스스로 작성한다.
4. 답을 GPT에게 넣고 틀린 부분이 있는지 검토받는다.   
   이때, 맞은 건 패쓰하고, 틀린 부분은 다시 생각해볼 수 있도록 질문해달라고 프롬프팅 했다.
5. 3번과 4번을 30분 동안 반복하고, 30분이 초과했는데 안끝난 질문은 GPT에게 개념 설명을 요청한다.
6. 코드 구현하며, 위에서 학습했던 개념과 연결지어본다.

### 코드 구현 질문
1. 도메인 필드로 id를 가지고 있어야하는가?    
Reservation과 ReservationTime을 만들었을 때, 처음에는 id라는 값을 속성으로 포함하지 않았습니다.
하지만 미션 3단계에서 외래키라는 개념이 들어가다보니 ReservationTime의 id 값이 필요해서 ReservationTime에만 id 필드를 추가했습니다.
Reservation에서도 통일성 있게 id를 추가해야할지, ReservationTime처럼 필요할 때가 되서 추가하는 것이 좋을지 궁금합니다.
그리고 id를 갖고 있다면 도메인보다는 엔티티에 가까워진다고 생각하는데, DB를 붙임으로써 도메인이 엔티티로 넘어가는 것이 자연스러운 현상인가요? (아직 도메인과 엔티티에 대해 헷갈리는 것 같습니다..!) 


2. DAO에서 dto 생성   
dto를 생성하는 책임은 service에 있다고 생각합니다. 
하지만, dto/ReservationCreateResponse와 같이 dto가 이중 클래스인 경우 조인 쿼리를 날린 결과를 바로 DAO에서 매핑하면 효율적일거 같다는 생각이 듭니다.
DAO에서 dto를 생성해도 되는 걸까요? 아니면 단순 조회용 dto에 한해서는 괜찮은 걸까요? 이것에 어떻게 생각하시는지 궁금합니다!


3. 계층분리   
현재 구조에서 계층의 분리가 잘 되어있는 것인지 피드백 받고 싶습니다!

### 학습법 질문


1. 나에게 맞는 학습법인지 판단하는 방법이 있을까요?   
이해가 잘됐던 학습법은 미션 1단계의 방법이지만 시간이 굉장히 많이 걸렸고,
효율적이었던 학습법은 미션 2단계지만 시작부터 AI를 사용하면 AI가 제한해둔 범위에 갇히지 않을까 걱정이 되더라고요.
그래서 기론은 어떤 학습법을 사용하시는지와, 본인에게 잘 맞는 학습법을 판단하는 기준이 있으신지 궁금합니다!


2. 학습 과정에서의 AI 사용   
AI는 배운의 문턱을 낮춰주지만, 동시에 너무 의존적으로 학습하게 될 수도 있다고 생각합니다. 기론은 학습과정에서 Ai를 어느정도까지 사용하는 것이 좋다고 생각하시는지 궁금합니다.


3. 학습의 깊이    
미션을 수행하면서 공부한 내용을 docs/study-content에 정리해두었습니다. 
평소에 너무 깊이 공부하려다가 시간이 모자랐던 경험이 많다보니, 이번 미션에서는 질문을 먼저 정해두고 질문에 답할 정도만 공부하기로 했습니다. 
기론이 보시기에는 학습의 깊이가 어떤지 궁금합니다. (ex. 더 깊이 파고들어야한다, 과제와 벗어난 개념까지 공부한것 같다 등의 의견이 궁금합니다!)
