# 서비스로 넘기기 위한 Command 패턴

HTTP로부터 받은 DTO를 그대로 서비스에 활용할 수도 있다. 그런데 굳이
command로 분리해야할 (`request.toCommand()`)로 바꿔야 할 이유가 있을까?

http용 dto를 command에서도 쓰게 되면 나중에 변경이 필요할 때 문제가 생길 수 있다.

첫째로 API 응답 json의 key명을 바꾸기로 했다고 하자. "name"을 "userName"으로 바꾼다고 하면 서비스까지 코드가 수정되어야 한다.
두번째로 API 응답형태를 변경하고 싶다고 하자. 응답 json에 status나 인증 코드, http code를 직접 담기로 변경했다고 하자. 그런데 서비스가 이 정보까지 알 필요가 없다.

이렇게 네트워크 상으로 받을 데이터 형식이 변경되는데 비즈니스에 로직에까지 인증 수단 같은 정보가 노출되는 문제 방지를 위해 command를 활용할 수 있다.
