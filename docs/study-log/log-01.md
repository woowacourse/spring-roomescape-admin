### 1. 막힌 것의 종류

이번에 막힌 것은 어떤 종류의 어려움이었는가? (해당하는 것에 체크)

- [ ] 개념 자체를 모르겠다 (예: "스프링 빈이 뭔지 모르겠다")
- [ ] 개념은 알겠는데 코드로 어떻게 쓰는지 모르겠다 (예: "JdbcTemplate 문법을 모르겠다")
- [ ] 코드는 돌아가는데 이게 맞는 건지 모르겠다 (예: "계층 분리를 이렇게 해도 되나?")
- [x] 기타:
    - 메모리 db를 만들기 위해 구글링해서 찾은 코드 중에 쓰인 개념이 정확히 무엇이며, 어떤 트레이드 오프가 있는지 모르겠다.
    - 예외가 발생했는데, 처음 보는 에러가 왜 발생했는지 원인을 모르겠다.
    - 어떤 어노테이션을 사용해야 하는지 모르겠다.

### 2. 이번 타임의 학습 전략

- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?
    - > 전략: 내 코드에서 생긴 질문 하나를 공식문서로 확인하고, AI를 통해 내 이해를 검증하는 학습법
- 실제로 어떻게 학습했는지 디테일한 과정을 써보세요.
    1. 작성한 코드(`public void createReservation(@ CreateReservationRequest request`)에서 어떤 어노테이션을 붙여야 하는지 고민했다.
    2. 우테코 페이지에서 제공하는 `@RequestBody`와 `@PathVariable` 에 대해 공식문서를 통해 학습했다.
    3. 공식문서를 읽다보니 이해가 가지 않는 개념을 AI를 통해 간략히 학습했다. (`역직렬화`)
    4. AI를 통해 퀴즈를 생성하여 이해 여부를 검증했다.

### 3. 전략 평가

- 효과적이었던 것과 그 이유:
    - 작성한 코드에서 생긴 궁금증을 출발점으로 삼아 공식문서를 확인한 점이 효과적이었다.
    - 파악해야 하는 부분만 공식문서를 통해 빠르고, 그리고 정확하게 학습할 수 있었다.
- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?:
    - 이번에 막힌 지점은 “새로운 개념 전체를 이해하지 못해서 막힌 것”이라기보다, 작성 중인 코드에서 어떤 어노테이션을 적용해야 하는지 모르는 문제에 가까웠다.
    - 이런 종류의 막힘에는 이번 전략이 잘 맞았다. 왜냐하면 공식문서는 특정 어노테이션의 역할과 사용 맥락을 정확하게 설명해주고, 현재 코드의 질문과 직접 연결되는 부분만 찾아볼 수 있기 때문이다.

### 4. AI 피드백

- 자신의 학습 전략에 대해 AI 학습 전문가에게 피드백을 요청하고,
  유용했던 제안 1가지 이상 기록

```text
이번 질문은 이런 형태였습니다.

어떤 어노테이션을 붙여야 하지?

이 질문은 출발점으로는 좋습니다.
하지만 학습 효율을 더 높이려면 여기서 한 단계 더 나아가야 합니다.

예를 들어:

왜 @RequestBody를 붙여야 하지?
@RequestBody가 없으면 Spring은 이 객체를 어디서 가져오려고 하지?

지금 createReservation(@RequestBody CreateReservationRequest request)에서 JSON 요청이 들어오면, 
Spring은 어떤 과정을 거쳐 CreateReservationRequest 객체를 만드는가?

이런 질문으로 확장되면 단순히 “정답 어노테이션 찾기”가 아니라,
Spring MVC가 요청을 처리하는 흐름을 이해하게 됩니다.

즉, 이번 학습은 잘했지만 약간 아쉬운 점은
```

### 5. 다음 타임에 바꿀 것

- 유지할 것과 그 이유
    - 내 코드에서 생긴 질문 하나를 공식문서로 확인하고, AI를 통해 내 이해를 검증하는 학습법
    ```
    이 방식은 이전처럼 공식문서를 처음부터 수동적으로 읽는 방식보다 훨씬 효과적이었다.
    코드에서 생긴 질문을 기준으로 문서를 읽으니 읽어야 할 범위가 줄었고,
    공식문서의 내용이 실제 코드와 바로 연결되었다.
    또한 AI를 정답을 얻기 위한 도구가 아니라, 내가 이해한 내용을 검증하는 도구로 사용하면서
    착각 학습을 줄일 수 있었다.
    ```

- 바꿀 것과 그 이유
    - 내 코드에서 생긴 질문을 공식문서로 확인한 뒤, “왜 동작하는지”를 내 말로 설명하고 AI로 검증하는 학습법
    ```
    다만 이번 학습은 “어떤 어노테이션을 써야 하는가”를 확인하는 데는 효과적이었지만, 
    “왜 이 어노테이션을 붙이면 동작하는가”까지 깊게 설명하는 과정은 부족했다. 
    따라서 다음부터는 공식문서로 답을 확인한 뒤, 반드시 한 단계 더 나아가 “왜 이 코드가 동작하는가?”를 내 말로 설명해보려 한다. 
    이를 위해 What → Why → Check라는 멘탈 모델을 적용해, 
    무엇을 써야 하는지 확인하고, 왜 동작하는지 설명한 뒤, AI를 통해 내 이해를 검증하는 방식으로 학습 효율을 높이고자 한다.
    ```
