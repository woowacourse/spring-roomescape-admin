### 2. 이번 타임의 학습 전략

- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?
  - 이번에는 단순하게 AI를 코드 리뷰어 역할로 활용하여, 현재 코드 구조가 레이어드 아키텍처의 기본 원칙에 부합하는지 검증하는 전략을 세웠음.

- 실제로 어떻게 학습했는지 디테일한 과정
  1. 레이어드 아키 텍처 구글링/AI 질문을 통해 개념 이해
  2. AI 답변을 통해 현재 코드 구조가 레이어드 아키텍처의 기본 원칙(계층 분리, 의존성 방향 등)에 부합하는지 확인
     - 특히 비지니스로직이 적은 지금 미션에서 서비스 클래스의 필요성을 위주로 질문

### 3. 전략 평가

- 효과적이었던 것과 그 이유
  - 추상적인 개념을 실제 코드 구조에 적용하는 과정에서 AI를 활용해 빠르게 검증할 수 있었음. 

- 비효과적이었던 것과 그 이유
  - 크게 없었다.

- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
  - “코드는 돌아가는데 이게 맞는 건지 모르겠다” 유형에는 적합했음. 
  특히 레이어드 아키텍처는 개념적으로는 이해하기 쉽지만, 실제 코드에서 각 계층이 제대로 분리되고 의존성 방향이 맞는지 판단하는 게 어려운데, AI를 통해 빠르게 검증할 수 있었음.

### 4. AI 피드백

- 자신의 학습 전략에 대해 AI 학습 전문가에게 피드백 요청 결과:
  >검증 도구로서의 AI 활용: AI가 짜주는 코드를 수동적으로 받지 않고, 본인의 설계안을 리뷰받거나 원칙(의존성 방향 등)에 부합하는지 확인하는 '검증자'로 활용하는 방식이 매우 능동적입니다
- 유용했던 제안
  >'변경 시나리오'로 유연성 테스트: 레이어드 아키텍처의 목적은 변경에 유연한 구조를 만드는 것입니다. AI에게 "DB가 바뀌거나 UI가 콘솔로 바뀌어도 핵심 로직이 안전한가?"를 묻고, 필요하다면 DAO를 인터페이스로 추상화해 보세요
