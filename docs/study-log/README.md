# 방탈출 예약 관리 API 요구사항

방탈출 관리자가 예약을 등록하고 관리하기 위한 REST API를 구현한다.

## 기능 요구사항

### 예약 관리

- 관리자는 예약 목록을 조회할 수 있다.
- 관리자는 예약을 추가할 수 있다.
- 관리자는 예약을 삭제할 수 있다.
- 예약은 예약자 이름, 예약 날짜, 예약 시간 정보를 가진다.
- 각 예약은 하나의 예약 시간과 연결된다.

### 예약 시간 관리

- 관리자는 예약 시간 목록을 조회할 수 있다.
- 관리자는 예약 시간을 추가할 수 있다.
- 관리자는 예약 시간을 삭제할 수 있다.
- 이미 예약에 사용 중인 시간은 삭제할 수 없다.

## 시스템 요구사항

### 데이터 저장 및 관리

- H2 Database를 사용한다.
- 데이터 접근은 `JdbcTemplate`을 기반으로 구현한다.
- 예약과 예약 시간의 ID는 데이터베이스가 생성한 값을 사용한다.
- 예약 추가 응답에는 데이터베이스가 생성한 예약 ID를 포함한다.
- 초기 단계에서 사용한 `List<Reservation>`, `AtomicLong` 기반 저장 방식은 제거한다.

### 통신

- 별도의 프론트엔드는 구현하지 않는다.
- HTTP 기반의 REST API로 통신한다.
- 요청과 응답의 데이터 교환 포맷은 JSON을 사용한다.

### 계층 구조

- Controller는 HTTP 요청과 응답을 처리한다.
- Service는 비즈니스 규칙과 검증 흐름을 담당한다.
- Repository는 `JdbcTemplate`을 사용해 데이터베이스에 접근한다.
- Domain 객체는 예약자 이름, 예약 날짜, 예약 시간의 유효성을 검증한다.

## 입력 검증

### 예약자 이름

- 이름은 `null`일 수 없다.
- 이름은 공백만으로 구성될 수 없다.
- 이름 앞뒤 공백은 제거한다.
- 이름은 최대 10자까지 허용한다.

### 예약 날짜

- 날짜는 `null`일 수 없다.
- 날짜는 공백만으로 구성될 수 없다.
- 날짜 앞뒤 공백은 제거한다.
- 날짜 형식은 `YYYY-MM-DD`이다.
- 날짜 형식이 올바르지 않으면 예외를 발생시킨다.

### 예약 시간

- 시간은 `null`일 수 없다.
- 시간은 공백만으로 구성될 수 없다.
- 시간 앞뒤 공백은 제거한다.
- 시간 형식은 `HH:MM`이다.
- 시간 형식이 올바르지 않으면 예외를 발생시킨다.

### 예약 생성

- 예약 시간 ID는 양수여야 한다.
- 존재하지 않는 예약 시간 ID로 예약을 생성할 수 없다.
- 같은 날짜와 같은 시간에 중복 예약을 생성할 수 없다.

## API 명세

### 예약 목록 조회

`GET /reservations`

응답:

```http
200 OK
```

```json
[
  {
    "id": 1,
    "name": "브라운",
    "date": "2023-08-05",
    "time": {
      "id": 1,
      "startAt": "10:00"
    }
  }
]
```

### 예약 추가

`POST /reservations`

요청:

```json
{
  "name": "브라운",
  "date": "2023-08-05",
  "timeId": 1
}
```

응답:

```http
201 Created
```

```json
{
  "id": 1,
  "name": "브라운",
  "date": "2023-08-05",
  "time": {
    "id": 1,
    "startAt": "10:00"
  }
}
```

### 예약 삭제

`DELETE /reservations/{id}`

응답:

```http
204 No Content
```

### 예약 시간 목록 조회

`GET /times`

응답:

```http
200 OK
```

```json
[
  {
    "id": 1,
    "startAt": "10:00"
  }
]
```

### 예약 시간 추가

`POST /times`

요청:

```json
{
  "startAt": "10:00"
}
```

응답:

```http
201 Created
```

```json
{
  "id": 1,
  "startAt": "10:00"
}
```

### 예약 시간 삭제

`DELETE /times/{id}`

응답:

```http
204 No Content
```

## 미션 단계별 구현 세부사항

### 1단계: In-Memory 예약 관리

- `List<Reservation>`으로 예약 데이터를 관리한다.
- `AtomicLong`으로 예약 ID를 순차적으로 생성한다.
- 예약 조회, 추가, 삭제 API를 구현한다.
- 데이터는 서버 재시작 시 초기화된다.

### 2단계: H2 Database 전환

- In-Memory 저장소와 `AtomicLong`을 제거한다.
- H2 Database와 `JdbcTemplate` 기반 저장소로 전환한다.

### 3단계: 예약 시간 관리

- 예약 시간 조회, 추가, 삭제 API를 구현한다.
- 예약은 문자열 시간이 아니라 예약 시간 ID를 통해 시간과 연결된다.
- 예약 조회 응답에는 연결된 예약 시간 정보를 포함한다.

### 4단계: 계층화 리팩터링

- Controller에서 데이터 접근 책임을 제거한다.
- Controller, Service, Repository, Domain의 역할을 분리한다.
