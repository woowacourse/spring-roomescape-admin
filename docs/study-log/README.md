## v1 — 기존 학습법

- 처음 접하는 메서드나 라이브러리는 내부 소스 코드를 직접 열어 구조와 설계 의도를 파악
- 이해한 내용은 노션에 정리하고, 설명할 수 있을 만큼 정리된 주제는 블로그 글로 작성
- 『오브젝트』, 『객체지향의 사실과 오해』 등의 도서를 읽으며 기존 코드를 설계 관점으로 회고하고 개선
- 문제 상황과 개선 방향을 함께 기록해두어 같은 실수를 반복하지 않도록 함

## v2 — 탐색 전환 횟수 제한 추가

- 탐색 중 주제가 전환되는 지점에서 최대 2번까지만 따라감
- 전환할 때마다 "이게 지금 목적에 필요한 한 단계인가?"를 스스로에게 질문
- 2번을 넘어서는 전환은 메모만 남기고 넘어감

## v3 — 모호함 태깅 + 기록의 선택과 집중

- 탐색을 끊어낼 때 왜 끊었는지를 태그로 명시

  - [시간 제한] — 지금은 미션 진행이 우선이라 끊었다
  - [i+1 초과] — 지금 목적과 너무 멀어져서 끊었다
  - [나중에 반드시] — 휘발되면 안 되는 수준의 개념이다


- 모든 것을 기록하려 하지 않음 — 반복해서 등장하는 개념이 곧 중요한 개념이라는 신호
  - [나중에 반드시] 태그가 붙은 것만 노션이나 블로그에 깊게 정리
