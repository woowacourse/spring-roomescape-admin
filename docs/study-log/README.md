## 학습법 변천

#### v1. 직접 부딪히는 경험 중심 학습

방식: 선 구현 후 개선, 실패→성공 루트의 직접 경험 중시

특징: 정답을 먼저 보기보다 스스로 해결할 때까지 AI와 끝장 토론을 하며 지엽적인 부분까지 파고듦

한계: 깊이에 매몰되어 넓이(전반적인 필수 지식)를 챙기지 못하는 문제 발생

#### v2. 리소스 활용과 속도전

방식: 빠른 완성 후 PR을 목표로 리소스(AI, 피드백) 적극 활용

특징: 무엇이 중요한지 스스로 판단하지 않고 AI/피드백에 의존하여 투자 시간 결정. 단순 호기심(예: Gradle 내부 동작)은 과감히 생략

변화: 직접 경험만 고집하던 도구 제약을 풀고, 효율적인 도구 활용으로 전환

#### v3. 리소스 활용(속도)과 경험의 균형

방식:

- 주어진 문제에 대해 '어떻게 해결해야 하는지 안다'는 확신이 드는 지점까지는 AI를 활용하지 않고 스스로 코드를 작성한다.

- 이때 완벽한 해결을 목표로 삼지 않는다. 대략적인 해결 계획을 세우며 초안을 빠르게 작성하는 것에 집중한다.

- 이 과정에서 작성하는 코드는 완벽한 구현이 목적이 아니라, 문제 해결의 맥락 파악과 논리적 구조 이해를 목적으로 한다.

- 구현 중 에러가 발생하거나 '어떻게 해결해야 할지 모르겠다'는 생각이 들면, 즉시 AI에게 최소한의 코드를 요청하고 이를 철저히 이해한다.

- 모르는 부분은 학습하되, 당장 해결에 지엽적인 내용은 기록만 해두고 넘어간다. (심화 학습은 문제 해결 완료 후 수행한다.)
