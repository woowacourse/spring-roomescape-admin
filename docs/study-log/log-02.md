### 1. 막힌 것의 종류

이번에 막힌 것은 어떤 종류의 어려움이었는가? (해당하는 것에 체크)

- [ ] 개념 자체를 모르겠다 (예: "스프링 빈이 뭔지 모르겠다")
- [x] 개념은 알겠는데 코드로 어떻게 쓰는지 모르겠다 (예: "JdbcTemplate 문법을 모르겠다")
    - JdbcTemplate에 어떤 API가 있고, 어떤 상황에 어떤 API를 활용 해야할 지 파악하기 어려웠다.
- [ ] 코드는 돌아가는데 이게 맞는 건지 모르겠다 (예: "계층 분리를 이렇게 해도 되나?")
- [x] 기타: db가 연결이 안 된다는 에러를 마주쳤는데, 에러를 유발하는 원인이 여러 가지라 내 상황에 맞는 실제 원인을 찾는 데 어려움을 겪었다.
    - 단계 테스트를 보기 좋게 정리하려고 `@Nested` 를 활용했다.
    - 최상위 클래스에 `JdbcTemplate`를 주입했는데, 스프링에서 현재 동작하는 테스트의 클래스를 기준으로 의존성 주입을 시도하여 db 연결이 계속 실패했다.
    - 원인을 파악하기 전까지는 DB 설정, 테스트 컨텍스트, 코드 전반을 모두 의심하게 되어 많은 시간이 필요했다.

### 2. 이번 타임의 학습 전략

- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?
    - > 전략: 내 코드에서 생긴 질문을 공식문서로 확인한 뒤, “왜 동작하는지”를 내 말로 설명하고 AI로 검증하는 학습법
    - 실행 🔺
        - 이유: 코드에서 생긴 질문을 공식문서를 통해 해결하였지만, “왜 동작하는지”를 내 말로 설명하고 AI로 검증하는 과정을 거치지 않았다.
- 실제로 어떻게 학습했는지 디테일한 과정을 써보세요.
    1. 학습 테스트를 통해 사용할 수 있는 API 키워드를 얻는다.
    2. 공식문서에서 해당 키워드에 대해 공부한다. (언제 사용할 수 있는지, 시그니처가 어떻게 되는지 파악)
    3. 내 코드에 적용하여 기능을 구현한다.

### 3. 전략 평가

- 효과적이었던 것과 그 이유:
    - 공식문서를 통해 API의 정확한 사용법뿐 아니라, 어떤 API가 deprecated 되었고 어떤 방식으로 개선되었는지까지 확인할 수 있어 좋았다.
    - 기존에 사용하려던 API가 있었지만, 공식문서를 통해 더 최신의 API를 확인할 수 있었고, 덕분에 이후 리팩토링에 들 시간을 줄일 수 있었다.
- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?:
    - 공식문서를 활용하는 전략은 API 키워드를 알고 있을 때 효과적이었다.
    - 반면 적절한 키워드를 찾지 못한 상황에서는, 공식문서 안에서 필요한 정보를 찾아내는 데 시간이 오래 걸렸다.

### 4. AI 피드백

- 자신의 학습 전략에 대해 AI 학습 전문가에게 피드백을 요청하고,
  유용했던 제안 1가지 이상 기록

```text
공식문서에서 사용법을 확인하고 코드에 적용하는 데서 멈춘 점은 아쉬웠다. 
원래 전략은 공식문서로 확인한 뒤 “왜 이 API가 이 상황에 맞는지”를 내 말로 설명하고 AI로 검증하는 것까지 포함했지만, 
이번에는 그 단계가 충분히 실행되지 않았다.

AI 학습 전문가는 다음 학습에서 `Find → Choose → Explain` 멘탈 모델을 적용해보라고 제안했다.

1. Find: 공식문서에서 가능한 API를 찾는다.
2. Choose: 내 코드 상황에 맞는 API를 선택한다.
3. Explain: 왜 이 API를 선택했는지 내 말로 설명하고 AI로 검증한다.
```

### 5. 다음 타임에 바꿀 것

- 유지할 것과 그 이유
    ```
  학습 테스트나 작성 중인 코드에서 생긴 질문을 출발점으로 삼고, 공식문서를 1순위로 확인하는 방식은 유지한다.
  이번에 JdbcTemplate API를 학습할 때, 사용할 API 키워드를 먼저 얻은 뒤 공식문서를 확인하니 필요한 부분만 빠르고 정확하게 학습할 수 있었다. 
  또한 공식문서를 통해 deprecated 여부나 더 권장되는 API까지 확인할 수 있어 이후 리팩토링 비용을 줄이는 데 도움이 되었다.
  따라서 앞으로도 새로운 기술을 학습할 때 블로그나 AI 답변을 먼저 보기보다,
  내 코드에서 생긴 질문을 기준으로 공식문서를 확인하는 방식은 유지하려 한다.
    ```

- 바꿀 것과 그 이유
    ```
  공식문서를 읽을 때 매번 동작 원리까지 깊게 파악하려고 하기보다, 우선 구현에 필요한 API 사용법을 확인하고 코드에 적용하는 데 집중한다.
  이번에 JdbcTemplate API를 학습하면서 공식문서를 통해 정확한 사용법을 확인하는 것은 효과적이었지만, 
  동작 원리까지 함께 파고들면 시간이 오래 걸릴 수 있다고 느꼈다. 
  미션 상황에서는 제한된 시간 안에 기능 구현을 완료하는 것도 중요하므로, 원리 파악은 우선순위를 조절할 필요가 있다.
  따라서 다음 타임에는 먼저 필요한 API를 공식문서로 확인해 구현을 완료하고, 
  시간이 남거나 같은 개념이 반복해서 막힐 때 동작 원리를 추가로 정리하는 방식으로 바꾸려 한다.
  
  또한 내가 스스로 공식문서를 일일이 읽어보며 원하는 내용을 찾는 건 오래걸리기 때문에,
  AI를 통해 키워드 및 공식문서 URL을 받아온 후 공식문서를 읽어보려 한다.
   ```
