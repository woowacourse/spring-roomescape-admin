### 2. 이번 타임의 학습 전략

- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?
  - v3의 “해결할 문제/장애 상황 먼저 설정한다." -> 이번에는 “개념은 아는데 사용법이 막힘” 상황이었기 때문에 장애나 문제상황을 설정할 필요가 없었음

- 실제로 어떻게 학습했는지 디테일한 과정
  1. JdbcTemplate의 이름과 역할(순수 JDBC 반복 제거용)은 알고 있었으나 실제 구현 문법과 적용 방식이 부족하다고 판단
  2. AI에게 `query`, `queryForObject`, `RowMapper`, `MERGE` 등 실제 구현에 필요한 문법 단위로 질문
  3. AI 답변을 통해 Repository 구조, SQL 작성 방식, RowMapper 역할을 빠르게 정리
  4. 이후 블로그/공식 문서 스타일 자료를 통해 `queryForObject` 예외 상황, RowMapper 위치, H2 MERGE 문법 차이 등 교차 검증
  5. 검증한 내용을 바탕으로 실제 프로젝트 코드에 JdbcTemplate 기반 Repository CRUD를 직접 구현 및 적용
  6. 단순 문법 이해에서 끝나지 않고, 현재 미션 코드베이스에 연결하며 실행 가능한 수준으로 전환

### 3. 전략 평가

- 효과적이었던 것과 그 이유
  - AI에게 세부 문법을 즉시 질의 → 짧은 시간 내 전체 구조와 필요한 사용법 빠르게 확보 가능
  - 블로그 검색으로 실제 사례 검증 → AI 답변을 그대로 수용하지 않고 검증 가능
  - 필요한 문제 단위로 쪼개 학습 → 추상 개념 암기보다 실제 코드 적용 속도가 빨랐음
  - 이미 이름과 목적을 알고 있었기 때문에 AI+검색 기반 빠른 문법 습득 → 즉시 구현 방식이 높은 효율을 보였음

- 비효과적이었던 것과 그 이유
  - 첫 개념 학습 단계에서 구조 이해 없이 문법만 대량 습득하면 혼란 가능성 존재
  - DBMS별 문법 차이(MERGE 등)는 현재 필요한 범위를 넘어서면 학습 효율 저하 가능

- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
  - “개념은 아는데 사용법이 막힘” 유형에는 매우 적합했음
