# Recall 03

날짜: 2026-04-29

## Service를 왜 쓰는가?

기본적으로 **비즈니스 로직을 독립적으로 처리하는 계층을 만들기 위해 필요하다.**

서비스를 안 쓸 때를 생각해보면 컨트롤러가 `jdbcTemplate`나 레포지토리에 바로 의존하게 된다.

웹 서비스만 할 거라면 상관 없을 수도 있다. 도메인 검증 로직만 필요하다면 그 도메인을 검증하는 validator를 빼면 된다.

하지만 웹이 아니라 콘솔 환경에서도 동일 비즈니스 로직을 쓰고 싶으면 비즈니스 로직과 http 응답 처리 로직이 강하게 결합되어 있어 활용이 어렵다. 입력단을 유연하게 갈아 끼우기 위해 비즈니스 로직을 분리해야 하고 이를 위해 서비스 계층이 필요하다.

## 레포지토리가 HTTP용 DTO를 왜 알면 안될까?

앞서 말한 입력단 갈아끼우기와 연계된다. 작은 규모에서는 콘솔과 웹 두 환경에서 dto가 요구하는게 같을 것이다. 하지만 규모가 커질 수록 http dto에서 요구하는 속성, 콘솔에서 요구하는 속성이 서로 달라지거나, 필드 이름 수정이 필요하면 데이터베이스에 액세스하는 계층까지 영향이 가게된다. 불필요한 수정이 발생한다. 이것을 최대한 막기 위해 레포지토리가 dto를 알면 안된다.
