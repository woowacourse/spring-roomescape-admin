### 2. 이번 타임의 학습 전략

우선 학습을 시작하기 전, 최종적으로 학습하고자 하는 기술이나 개념에 대해 경계를 확정할 것이다.

이후에 현재 해결해야 하는 문제를 기준으로, 그 문제를 해결하는 데 필요한 수준까지 키워드를 중심으로 학습을 이어나갈 계획이다. 

즉 특정 키워드 하나를 깊게 파고들기보다는, 현재 보고 있는 설명을 이해할 수 있을 정도의 수준까지만 빠르게 이해하는 방식을 사용할 것이다. 

예를 들어 JUnit5를 학습한다고 할 때, JUnit5를 설명하는 공식 문서의 문장을 이해하는데 필요한 수준까지만 JUnit Platform을 학습할 것이고, 
마찬가지로 JUnit Platform을 이해하는데 필요한 정도까지만 Test Engine을 학습할 것이다.

### 3. 전략 평가

#### 효과적이었던 것과 그 이유

학습을 시작하기 전, 학습하고자 하는 기술이나 개념에 대한 경계를 확정하는 것이 효과적이었다. 

`RestAssured`에 대해 학습을 시작하기 전, "이 기술이 무엇인지"와 "사용법"을 학습하겠다는 목표를 세웠다.
이 목표는 공식 문서에서 내가 읽어야 할 부분을 판단하는 나침반으로 작동할 뿐만 아니라, 공식 문서를 읽다가도 빠르게 AI로 넘어갈 수 있게 도왔다.

#### 비효과적이었던 것과 그 이유

나의 계획은 개인이서 학습한다는게 전제가 된 것이었다. 

그런데 어떤게 베스트 프렉티스인지에 대해 확인하는 것은 정보 검색이 쉽지 않고, 또 크루들과 토론하는 과정에서 다양한 시야를 얻을 수 있기 때문에, 크루들과의 토론이 더 좋았다.

#### 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?

"코드는 돌아가는데 이게 맞는 건지 모르겠다"와는 궁합이 좋지는 않았던 것 같다. 이런 경우에는 크루와의 토론이 더 적절한 것 같다.

### 4. AI 피드백

- 자신의 학습 전략에 대해 AI 학습 전문가에게 피드백을 요청하고,
  유용했던 제안 1가지 이상 기록

```markdown
개선안 2: “막힘 유형별 대응 전략”을 명시적으로 분리

이미 막힘 유형을 인지했기 때문에, 이걸 전략에 포함시켜야 한다

지금 상태
하나의 전략으로 모든 문제 해결하려고 함
개선

막힘을 2가지로 나누고 대응 전략을 다르게 가져간다:

이해 막힘
→ 지금 전략 유지 (키워드 확장)
판단 막힘 (“이게 맞나?”)
→ 바로 토론 / 비교 / 사례 탐색으로 전환
규칙으로 만들면
if (이해가 안됨) → 키워드 확장
if (맞는지 모르겠음) → 혼자 고민 금지, 외부 기준 확보

```
