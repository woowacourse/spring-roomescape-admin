### 2. 이번 타임의 학습 전략

JdbcTemplate을 사용해 DB 연동 코드를 작성하면서, 왜 순수 JDBC 대신 JdbcTemplate을 쓰는지 이유가 궁금해졌다.

### 4. AI 피드백

- "5번 바꿀 것"에 말로 설명해 보는 단계를 스스로 추가한 것이 눈에 띈다. 피드백을 받기 전에 스스로 그 필요성을 느끼고 전략을 수정한 것이다. 자신의 학습을 메타적으로 관찰하고 조정하는 능력 자체가 전문성 성장의 지표다.
- 다만 비교 학습이 표면에서 멈출 위험이 있다. 비교는 차이를 아는 것이 아니라, 그 차이가 실제 상황에서 어떤 판단을 바꾸는지까지 연결될 때 완성된다.
- **추가 질문**: "JdbcTemplate이 내부적으로 처리해 주는 것들을 순수 JDBC로 직접 구현한다면, 코드에서 어떤 부분이 추가되어야 하는가?" → 완성된 코드가 아니어도 좋다. Connection을 열고 닫는 부분, 예외 처리 부분을 직접 써보다가 막히는 지점이 생기면, 그 지점이 아직 이해가 표면에 머물러 있다는 신호다.
- 공식 문서 → 말로 설명 → 직접 구현 시도, 이 세 단계가 하나의 사이클이 될 때 개념이 진짜 자기 것이 된다.

```
피드백에 따른 추가 학습 내용
순수 JDBC를 사용할 경우 매 쿼리마다 아래 과정을 반복해야 함
- Connection 획득
- PreparedStatement 생성
- 파라미터 바인딩
- 쿼리 실행
- ResultSet 처리
- 예외 처리
- Connection/Statement/ResultSet 자원 해제 (finally 블록)

JdbcTemplate은 위 과정 중 반복되는 부분(Connection 관리, 자원 해제, 예외 변환)을 대신 처리해 줌
=> 개발자는 SQL과 파라미터 바인딩, 결과 매핑에만 집중할 수 있음
```
