## v1: AI 아니면 구글링

사실: 모르는 개념이 생기면 이를 해결하기 위해 AI 또는 구글링(상단 블로그 글 위주)을 통해 학습한다.
문제: 공식문서를 1순위로 확인하기보다, 더 빠르고 편하게 얻을 수 있는 자료를 먼저 찾게 된다.
때로는 공식문서를 아예 확인하지 않는 경우도 많다.

## v2:공식문서를 최우선으로 학습하기

Gradle 기초 핵심 모음을 30분 동안 읽어보았다.

처음에는 별다른 목적 없이 첫 페이지부터 순서대로 읽기 시작했다. 하지만 2페이지 정도 읽고 나니 “내가 이걸 왜 읽고 있지?”라는 의문이 들었다.
공식문서이긴 했지만, 지금 내 코드나 미션과 직접 연결되는 지점이 아니라 처음부터 수동적으로 읽다 보니 내용이 잘 와닿지 않았고, 배움보다 의문이 더 크게 남았다.

이후 크루(쿠다)의 학습 방식과 비교해보니 차이가 보였다. 크루(쿠다)는 미션에서 실제로 build.gradle을 사용하는 부분을 기준으로, 필요한 내용을 공식문서에서 찾아가며 학습했다.
반면 나는 “Gradle을 공부해야 한다”는 생각만 가지고 처음부터 끝까지 읽으려 했다. 그래서 공식문서를 읽고 있음에도, 문제 해결이나 코드 이해로 이어지지 못했던 것 같다.

잘 동작한 부분도 있었다. Gradle에 대해 블로그처럼 출처가 불분명한 글을 먼저 참고하기보다, 공식문서를 1순위로 두고 학습했다는 점이다.
그리고 공식문서를 읽은 뒤에는 AI를 활용해 내가 이해한 내용이 맞는지 확인하면서 개념을 점검했다.
이 과정은 단순히 AI에게 답을 받는 것이 아니라, 공식문서를 기준으로 내 이해를 검증하는 방식이었기 때문에 도움이 되었다.

결론적으로, 공식문서를 보는 방향 자체는 좋았지만, “무엇을 해결하기 위해 읽는가?”라는 질문이 부족했다.
앞으로는 공식문서를 처음부터 수동적으로 읽기보다, 현재 코드에서 궁금한 점이나 해결하고 싶은 문제를 먼저 정하고, 그에 필요한 부분을 찾아 읽는 방식으로 학습해야겠다고 느꼈다.

## v3: 1 Question → 1 Doc → 1 Check

1. Question: 코드에서 질문 하나 만들기
   공식문서를 열기 전에 먼저 내 코드나 미션에서 궁금한 점을 하나 정합니다.

2. Doc: 공식문서에서 필요한 부분만 읽기
   질문과 직접 연결된 공식문서 부분만 찾아 읽습니다.

이때 목표는 ' 내 질문에 답할 수 있는 근거를 공식문서에서 찾기 '입니다.

3. Check: AI를 통해 이해도 확인하기
   공식문서를 읽은 뒤, 바로 AI에게 정답을 물어보는 것이 아니라 내가 이해한 내용을 먼저 설명합니다.

예를 들어:

내가 Gradle 공식문서를 읽고 이해한 내용은 다음과 같아.

application 플러그인은 실행 가능한 JVM 애플리케이션을 만들기 위한 플러그인이다.
이 플러그인을 적용하면 java 플러그인도 함께 적용되기 때문에 컴파일, 테스트, jar 관련 기능을 사용할 수 있다.
또한 run task를 제공하고, 실행할 main 클래스를 알기 위해 mainClass 설정이 필요하다.

이 이해가 맞는지 확인해줘.
틀린 부분이 있다면 공식문서 기준으로 어떤 부분이 부정확한지 짚어줘.
그리고 내가 놓친 핵심 개념이 있다면 1~2개만 알려줘.
