### 2. 이번 타임의 학습 전략
- 실제로 어떻게 학습했는지 디테일한 과정을 써보세요.
1. 현재 직면한 문제 상황 정의 
Reservation이 ReservationTime을 가지게 되면서 기존 테스트가 깨진다.
대표적인 원인은 Reservation생성을 위해서는 이미 존재하는 ResrvationTimeId 값이 필요한데, DB에 존재하지 않기 때문이다.
2. 해결 방안에 대한 가설 세우기
   a. 시간 데이터가 존재하지 않는 경우 기본값 반환
   b. DB에 특정 id값에 대한 더미데이터 추가
a 방식의 경우 의도하지 않은대로 동작할 수 있다. 시간 값이 존재하지 않을 때는 예외 처리가 필요하다.
b 방식 도입 시 더미데이터가 프로덕션 환경에 영향을 주면 안되기 때문에 테스트 환경을 분리할 필요가 있다.

3. 가설 기반으로 AI에 검증
4. AI응답 결과 중 문서 참조 가이드 관련 내용을 확인
사용 중인 언어/프레임워크의 공식 문서에서 'Test Data Fixtures' 또는 'Transaction Management in Tests' 부분을 찾아보십시오.
5. Test Data Fixtures 검색 후 블로그 내용 확인(공식 문서를 찾을 수 없었음)
6. Test Data Fixtures는 현재 문제를 해결하는 방법이 아니라는 것을 확인
7. 크루들의 해결방법을 물어보고 기존에 사용해본 Test전용 유틸 클래스를 정의하여 해결
