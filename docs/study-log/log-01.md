### 2. 이번 타임의 학습 전략

이번에는 ai의 도움을 빌려 모르는 키워드를 빠르게 학습했다. automiclong을 사용하는 과정에서 문법 사용에 익숙치 않아 어려움을 겪었는데 효율적으로 학습했다.

### 3. 전략 평가
- 효과적이었던 것
  - 1단계는 spring에대한 구체적인 개념보다는 간단한 어노테이션 사용법 수준의 개념이 대부분이라, AI를 통해 빠르게 학습해 효율성을 높였다.
- 비효과적이었던 것
  - 메모하지 않다보니 빠르게 기억에서 휘발되었다.
- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
  - "사용법을 모름"이라는 단순한 막힘에는 AI 즉문즉답 방식이 잘 맞았다. 다만 AI에서 받은 설명만으로 진행했기 때문에 학습법 v2의 한계(AI 설명에 사고가 갇힘) 재발의 위험이있었다.

### 4. AI 피드백

빠르게 학습한 내용은 한 줄이라도 자기 언어로 정리해두지 않으면 다음 단계에서 동일한 비용을 다시 지불하게 된다.
→ AtomicLong처럼 단순한 키워드라도 "왜 이걸 썼는지(메모리 저장 시 ID 자동 증가 + 동시성)"를 짧게 남겨두면, 2단계에서 JDBC `SimpleJdbcInsert`로 ID 생성을 DB에 위임할 때 "무엇이 사라지고 무엇이 새로 생겼는지" 비교할 수 있는 기준이 생긴다.

### 5. 다음 타임에 바꿀 것
- 유지할 것
  - **막힌 키워드는 AI로 빠르게 푸는 방식**: 1단계는 문법 수준 막힘이 대부분이라 AI 활용이 가장 효율적이었다.
- 바꿀 것
  - **학습 즉시 한 줄 메모 남기기**: 휘발 문제를 줄이고, 이후 단계에서 동일 개념을 다시 학습하는 비용을 줄이기 위함.
  - **AI 설명 한 가지로 끝내지 않기**: 다음 단계부터는 학습법 v3의 1단계(다양한 관점 수집)를 의식적으로 적용해, 공식 문서/팀원 설명 등 다른 출처를 한 번 더 거치는 단계를 둔다.

### 6. 단계 전환 체크

이번 단계에서 검증된 "AI로 모르는 키워드 빠르게 쳐내기"는 다음 단계에서도 그대로 들고 가려고 한다. 1단계의 막힘이 대부분 문법/사용법 수준이었기 때문에 즉답이 잘 들어맞았던 것뿐이고, 다음 단계에서 막히는 종류가 달라진다면 이 방식만으로는 부족할 수 있다.

다음 단계는 DB 연동인데, 막힘의 종류가 "사용법"에서 "개념"으로 옮겨갈 가능성이 높다. 
JDBC, 트랜잭션, 빈 등록 같은 개념은 짧은 즉답으로는 휘발될 가능성이 더 크기 때문에, 1단계에서 발견한 "메모하지 않으면 휘발된다"는 한계를 다음 단계에서 보완하는 것이 핵심이다. 

그래서 다음 타임에는 AI 즉답은 유지하되, 그 위에 "한 줄이라도 정리해두기"와 "다른 출처(공식 문서/팀원)도 한 번 거치기"를 의도적으로 끼워 넣는다.
