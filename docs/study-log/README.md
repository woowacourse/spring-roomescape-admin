## 사전학습

### 학습법 변천사
* **학습법 v1 - [v1 학습 로그](log-01.md)**

  **특징**

   * 학습이 필요한 이유(왜)를 먼저 정의하고, 원리만 파악되면 디테일은 타협한다.
   * AI 활용 전 내 생각을 정리하고, 학습 후 1~2문장으로 요약한다.

  **한계**

   * 시간 압박이 있으면 AI를 검색엔진처럼만 사용하게 된다.
   * 공식 문서 활용이 거의 안 됐다.
   * AI 질문 전 생각 정리 과정이 모호해서 자주 생략됐다.


* **학습법 v2 - [v2 학습 로그](log-02.md)**

  **특징**

   * AI 질문 전에 가설을 세우고, AI로 논리적 허점을 검증한다.
   * 허점 확인 후 “내가 어떤 개념을 놓쳤는지”까지 역질문하며 사고를 보완한다.
   * 가설을 쓸 때 이유까지 함께 작성한다.

---

* **학습법 v3 - [v3 학습 로그](log-03.md), [log-04.md](log-04.md)**

  **특징**

   * 트러블슈팅 시 로그만 보지 않고 예외 클래스 주석까지 확인해 원인을 좁힌다.
   * 해결 시도는 브랜치를 따서 진행해 상황 오염을 막는다.
   * AI가 준 키워드가 모호하면 구체적인 기술명/패턴명을 재질문한다.
   * 필요하면 크루에게 물어보는 방식을 우선한다.



### 배경
학습에 즐거움을 느낄 수 있게 되는 것이 가장 빠르게 배울 수 있는 방법이라고 생각했습니다.

그래서 PiFSR 원칙에 기반하여 실제로 필요를 느끼는 경우 `왜 필요한가`를 먼저 정의한 후 해당 내용을 학습하는 것을 원칙으로 삼았습니다.
실제 필요를 느낀 시점에서 학습을 진행하는 것이 즐겁다고 느낀 경험이 있었기 때문입니다.

또 휘발되는 기억을 최소화하기 위해 의식적으로 학습한 내용을 정리하고 연결하기 위한 학습법을 정의했습니다.

마지막으로 공식 문서를 볼 수 있는 능력을 기르고자 우선적으로 공식 문서를 활용해보는 학습법을 정의했습니다.


## 피드백 활동
### 금요일 코칭 아이디어
- **내용**: 정확히 이해하고 싶은 개념을 AI 음성 기능을 통해 설명하고, AI가 논리적 허점이 없다고 판단할 때까지 보완한다.

**적용 시나리오**
1. mvc에서 각 계층별 존재 목적과 담당하는 역할에 대해서 AI에게
   설명한다.
2. 논리적 허점을 확인하면, 이를 수단과 방법을 가리지 않고 보완하여 스스로의 결론을 만들어낸다.
3. 초기 프롬프트에 설명에 논리적 허점이 존재하지 않는 경우 종료하도록 요청하고, AI가 판단하기에 설명에 허점이 없으면 종료한다.
