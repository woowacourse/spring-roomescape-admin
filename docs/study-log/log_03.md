## 학습 로그 #3

**시간**: MM/DD HH:MM ~ HH:MM (약 __분) <br>
**학습 범위**: 3단계 시간 관리

### 1. 막힌 것의 종류
이번에 막힌 것은 어떤 종류의 어려움이었는가? (해당하는 것에 체크)
- [ ] 개념 자체를 모르겠다 (예: "스프링 빈이 뭔지 모르겠다")
- [ ] 개념은 알겠는데 코드로 어떻게 쓰는지 모르겠다 (예: "JdbcTemplate 문법을 모르겠다")
- [x] 코드는 돌아가는데 이게 맞는 건지 모르겠다 (예: "계층 분리를 이렇게 해도 되나?")
- [ ] 기타: ___

### 2. 이번 타임의 학습 전략
- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?
```
1. 모르는 개념을 먼저 검색하여 간략하게 지식을 습득한다. (언제, 왜 쓰는가 위주로)
2. 마인드맵으로 나만의 언어로 정리해본다. 간략한 코드도 함께 작성한다.
3. 관련 개념 중 모르는 부분을 마인드맵을 통해 파악한다.
4. 단, 2~3번 진행 시 유사 개념은 메모만 해두고 지식을 습득하지는 않는다.
5. PR 이후 AI 면접 형식으로 검증한다. 
```
개념 학습을 사용할 때는 마인드맵이 좋았지만 선택지를 고민할 때는 불편하여 사용하지 않았습니다.


- 실제로 어떻게 학습했는지 디테일한 과정을 써보세요.
이번 단계 3에서는 개념 학습보다 두 가지 방식 중에 어떤 방식을 선택할지 트레이드 오프가 중요했습니다.
그러하여, 마인드맵을 사용하여 해당 내용을 작성하기 어렵다고 느껴 글문서 형식을 사용했습니다.


### 3. 전략 평가
- 효과적이었던 것과 그 이유
1번 전략은 효과적이었습니다. 
필요한 지식만 선별해서 습득하다 보니 과도하게 공부하는 일이 줄었고, 배운 내용을 즉각적으로 적용하면서 더 잘 정리되는 느낌이었습니다

- 비효과적이었던 것과 그 이유
2번 전략은 비효과적이었습니다. 
이번 단계는 개념을 새로 습득하는 것이 아니라 두 가지 방식 중 하나를 선택하는 트레이드오프 상황이었는데, 마인드맵은 이런 비교 및 선택 과정을 정리하기에 적합하지 않았습니다. 
그래서 해당 상황에서는 글 문서 형식으로 전환했습니다. 

- 막힌 것의 종류(1번)와 전략의 궁합은 어땠는가?
궁합이 좋지 않았습니다.
위에 비효과적이었던 이유와 동일하게 트레이드오프 상황에서는 마인드맵 형식이 좋지 않다고 느꼈습니다.

### 4. AI 피드백
- 자신의 학습 전략에 대해 AI 학습 전문가에게 피드백을 요청하고,
  유용했던 제안 1가지 이상 기록

> 이번에 스스로 파악한 게 중요해요. 막힌 것의 종류에 따라 도구를 바꿔야 한다는 걸 직접 경험으로 발견했잖아요.
- 개념을 모른다 -> 마인드맵
- 코드 작성법을 모른다 -> 마인드맵 + 예시 코드
- 어떤 선택이 맞는지 모른다 -> 글 문서 (트레이드오프 비교)
앞으로 학습 타임 시작할 때 "이번에 막힌 게 어떤 종류인가?"를 먼저 파악하고 도구를 고르면, 매번 도구가 안 맞아서 시간을 낭비하는 일이 줄어들 거예요.


### 5. 다음 타임에 바꿀 것
- 유지할 것과 그 이유
모르는 개념을 학습할 때는 마인드맵을 사용한다는 학습법은 유지할 것입니다.

- 바꿀 것과 그 이유
위 학습법은 모르는 개념을 학습할 때는 좋지만 트레이드오프 상황에서는 비효과적이기 때문에 이를 분리하여 학습법을 선택할 생각입니다.
모르는 개념을 학습할 때는 마인드맵을 사용하고 트레이드오프 상황일 때는 글 문서를 사용할 생각입니다.
