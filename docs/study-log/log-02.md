**1단계와 달라진 점**
전략 자체는 같았지만, 이번에는 배운 개념을 AI에게 직접 설명하고 피드백을 받는 과정을 추가했다.
- 설명하다 막히는 지점 or 틀린 지점 → 즉각 피드백 → 다시 설명

**해소 기준 확인**
- 오늘 배운 KeyHolder를 아무것도 보지 않고 AI에게 설명했다.
- 설명: KeyHolder는 INSERT 후 DB가 만든 id를 Java에서 받아야 할 때 쓴다. prepareStatement를 만들 때 id를 돌려달라는 옵션을 끼워넣고, 실행 후 keyHolder.getKey()로 꺼낸다.
- 피드백: 설명이 맞았고, 왜 람다로 받는지까지 연결되면 완성이라는 피드백을 받았다. → 람다로 받는 이유: prepareStatement 생성 시점에 직접 개입해야 하기 때문

### 4. AI 피드백
**의도적 연습 관점에서**

### 2. 선 이해
#### 1단계 — 초록 스터디 JDBC 1

깊이보다 과제를 완성할 수 있는 흐름을 먼저 잡는 것을 목표로 했다.

#### 2단계 — AI와의 대화를 통한 보완

  - INSERT 후 id 반환 → KeyHolder 원리와 사용 방법 이해
  
`깊이보다 과제를 완성할 수 있는 흐름을 먼저 잡는 것을 목표로 했다.`

### 3. 막히는 부분 다시 생각해보기
- SQL 작성과 JdbcTemplate 활용 중 헷갈리는 부분을 직접 설명해보며 이해를 확인했다. 특히 INSERT 후 id 반환 부분은 일반 update() 와 KeyHolder를 쓰는 update() 가 왜 다른지를 중심으로 다시 짚었다.

#### 해소 기준 확인
- KeyHolder는 DB가 auto increment로 생성한 id를 Java에서 받아야 하기 때문에, prepareStatement를 만드는 시점에 id 반환 옵션을 끼워넣는 방식으로 동작한다. 그래서 INSERT 후 생성된 id를 바로 사용해야 하는 상황에서 의미가 있다.
