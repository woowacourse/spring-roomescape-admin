- [ ] 코드는 돌아가는데 이게 맞는 건지 모르겠다 (예: "계층 분리를 이렇게 해도 되나?")
- [x] 기타: 테스트 환경 충돌 정리

### 2. 이번 타임의 학습 전략
- 먼저 현재 코드가 이미 4단계 요구사항을 어느 정도 만족하는지 확인했다.
- `ReservationController`에 `JdbcTemplate`이 없는지, 역할이 Controller-Service-DAO-Domain으로 나뉘어 있는지를 먼저 봤다.
- 큰 구조를 새로 바꾸기보다, 필요한 이름 정리와 응답 DTO 분리, 테스트 충돌 해결처럼 부족한 부분만 수정했다.

### 3. 전략 평가
- 효과적이었던 점은 처음부터 대대적으로 리팩터링하지 않고, 현재 구조를 먼저 검토한 뒤 필요한 수정만 한 것이다.
- 이미 이전 단계에서 계층 분리를 많이 해둬서 이번 단계 자체는 크게 어렵지 않았다.
- 오히려 실제로 막힌 부분은 계층 분리보다 테스트 컨텍스트와 DB 초기화 충돌 같은 실행 환경 쪽이었다.

### 4. AI 피드백
- 이미 구조가 요구사항을 만족하고 있다면 억지로 더 나누기보다, 테스트 기준으로 부족한 부분만 보완하라는 피드백이 유용했다.

### 5. 다음 타임에 바꿀 것

    2. 큰 리팩터링 전에 실제로 필요한 변경 범위부터 좁히는 방식.
    3. 응답 형식과 테스트 조건을 같이 확인하면서 수정하는 방식.
