# 학습법 버전 1

>- **사실**: 기록하고 싶은 개념이 생기면 아카이빙 문서를 작성한다.
>- **문제**: 구현을 우선으로 두기 위해 아카이빙은 키워드로만 진행하고, 나중에 시간이 생기면 공부하는 방식을 사용하여 막상 공부를 진행한 키워드는 절반이 되지 않는다.

> - **사실**: 트러블슈팅이 발생하면 문제상황을 간단히 기록한다
> - **문제**: 해결에 급급해 기록이 파편화되어 정확한 문제와 나의 시도, 경과를 파악하기 어렵다.

> - **사실**: 모르는 개념이 생기면 구글링을 하고, 날짜-제목-링크를 간단히 기록한다. 관련 아카이빙이 존재하는 경우 이 페이지와 연결해 기록한다.
> - **효과**: 과정이 간단하여 기록하기가 쉽고, 언제 어떤 개념을 찾으려 했는지 나중에 확인하기 쉽다.

> - **사실**: 사이클이 끝날 때마다 lms 학습 정리, 리뷰 코멘트 정리, 회고 정리를 기록한다.
> - **효과**: 한 미션을 한 페이지 안에서 돌아볼 수 있다.

> - **사실**: 리뷰어 코멘트를 정리할 때 AI를 사용해 요약했다.
> - **문제**: 실제와 다르거나 만족스럽지 않은 결과를 도출하여, 부수적으로 점검해야 했으며 직접 스스로 다 정리했을 때보다는 기억에 남는 게 적었다.


> - **사실**: 매일 회고(오늘 할(한) 일, 내일 할 일, 궁금한/필요한/알아낸 것, 느낀점 기록)를 진행했다.
> - **효과**: 내 작업 속도를 파악할 수 있다. 아카이빙에 들어가기엔 애매한 개발 고민을 기록할 수 있다. 내 컨디션을 파악할 수 있다.
> - **문제**: 할 일의 단위가 너무 크거나(PR 날리기) 작고(할 일을 하나하나 나열), 날마다 다르다.

>  ⇒ 정량화된 할 일의 단위가 필요하다(소요시간 기준, 나만의 task 기준으로 1task 등)
