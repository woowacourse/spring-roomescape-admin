## 단계 전환 체크

---

### 1단계 → 2단계

- **이전 접근법을 그대로 쓸 것인가, 바꿔볼 것인가?**
  부분적으로 바꿨다. AI 퀴즈 풀기는 유지하되, 학습 자료를 전부 훑는 방식은 버렸다.

- **바꾼 이유**
  1단계에서 spring-learning-test 전체를 다 공부하다 보니 시간이 너무 많이 걸렸다. 슬슬 시간이 부족하다는 느낌이 들었고, 전부 다 보는 것보다 필요한 부분만 찾아서 학습하는 게 더 맞겠다 싶었다. 키워드 정리도 직접 하는 것보다 AI가 대화 맥락에서 뽑아주는 방식이 더 객관적이고 효율적이라고 느꼈다.

- **이전 단계의 전략이 새 단계에서도 통할 것 같은가?**
  퀴즈 전략은 통했지만, 전체 자료 정독은 통하지 않았다. 막힌 것의 종류가 "개념을 모름"에서 "코드로 어떻게 쓰는지 모름"으로 바뀌었기 때문에, 개념을 넓게 훑는 것보다 필요한 문법을 빠르게 찾아 쓰는 게 더 궁합이 맞았다.

---

### 2단계 → 3단계

- **이전 접근법을 그대로 쓸 것인가, 바꿔볼 것인가?**
  속도 중심의 방식은 유지하되, 애매하게 넘어간 부분을 기록하는 걸 추가했다.

- **바꾼 이유**
  2단계에서 빠르게 넘긴 덕분에 구현은 됐는데, 머릿속에 남는 게 없다는 느낌이 남았다. 이대로 계속 가면 안 되겠다 싶어서 재학습이 필요한 부분은 따로 기록해두기로 했다. 3단계 자체가 2단계 코드를 응용하는 구조여서 이전 코드를 먼저 복습하는 것도 자연스럽게 연결됐다.

- **이전 단계의 전략이 새 단계에서도 통할 것 같은가?**
  절반 정도 통했다. 구현 속도를 높이는 데는 여전히 유효했지만, 3단계에서 막힌 것의 종류가 "코드는 돌아가는데 이게 맞는 건지 모르겠다"로 바뀌었다. 빠르게 넘어가는 전략으로는 이 부분이 해소가 안 됐다. 뭔가 다른 장치가 필요하다는 걸 느꼈다.

---

### 3단계 → 4단계

- **이전 접근법을 그대로 쓸 것인가, 바꿔볼 것인가?**
  AI 퀴즈, 필요한 부분만 학습, 애매한 개념 목록화, 이 3가지는 그대로 유지했다. 여기에 "이게 맞는 구조인가"라는 의심을 해소할 방법을 새로 찾아야 했다.

- **바꾼 이유**
  3단계에 이어 4단계에서도 같은 유형의 막힘이 반복됐다. 혼자 고민하거나 남의 코드와 비교해봐도 의심이 해소되지 않았고, 오히려 주눅이 드는 부작용이 생겼다. 돌아보니 미션을 쳐내기에 바빠서 크루들과 코드에 대해 제대로 토론해본 적이 없었다. 이 부분이 빠져 있었던 것 같다.

- **이전 단계의 전략이 새 단계에서도 통할 것 같은가?**
  개인 학습 영역에서는 통한다. 그런데 "이 방향이 맞는가"라는 질문은 혼자 해결할 수 있는 범위를 벗어난 것 같다. 나만의 학습 원칙 3가지는 잘 자리를 잡았으니, 이제는 여기에 크루들과의 토론이나 코드 리뷰 같은 외부 피드백을 사이클 안에 넣어야 전략이 완성될 것 같다.
