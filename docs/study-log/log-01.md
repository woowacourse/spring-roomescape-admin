**시간**: 04/28 9:00 ~ 10:30 (약 90분)
**학습 범위**: 1단계 MVC

### 1. 막힌 것의 종류
이번에 막힌 것은 어떤 종류의 어려움이었는가? 
- 안다고 생각했던 개념이 실제로는 흐릿했다.
  - 기본적인 CRUD 코드를 AI를 활용해 작성해본 적은 있었지만, 각 코드의 역할을 정확히 설명하지 못했다.
- 개념은 알겠는데 코드로 직접 쓰는 것이 어려웠다.
  - 알고는 있다고 생각했지만, 직접 작성하려 하면 손이 멈췄다.
  
### 2. 이번 타임의 학습 전략

**이전에 바꾸기로 한 전략과 실행 여부**
- 학습 목표를 먼저 명확하게 정했다.
- 과제를 완성할 수 있는 수준의 개념 숙지를 1순위 목표로 잡았다.
- deep dive는 과제를 완성할 정도로만 하고, 너무 깊이 파고들지 않았다.
- 지금 당장 다루지 않는 것들은 다음 학습으로 열어두는 방향으로 처리했다.

**실제 학습 과정**
- 초록 스터디 MVC 1, 2로 전체 흐름을 먼저 훑었다.
- 과제를 진행하면서 막히는 지점을 AI와의 대화를 통해 그때그때 채워갔다.


### 3. 전략 평가
**효과적이었던 것**
목표를 좁힌 것이 가장 효과적이었다. 이전에는 모든 개념을 완전히 이해해야 한다는 강박이 있어 본래 목적을 잃는 경우가 많았다. 이번에는 범위를 줄이니 부담감이 줄었고, 미션 1을 빠르게 끝낼 수 있었다.

**비효과적이었던 것**
기존 지식과 연결하는 부분은 잘 되지 않았다. 연결하려면 이미 쌓인 지식이 있어야 하는데, 지금 단계에서는 그 연결고리 자체가 부족했다. 억지로 연결하려 한 것이 오히려 부담이었다.

**막힌 것의 종류와 전략의 궁합**
범위를 줄이는 전략이 잘 맞았다. 당장 알아야 할 것에만 집중하니 학습에 더 잘 몰입할 수 있었다.

### 4. AI 피드백
**기존 지식과 연결이 안 된 것에 대해**
연결이 안 된 것을 아쉽게 볼 필요가 없다. 나선형 학습에서 첫 번째 나선은 원래 그렇다. 처음 만나는 개념은 직관적으로 가볍게 이해하는 것으로 충분하다. 연결은 두 번째, 세 번째 나선에서 자연스럽게 생긴다.
지금 단계에서 중요한 것은 연결보다 **이해의 층위**다. `@RestController`가 동작한다는 것을 아는 것과, 왜 동작하는지 한 문장으로 설명할 수 있는 것은 다르다. 다음 학습 전, 오늘 배운 개념 하나에 대해 아래 문장을 채워보는 것을 권한다.

> "\_\_\_는 \_\_\_때문에 \_\_\_방식으로 동작한다. 그래서 \_\_\_상황에서 의미가 있다."

채워지면 이해한 것이고, 막힌다면 그게 다음 deep dive의 시작점이다. 연결은 그 다음에 따라온다.

### 5. 다음 타임에 바꿀 것
**유지할 것**
- 학습 목표를 먼저 정하는 것
- 범위를 좁혀 과제 완성 수준으로만 이해하는 것
- deep dive 목록을 열어두는 것

**바꿀 것**
- 기존 지식과 연결하는 항목은 지금 단계에서 억지로 하지 않는다. 나선이 한 바퀴 더 돌고 나면 자연스럽게 생길 것이다.

## 학습 과정
### 1. 학습 목표
- 시작 전: 왜 배우는가
  "CRUD API를 배우는 이유 → 과제에서 예약 생성/조회/삭제 요청을 처리하는 흐름을 이해하기 위해"

### 2. 선 이해
#### 1단계 — 초록 스터디 MVC 1, 2
- 정적 파일 서빙, @Controller, @RestController, ResponseEntity 등 스프링 MVC 전반적인 흐름을 먼저 훑었다.
#### 2단계 — AI와의 대화를 통한 보완
- 과제를 진행하면서 막히는 지점을 그때그때 질문하며 이해를 채워갔다.

`깊이보다 과제를 완성할 수 있는 흐름을 먼저 잡는 것을 목표로 했다.`

### 3. 말해보기
- 말해보기 같은 경우는 제목을 변경해야할 것 같다. 글로 설명 하는 방식도 좋을 것 같다.
- 기본적인 crud 같은 경우 옛날에 해보았기 때문에 동작 부분에서 막히는 부분은 없었다.

### 4. 정리하기
- 이해하고, 과제를 한 것을 바탕으로 정리를 하면서 다시 보았다.

### 5. 기존 지식과 연결
- 연결할 부분을 찾지 못하였다.

### 6. deep dive
1. Jackson 직렬화/역직렬화
2. 스프링 MVC 내부 동작 (DispatcherServlet 흐름)
3. HTTP 상태코드
4. 어노테이션 내부 동작
   (@RestController, @RequestBody, @GetMapping 등이
   실제로 어떻게 처리되는가)
