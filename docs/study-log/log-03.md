## 학습 로그 #2

**시간**: 04/29 17:30 ~ 21:00 / 04/30 11:00 ~ 12:00 (총 약 4시간 30분)
**학습 범위**: 3단계 — 시간 관리 (도메인 간 의존, FK, JOIN)

### 1. 막힌 것의 종류

> SQL로 테이블 간 관계(FK)를 설정하고, JOIN으로 연결된 데이터를 한 번에 조회하는 것이 어려웠다

- 이전에 바꾸기로 한 전략: 일단 이전 방식 유지
- 실제 학습 과정
  1. 테스트 파일로 목표 확인 — StepThree 테스트를 먼저 읽고 구현 방향 정의
  2. ReservationTime 엔티티 및 테이블 생성
  3. 예약 시간 CRUD(목록 조회·생성·삭제) 구현
  4. reservation 테이블에 FK 컬럼(time_id) 추가 및 스키마 변경
  5. INNER JOIN 쿼리로 Reservation ↔ ReservationTime 연결
  6. 미사용 필드 제거, deleteById SELECT+DELETE → update() 반환값으로 단순화

### 3. 전략 평가

- **효과적이었던 것**
  - 조금씩 공식문서를 읽는 것이 자연스러워지고있다

- **비효과적이었던 것**
  - 문서 전체가 영어로 되어있고, 아주 친절하지는 않은 편이어서 이해하고 적용하는데에 시간이 많이 걸린다
  - 분명 더 좋은 쿼리나 아키텍쳐가 있을텐데, AI가 절대 답을 주지 않아서 코드 개선에는 한계가 있다
    - 내 머리속에서 나온 가장 최선의 방법이었지만 그게 정말 최선인지는 확인이 불가능하다

- **막힌 것의 종류와 전략의 궁합**
  - SQL 관계 설정은 ERD(테이블 구조)를 먼저 그려보고 접근했으면 더 빨랐을 것 같다

### 4. AI 피드백

- 코드 리뷰에서 "잘한 것 → 개선 포인트 → 질문" 순서로 접근하니 스스로 개선 방향을 찾아가는 흐름이 됐다
- AI 가 절대 답을 알려주지 않아서, 직접 코드를 먼저 써보고 피드백을 받으니 체화가 잘 됐다
