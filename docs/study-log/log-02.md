### 1. 막힌 것의 종류
이번에 막힌 것은 어떤 종류의 어려움이었는가? (해당하는 것에 체크)

- [ ] 개념 자체를 모르겠다
- [x] 개념은 알겠는데 코드로 어떻게 쓰는지 모르겠다  
  (예: `given()`, `when()`, `then()`, `log().all()`, `body()` 등 RestAssured DSL의 구조)
- [ ] 코드는 돌아가는데 이게 맞는 건지 모르겠다
- [ ] 기타: 테스트 코드 흐름은 보이지만 각 메서드의 역할과 연결 구조가 즉시 해석되지 않음

**정리:**  
RestAssured가 HTTP 요청/응답 테스트 도구라는 점은 알고 있었으나,  
실제 테스트 코드에서 요청 준비 → 실행 → 검증이 어떤 DSL 구조로 연결되는지가 핵심 장애였음.

즉, **개념 부족보다 DSL 사용법/문법 구조 이해 문제**에 가까웠음.

### 2. 이번 타임의 학습 전략

- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가?
  - 아는 개념과 처음 접하는 개념을 명확히 구분하여 학습 전략을 세분화한다.(실행함)
    - 개념 자체를 모르는 경우: 먼저 개념 이해에 집중하는 전략
    - 개념은 아는데 사용법이 막히는 경우: 빠른 문법 습득과 적용 전략을 명확히 구분하여 적용한다.

- 실제로 어떻게 학습했는지 디테일한 과정
  1. RestAssured가 API 테스트 도구이며 HTTP 요청/응답 검증에 사용된다는 기본 목적은 이미 알고 있었음
  2. 실제 코드에서 `given`, `when`, `then`, `log`, `body`, `statusCode` 등이 어떤 역할 분리를 가지는지 불명확하다고 판단
  3. AI에게 각 메서드의 역할과 전체 체이닝 구조를 “요청 준비 / 요청 실행 / 응답 검증” 흐름 기준으로 질문
  4. AI 답변을 통해 DSL 구조를 큰 흐름으로 이해한 뒤, `body("size()", is(0))` 같은 실제 검증 표현 방식까지 세부 확인
  5. 이후 블로그 예제를 통해 JSON Path, Matcher, 로그 출력 방식 등을 교차 검증
  6. 검증한 내용을 현재 미션 테스트 코드에서도 동일하게 적용되는지 확인
