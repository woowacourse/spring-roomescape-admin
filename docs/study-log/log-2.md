### 1. 막힌 것의 종류

이번에 막힌 것은 어떤 종류의 어려움이었는가?

- [ ] 개념 자체를 모르겠다 (예: "스프링 빈이 뭔지 모르겠다")
- [x] 개념은 알겠는데 코드로 어떻게 쓰는지 모르겠다 (예: "JdbcTemplate 문법을 모르겠다")
- [ ] 코드는 돌아가는데 이게 맞는 건지 모르겠다 (예: "계층 분리를 이렇게 해도 되나?")
- [ ] 기타: ___

JdbcTemplate의 사용법이었다. JdbcTemplate에 다양한 query 메서드가 존재해 조회/저장 상황에서 어떤 쿼리를 사용해야 하는지 막혔다.

### 2. 이번 타임의 학습 전략

**이전에 바꾸기로 한 전략**: 하나의 세션에서 범위가 확장되는 것을 의식적으로 제한하기. 추가 궁금증은 메모만 해두고 다음 세션 주제로 넘기기.

**실행 여부**: 실행함

**실제 학습 과정**:

**1단계 (실제 문제 출발)**: "예약 시간 저장/조회 기능에서 JdbcTemplate의 어떤 메서드를 써야 하는가"에서 출발

**2단계 (한 문장 정의)**: "단건 조회 / 다건 조회 / 저장(+생성된 id 회수) 각각에 매칭되는 query 메서드 하나씩만 확정한다"로 범위를 못 박음

**3단계 (범위 제한)**: 트랜잭션, 예외 변환, RowMapper 추상화 같은 곁가지 주제는 떠오를 때마다 메모장에 적어두고 이번 세션에서는 다루지 않음

**4단계 (혼자 생각하기)**: 시그니처만 보고 "어떤 메서드가 어떤 상황에 맞을지" 먼저 추측 — 반환 타입(`List<T>` vs `T` vs `int`)으로 용도를 구분할 수 있겠다는 가설을 세움

**5~6단계 (구글링 + AI 질문)**: 가설 검증 위주로 질문. 특히 `queryForObject`가 결과 0건일 때 예외를 던지는 동작과, `KeyHolder` + `PreparedStatementCreator` 조합으로 auto-increment id를 받아오는 패턴을 확인

**실제 적용**: 시간 추가/조회/삭제 기능에 적용 (커밋: `feat: 시간 추가/조회/삭제 기능 구현`)

### 3. 전략 평가

**효과적이었던 것**:
범위 제한이 확실히 효과가 있었다. log-1에서 한 주제가 네 갈래로 번졌던 것에 비해, 이번엔 "query 메서드 매핑"이라는 좁은 목표를 20분 안에 닫고 끝낼 수 있었다. 트랜잭션, RowMapper 재사용 등을 메모로 미뤄 세션 집중도를 올려줬다.

**비효과적이었던 것**:
"개념은 알겠는데 코드로 어떻게 쓰는지 모르겠다" 유형이라 혼자 생각하는 단계의 효용이 log-1보다 작았다. 결국 시그니처와 예시를 직접 봐야 답이 나오는 문제여서, 4단계(혼자 추측)에 시간을 들이기보다 5단계(레퍼런스 확인)로 빨리 넘어가는 게 더 적절했을 수 있다.

**막힌 것의 종류와 전략의 궁합**:
"코드 작성법 모름" 유형에는 v3의 8단계 흐름이 다소 무겁다. 이런 유형은 *공식 문서/레퍼런스를 빠르게 훑어 패턴을 익히고, 곧장 적용해보며 실패로 학습*하는 게 더 자연스럽다. 단, 범위 제한 원칙은 유형과 무관하게 잘 맞았다.

---

### 4. AI 피드백

**개선 제안**:
막힘의 종류에 따라 학습 단계의 가중치를 다르게 두라는 제안. "설계 판단" 유형(log-1)은 혼자 생각하기 → 자료 비교가 핵심이고, "코드 작성법" 유형(log-2)은 레퍼런스 확인 → 즉시 적용 → 실패 회고가 핵심이다. 같은 v3 프레임워크라도 단계별 시간 배분을 유형에 맞게 조정해야 한다.
