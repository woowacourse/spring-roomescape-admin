### 2. 이번 타임의 학습 전략
- 이전에 바꾸기로 한 전략은 무엇이었고, 실행했는가? 
  - v1, v2, v3를 거쳐 도출한 학습 전략은 다음과 같습니다. 
  ```
  개념을 깊게 파고들기 전에, 문제 해결에 필요한 만큼만 먼저 이해하고 바로 구현한다.
  1. 문제를 먼저 확인한다.
  2. 개념적으로 아예 모르는 내용이 나오면 멈춘다.
  3. 바로 깊게 공부하지 않고, 아래의 문제 해결용 멘탈 모델 카드 5개를 채운다.
      - 이 개념은 무엇인가?
      - 왜 필요한가?
      - 어떤 흐름으로 동작하는가?
      - 지금 문제에서 어디에 적용되는가?
      - 자주 터지는 실수나 주의점은 무엇인가?
  4. 5개의 질문이 채워지면 학습을 멈추고 바로 구현한다.
  5. 구현 중 실패하면, 실패한 부분만 다시 학습한다.
  ```
  - 위와 같이 학습전략을 구성했으나, 1단계를 마무리하고 학습로그를 작성하는 과정에서, 이번에 세운 학습 전략을 적용하지 않고 진행했다는 것을 깨달았습니다. 코드를 전부 지운 후 학습 전략을 적용하여 다시 학습을 진행하였습니다.


- 실제로 어떻게 학습했는지 디테일한 과정을 써보세요.
    ```
    1단계를 진행하기에 앞서, 1단계 참고 자료에 있는 학습 테스트를 먼저 진행했습니다.
    
    학습 테스트의 README를 읽으며 순서대로 학습했고, 모르는 개념이 나올 때마다 앞서 세웠던 학습 전략을 적용했습니다.  
    즉, 바로 깊게 파고들기보다 먼저 문제 해결용 멘탈 모델 카드 5개를 채우고, 이를 노션에 기록했습니다. 또한 학습 테스트를 진행하면서 생긴 궁금증도 함께 정리했습니다.
    
    즉, 모르는 개념에 대해서 먼저 멘탈 모델 카드 5개를 채우며 사전 학습을 하고, 이후 학습 테스트를 통해 제가 이해한 내용을 다시 확인하는 방식으로 공부했습니다.
    
    특히 멘탈 모델 카드 중 “자주 터지는 실수나 주의점은 무엇인가?” 항목이 가장 도움이 되었습니다.  
    자주 발생하는 실수와 주의점을 미리 학습한 뒤 테스트를 풀어보니, 테스트가 어떤 의도를 가지고 있는지 더 잘 파악할 수 있었습니다.
    
    학습 테스트를 모두 마친 뒤 1단계를 진행했습니다.  
    v3에서 세웠던 전략대로 학습 테스트를 먼저 공부하고 구현을 시작하니, 대부분의 요구사항은 수월하게 진행할 수 있었습니다.
    
    다만 1단계 구현 후 테스트를 실행했을 때 한 번 실패한 부분이 있었습니다.  
    `ResponseEntity`는 객체를 JSON으로 변환할 때 클래스의 getter를 기준으로 값을 읽어 응답을 생성하는데, getter 이름을 `getName()`처럼 작성하지 않고 `name()`처럼 작성해서 문제가 발생했습니다.
    
    이 내용은 사전에 학습했던 부분이었지만, 실제 구현 과정에서 실수했고 이를 통해 머리에 깊게 남는 좋은 학습이 되었다고 생각합니다.  
    ```
