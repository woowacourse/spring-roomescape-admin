### 4. AI 피드백

앤더스 에릭슨 역할로 피드백을 받았다.

#### 4.1. pre-mortem

설계 판단이 지금과 다른 점은. 틀려도 코드는 돌아간다는 것이다. 그래서 나의 학습 로그에서 "코드는 돌아가는데 맞는 건지 모르겠다"가 떠오르는 것이다. 결정의 옳고 그름은 나중에 다른 결정과 부딪힐 때만 드러나는데, pre-mortem은 그 충돌을 사전에 시뮬레이션시킨다.

##### 룰

```text
[Pre-mortem 설계 일지 운영 룰]

위치: docs/study-log/premortem-NN.md (recall과 별도)
빈도: 4단계. 의사결정이 필요할 때마다
분량: A4 1장 / 마크다운 30줄 이내
시간: 15분 상한 (타이머 키기)
독자: 1주일 후의 너 (PR 머지 후 다시 읽음)

✓ 결정 5개 이내. 더 늘리지 말기 (도구 과잉 방어막)
✓ 증상 칸은 코드 차원으로. 추상 이론 금지 (i+5 폭주 방어막)
✓ 누적 15분 넘기면 미완성 그대로 제출
✓ "증상 모르겠음"도 정직하게 적기. 그 빈칸이 다음 학습 포인트
✗ PR 직전에 한 번에 다 쓰기 (사후 합리화 됨)
✗ 결정을 옳게 쓰려고 하기 (틀려야 학습됨. 적중률 낮을수록 좋음)
```

##### 결정 작성 템플릿

```text
### #N: ___을 ___에 두기로

대안: ___ (1개)
이유: ___ (1줄)
틀렸을 때 증상: ___ (1개, 코드 차원)

[PR 직전 체크]
실제: 나타남 / 안 나타남 / 다른 게 나타남(___)
```

##### 작성 흐름

```markdown
[1] 4단계 구현 시작
↓
[2] 첫 분리 결정 마주침
("어디에 둘까" 순간)
↓
[3] premortem-01.md 열고 결정 1개 적음 (3분) - 결정 / 대안 1개 / 증상 1개
↓
[4] 구현 복귀 — 다음 결정 마주치면 [3] 반복 (최대 3개)
↓
[5] PR 보내기 직전 5분
"예측한 증상이 코드에 실제 나타났나?" 체크
한 줄로 결과 적음
↓
[6] PR 보냄
```
