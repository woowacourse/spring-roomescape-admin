# 학습 로그

## 학습법 변천사

### v1 — 레벨1에서 가져온 방식

**핵심 방식**

AI를 답을 받는 도구가 아니라 내 판단을 검증하는 도구로 활용했다.
문제가 발생하면 혼자 먼저 분석 → 해결 방향 생각 → AI로 확인하는 순서를 지켰다.

**효과적이었던 것**
- 먼저 생각하고 AI에게 확인하는 구조 => 사고력 유지
- 심리적 여유가 있을 때 혼자 파고드는 과정 자체가 학습이 됨

**비효과적이었던 것**
- 마감 제한 상황에서 먼저 생각하는 단계가 무너지고 AI 의존성이 높아짐
- 공식 문서보다 블로그 선호 => 정보 신뢰성 문제

---

### v2 — 충돌 지점을 찾아 다듬은 방식

v1의 충돌 지점을 공유하고, PiFSR 5원칙과 나선형 학습을 참고하여 함께 개선했다.

**핵심 방식**

AI를 판단 검증 도구로 활용하되, 깊이 있는 학습을 위해 상황 제한성을 추가했다.
모든 학습은 '이걸 왜 배우는가?'라는 문제 정의에서 출발한다.

**문제 발생 시 순서**

막힌 지점 한 줄로 정리 → 내 가설/원인 한 줄 작성 → 혼자 분석 → 해결 방향 생각 → AI로 확인

**세부 규칙**
- 스스로 생각하는 과정 비중을 늘리기
- 고민한 과정과 해결 과정을 기록으로 남기기
- 궁금한 것은 깊게 파되, 진도가 안 나갈 땐 시간 제한을 두기
- 블로그보다 공식 문서 우선

---

### v3 — AI에게 피드백을 받고 수정한 방식

레벨2 개인 학습에서 Claude Code 공식 문서를 직접 참고하며 v2를 실제로 적용해봤다.
레벨1까지는 가독성을 이유로 블로그를 선호했는데, 이번에 공식 문서로 낯선 개념을 접해보니 생각이 달라졌다.
정보의 정확성과 출처가 명확하다는 점이 가독성보다 더 중요하다는 것을 직접 체감할 수 있었다.

이 경험을 바탕으로 v2를 다음과 같이 발전시켰다.

**핵심 방식**

- AI를 판단 검증 도구로 활용하되, 깊이 있는 학습을 위해 상황 제한성 추가
- 모든 학습은 '이걸 왜 배우는가?'라는 문제 정의에서 출발
- 새 개념을 배우기 전, '이게 없었다면 어떤 문제가 생겼을까?'를 먼저 상상한 뒤 시작

**문제 발생 시 순서**

막힌 지점 한 줄로 정리 → 내 가설/원인 한 줄 작성 → 혼자 분석 → 해결 방향 생각 → AI로 확인 → 배운 것을 한 문장으로 재설명 (자신의 언어로)

**세부 규칙**

**사고 과정**
- 순서 자체는 그대로 유지하되, 스스로 생각하는 과정 비중을 늘리기
- AI는 내 가설을 검증하는 도구로만 사용하고, 모르는 것을 바로 묻는 용도로 쓰지 않기

**기록**
- 고민한 과정과 해결 과정을 반드시 기록으로 남기기
- 기록 형식: 막힌 지점 / 내 가설 / 실제 원인 / 배운 것 한 문장 - 이 네 가지를 짧게라도 남겨두기

**시간 관리**
- 궁금한 것은 깊게 파되, 진도가 안 나갈 땐 타이머를 설정하고 시간 제한을 두기
- 시간 내에 해결 못한 개념은 미해결 목록에 따로 기록해두고, 같은 개념을 다시 만났을 때 한 겹 더 파고드는 방식으로 깊이 축적

**자료 참고 기준**
- 블로그보다 공식 문서 우선
- 익숙해진 개념은 다른 사람에게 설명하듯 정리글로 남기는 방향으로 심화 => 읽는 것보다 쓰는 것이 이해의 구멍을 더 잘 드러냄
