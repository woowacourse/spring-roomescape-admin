## 학습법 v1
### 레벨1에서 실제로 해온 학습법
- AI에게 필요한 정보를 요청하여 이해해본 뒤 바로 적용한다.
- 코드를 작성해보며 이해한게 맞는지 확인한다.
- 인터넷 강의를 들으며 기초를 다진다.
- 책을 읽으며 설계에 대한 개념을 익힌다.
- AI가 알려준 내용이 이해가 되지 않거나 틀렸다고 생각될 때, 구글링을 통해 공식 문서나 블로그를 찾아본다.

### 효과적이었던 것
- 책을 읽으며 설계에 대한 개념을 익히는 것은 멀게만 느껴졌던 개발에 더 가까워졌다는 느낌을 받게 했으며, 실제로 가장 큰 도움이 되었다고 생각합니다.
- 인터넷 강의는 강의 주제의 기술에 대해 기초적인 내용부터 선형적으로 가장 빠르게 지식을 쌓아갈 수 있는 방법이라고 생각합니다. 왜 이 기술을 사용하는지, 어떻게 사용하는지, 실무 노하우 등 다른 사람의 경험을 엿보는 것이라고 생각합니다. 내가 관심있는 특정 기술을 주제로 하는 강의라면 효과적이었다고 생각합니다.

### 비효과적이었던 것
- AI에게 물어보는 것은 비효과적이었다고 생각합니다. AI는 문제를 해결해주는 막강한 도구인 것임은 분명합니다. 하지만 AI의 답변을 내 것으로 만드는 것은 많이 느리게 느껴집니다. AI의 답변은 부가적인 내용이 너무 많아 제대로 읽지 않게되며, 중요한 것만 대답하게 한다면 제대로 대화가 되지 않는다는 느낌이 강합니다. 결국 문제를 빠르게 해결하는데에 도움이 되는 것은 분명하지만, 내가 공부하고, 이해하여 적용해보는 것보다 내게 남지 않는 방식의 도움이라고 생각됩니다. 같은 문제를 여러 번 반복하여 기계적인 정답을 갖게 될지라도 머리속에서 정리가 잘 되지 않아서 이게 정말 잘 알게 된 것인가?라는 질문에는 쉽게 대답할 수 없었습니다.

### 내가 반복적으로 쓰는 학습 방식
- 레벨1에서 가장 많이 사용했던 것은 AI를 활용한 학습입니다.

### 특히 잘 안 풀렸던 학습 상황
- AI가 계속 말을 바꾸는 상황이 잘 안풀렸다고 생각합니다.
객체지향 설계, 책임에 대한 내용을 물어봤을 때, 처음에는 여기가 좋다고 했다가, 나중에는 여기가 좋지 않다고 했다가.. 계속해서 설계에 대해 고민하게 만들고, 내가 고민하는 부분에 대한 갈증은 해소하지 못해줬습니다.
- 레벨2의 양을 지금의 학습법으로 감당할 수 있을 것 같은가?
  - 지금 생각하기로는 AI를 활용하여 감당할 수 있다고 생각합니다. 하지만 위에서도 얘기했듯이 AI를 활용하여 이 길을 지나간다면, 발자국은 희미하게 남아버릴 것이라고 생각합니다. AI를 최소한으로 사용하고, 직접 코드를 쳐가며 해보는 방식으로 전환해보려 합니다.

## 학습법 v2
- 문제 해결을 위한 학습을 진행하게 될 경우 실습이나 바로 적용해볼 수 있는 방법을 즉각 적용해본다.
- 시행 내용을 구조화하여 정리하여본다.
    - 막히는 부분이나 궁금한 부분들을 표기한다.
    - 표기된 부분에 대해 막힘이 해결되는 수준까지만 학습한다.(절대 깊게 알아보지 않는다. 필요한 개념이나 정의에서 만족할 것)
- AI는 막히는 부분이나 궁금한 부분을 해결하는 과정에서만 사용한다.

## 학습법 v3
[전체 흐름]  
목표/기대 설정 → 즉시 적용 → 막힘 해결 → Output 생성 → 검증/회고

---

### 0. 목표 / 기대 설정 (필수)

이번 학습에서 “내가 할 수 있어야 하는 것”을 명확히 정의한다.  
완료 여부를 판단할 수 있어야 한다.

좋은 예시
- 트랜잭션 전파 레벨을 설명할 수 있다
- @Transactional을 사용한 테스트 코드를 작성할 수 있다

나쁜 예시
- 트랜잭션 공부하기
- 개념 이해하기

기준
- 설명 가능하거나 구현 가능해야 한다
- 30분~2시간 안에 달성 가능한 수준이어야 한다

---

### 1. 즉시 적용 (기존 방식 유지)

읽기 전에 먼저 만들어보고 실행한다.

예시
- 간단한 API 작성
- 트랜잭션 적용
- 예외 발생시켜 롤백 확인

핵심
- “이해 후 구현”이 아니라 “구현하면서 이해”

---

### 2. 막힘 해결 (얕게, 빠르게)

막힌 부분만 해결하고, 문제 해결되면 즉시 멈춘다.  
깊게 파지 않는다.

예시  
문제: 롤백이 안 됨  
행동:
- @Transactional 위치 확인
- checked vs runtime exception 확인  
→ 해결되면 종료

기준
- 원리 완벽 이해까지 가지 않는다
- “문제 해결되면 끝”

---

### 3. Output 생성 (필수)

학습 결과를 반드시 외부에 남긴다.  
작게라도 남기는 것이 핵심이다.

아래 중 하나만 해도 충분하다
- 설명 3~5줄
- 간단한 코드
- 언제 사용하는지 기준 1줄

예시
- 트랜잭션은 RuntimeException에서 기본적으로 롤백된다
- DB 일관성이 필요한 로직에서 사용
- 간단한 @Transactional 코드 작성

기준
- 30초~2분 안에 만들 수 있는 수준
- “머릿속 이해”로 끝내지 않는다

---

### 4. 검증 & 회고 (짧게)

1~2분 안에 아래 3가지만 정리한다
1. 내가 예상한 것과 실제 다른 점은?
2. 내가 틀린 부분은 무엇인가?
3. 다음에 같은 상황이면 어떻게 할 것인가?

예시
- 예상: checked exception도 롤백될 줄 알았다
- 실제: runtime만 롤백됨
- 다음: rollbackFor 옵션 확인

기준
- 감상이 아니라 “틀린 부분” 중심으로 작성

---

### 헷갈리는 기준 정리

1. 얼마나 깊게 공부해야 하나?  
→ 문제 해결되면 끝
2. Output은 얼마나 해야 하나?  
→ 30초~2분 안에 끝나는 수준
3. 목표는 얼마나 크게 잡아야 하나?  
→ 30분~2시간 내 달성 가능
4. AI는 언제 써야 하나?  
→ 막혔을 때만 사용

---

### 핵심 요약

1. 목표를 정한다 (완료 기준 명확)
2. 바로 해본다
3. 막히면 필요한 만큼만 본다
4. 반드시 Output 남긴다
5. 틀린 부분만 확인한다
