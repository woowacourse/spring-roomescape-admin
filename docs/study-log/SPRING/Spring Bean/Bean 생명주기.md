객체 인스턴스화부터 종속성 주입 및 초기화까지, 그리고 파괴로 끝나는 내부 워크플로우와 스프링 IoC 컨테이너를 통해 빈을 관리하는 과정을 설명

> 이게 왜 태어난거지?
> 객체 생성/초기화/사용/종료를 일관되게 관리하려고 등장함
> 목적은 리소스 관리, 안정적인 초기화 및 정리
> 
> 약간 리소스가 큰 객체를 사용할 때 잘 초기화하고 사용하고 종료할 수 있도록 하는게 중요하기 때문인건가?

### 컨테이너 초기화
- Spring IoC 컨테이너는 구성 메타데이터(XML, 주석 또는 Java 구성)를 시작하고 로드합니다.
- 빈 정의가 등록되고 프로세서와 같은 인프라 구성 요소가 준비됩니다.

### 빈 인스턴스화
- 컨테이너는 생성자 또는 공장 방식을 사용하여 Bean 객체를 만듭니다.
- 이 단계에서 Bean은 기억 속에 존재하지만 의존성은 아직 주입되지 않았습니다.

### 의존성 주입
- 이 컨테이너는 IoC 컨테이너에서 요구되는 종속성을 해결합니다.
- 종속성은 생성자, 세터 또는 필드 주입을 통해 주입됩니다.

### 사용자 지정 시작 메서드
- 모든 종속성이 주입되면 맞춤형 init() 메서드를 호출합니다.
- 리소스 초기화, 속성 검증 또는 연결 시작과 같은 추가 설정을 수행하는 데 사용됩니다.

### 사용자 지정 유틸리티 메서드
- 맞춤형 유틸리티 방법은 스프링 빈 내부에서 정의되는 일반적인 비즈니스 또는 도우미 방법입니다.
- 개발자는 그것을 Bean 참조를 통해 수동으로 호출해야 합니다.

### 사용자 지정 파괴 메서드
- 정리 논리는 @PreDestroy, destroy() 또는 맞춤형 destroy 메서드를 사용하여 실행됩니다.
- 데이터베이스 연결이나 스레드와 같은 리소스는 콩 제거 전에 공개됩니다.

---
- 생성 → **생성자**
- DI → **생성자 주입 (@Autowired 생략 가능)** / @Component
- 초기화 → **@PostConstruct**
- 사용 → 일반 메서드
- 종료 → **@PreDestroy**

> 그러면 생성할 때 @Component로 사용해서 의존성 주입하고, DB 연결같은 거에서 @PostConstruct로 잘 초기화하고, 안에 메서드 사용하고, 이제 사용이 끝날 때 @PreDestory를 쓰는건가?
> 
> 컨테이너 종료 시에 @PreDestory 실행임?
> 
> → **@PreDestroy는 “Spring이 종료할 때 Bean에서 자동 실행되는 메서드”다**
