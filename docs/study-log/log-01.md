학습 범위: @RequestBody, @ResponseBody, @ResponseEntity

### 1. 어디서 막혔는가?
이번에 막힌 것은 어떤 종류의 어려움이었는가? (해당하는 것에 체크)
- [ ] 개념 자체를 모르겠다
- [ ] 개념은 알겠는데 코드로 어떻게 쓰는지 모르겠다
- [ ] 코드는 돌아가는데 이게 맞는 건지 모르겠다
- [x] 기타: 코드는 작성할 수 있는데 어떻게 동작하는 지 모르겠다 

### 2. 이번 시간 학습 전략
궁금한 키워드를 기록해뒀다가 학습 시작할 때 종이를 펼치고, 제 생각을 적었습니다. 
```aiignore
- @ResponseBody는 어떻게 동작하는가?
- @RequestBody는 어떻게 동작하는가?
- @ResponseEntity는 어떤 구조인가?
- ResponseEntity<Void>가 반환 타입일 때, build()를 왜 붙여야 하는가?
```
잘 몰라도 어떻게든 쥐어짜내서 적었습니다.
그리고 나서 AI에게 질문과 내 답을 줍니다. AI는 cluade를 사용했고, 루트 프로젝트에 학습을 위한 프롬프트를 넣었습니다.
```
이제 공부 하나 들어갈거야

질문: ResponseBody가 뭔데?
내 답: HttpResponse 프로토콜의 body 부분에 들어갈 값들을 말한다.
@ResponseBody 애노테이션을 사용하면 Jackson 라이브러리가 알아서 객체를 직렬화해준다.
이 때 상태코드는 무조건 200으로 반환된다?
```
개념을 익히고, 옵시디언에 개념을 다시 한두 문장으로 요약했습니다.

### 3. 전략 평가
1. 효과적이었던 것
: 맞든 틀리든 제 생각을 먼저 손으로 종이에 적는 작업을 하니깐, 내가 진짜 알고 있는 부분이 무엇이고 모르는 부분이 무엇인지 확실히 구분할 수 있었습니다.

2. 비효과적이었던 것과 이유
: 학습법에서 "코드로 검증하기", "마인드 맵 그리기"가 있었는데, 애초에 미션 중 코드를 작성하면서 궁금증이 유발된 것이므로 코드 작성은 중복이라 생각했습니다. 그리고 개념 학습 후에 마인드 맵을 그리는 일이 부담이라고 느껴 하지 않았습니다.

### 4. AI 피드백
- 코드 검증을 "5분 부수기 시간"으로 바꾸기.
- 거창하게 검증한다고 생각하지 말자
- 코드로 검증하기는 "정말 이해했는지 컴퓨터에게 물어보기"이다.

### 5. 다음 타임에 바꿀 것
- 개념마다 5분안에 코드로 검증한다면 키워드가 10개라면 약 1시간이 소요된다.
- 진짜 코드로 검증이 필요한지 판단 후 코드로 검증한다. 단계별 최대 2개로 제한합니다.

### 6. 단계 전환 체크
- "마인드맵 그리기"는 이번 미션에서 제거합니다.
  - 이유: 시간이 너무 오래걸립니다.
- "막힌 부분"만 AI에게 질문하는 것이 아니라, "질문과 내 답"을 AI에게 넣고 물어보기
  - 이유: 내 생각도 함께 피드백을 받기 위함입니다.
