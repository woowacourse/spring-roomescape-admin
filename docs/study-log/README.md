## **학습법 수정의 출발점**

> 매 버전은 이전 버전을 갈아엎지 않는다.  
> 실제 충돌 지점에서 드러난 최소 보정만 추가한다.

- i + n 문제 : 너무 많은 것을 하려는 흐름이 보였다.
- 학습법을 제시하였지만, 동작하지 않았던 부분이 많았다.
- 실제로 지킬 것만 작성하고, 내가 미션을 하면서 보였던 패턴들을 정리한다.


<br/>

## 학습 흐름

### 1단계: 새 기술/미션 진입

**1-1 한 줄 정의 :** "이 기술은 ___ 문제를 풀려고 만들어졌다."  
**1-2 흐름 스케치 : AI에게 질문을 던진다. 그 후 큰 흐름을 잡는다.**
> X는 어떤 문제를 풀려고 만들어졌는가?  
> 큰 흐름은 어떻게 되는가?  
> 이 단계에서 반드시 알아야 할 핵심 개념 3~5개만 알려달라. 그 외의 것은 빼라." 


- `요청 → ??? → DB → ??? → 응답` 식으로, 모르는 지점은 ???로 비워둔다.
- 핵심 키워드 3~5개를 공식문서에서 교차 확인한다 : 공식문서는 여기서 reference로 쓰인다
    - **키워드만 빠르게 확인하는 용도**이다. 깊게 들어가지 않는다.

### **2단계: 코드 작성**

- `코드 먼저 작성 → 찜찜함 포착` 흐름은 그대로다. AI 코드를 **그대로 받아 쓰는 것도 막지 않는다.**
- 1단계에서 그려둔 흐름 스케치 위에서 코드를 본다. ???로 비워뒀던 자리가 코드를 쓰면서 하나씩 채워진다.
- 모르는 부분이 있더라도 구현에 집중한다.

### **3단계: AI로 빠른 검증**

리팩토링 들어가기 전에 한 번은 다음 중 하나를 거친다. 이 단계에서 AI는 코드 생성기가 아니라 **검증자**다.

- AI에게 "이 코드의 함수가 어떤 동작을 하고, 생길 수 있는 문제점도 설명해줘" 질문하기
- 핵심 함수/개념을 공식문서에서 확인
- 모르는 키워드 하나만 검색해서 정리

**곧바로 해당 함수 및 어노테이션 등 동작원리로 들어가지 않는다.
→ 위에서 AI 코드를 그대로 쓴 내용을 AI + 공식문서를 통해 습득한다.**

### **4단계: 글 정리**

**Evergreen Note 분리**
미션 정리 문서 외에 **한 개념 = 한 노트** 형태로 별도 정리한다.

- 한 노트는 한 개념만 다루며 본인의 언어로 정리한다.
- 제목: 개념 이름 그 자체
- 코드를 작성하며 생겼던 문제, 그리고 3단계에서 나왔던 부분을 바탕으로 정리한다.
- 찜찜한 부분이 남으면 노트 끝에 **"??? 섹션"** 으로 명시한다.

## 피드백 활동 산출물
- 주말에 시도할 것 : 미션 시작 전 ??? 섹션 중 가장 거슬리는 1개만 골라 30분 안에 푼다.

- 적용 시나리오:
1. 다음 미션을 시작하기 전, 지난 학습 로그의 ??? 섹션을 펼쳐 가장 거슬리는 1개를 고른다. 여러 개에 끌리면 가장 자주 만났던 것 1개로 결정한다.  

  
2. 30분 타이머를 켜고 그 1개만 판다. 공식문서 한 페이지 + AI 검증 질문 1개 정도로 끝낸다. 
    다 풀리면 Evergreen Note을 작성한다.
   1. 어디서 막혔는지
   2. 어떻게 풀었는지
   3. 다음에 만나면 무엇을 떠올릴지도 같이 작성한다.  
   

3. 멈출 조건: 30분 안에 안 풀리면 멈추고 ??? 섹션에 "30분 시도, 미해결" 표시 후 다음으로 넘어간다.   
    또는 푸는 도중 다른 ???가 끌려서 손이 옮겨가면 즉시 멈추고 원래 1개로 돌아온다.
